> - **上线**:2026-10-20,四类组件已手动跑通;排期按北京时间错峰,mysql 04:00 → mongodb 04:15 → emqx 04:40 → configs 04:50。

## 阅读路径

- **要确认备份还在跑**:1 的「常用验证」,看 OSS 上当天日期目录是否齐全;
- **要恢复某个组件**:1 的「恢复速查」,按组件分四段;
- **想加一个新组件**:先看「明确不备份」表确认是否已排除,再照脚本清单里同类组件的写法加。

## 这个目录在讲什么

备份的难点不在备份,在恢复。这套文档把恢复步骤和验证命令写在前面,是因为备份任务成功不代表数据可用——`mongodump` 退出码 0 但归档损坏的情况真实存在。

「明确不备份」那张表比备份清单更重要:redis 是纯缓存、kafka 数据是流动消息、ES 与 nexus 可从源重建,这些判断写明白了,才不会有人某天顺手把 redis 也加进 cron。
