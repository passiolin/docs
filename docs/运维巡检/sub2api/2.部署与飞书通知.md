# 部署与飞书通知

## 前置条件

- 一台常开的 Linux 巡检机,能出网到网关与 `open.feishu.cn`;
- Python 3.9 及以上(脚本用 `zoneinfo`,只用标准库,不装第三方包);
- 网关的管理员 API Key(后台 → 设置 → 管理员 API Key);
- 一个内部飞书群,群里能加自定义机器人。

部署参数:

| 项 | 值 |
| --- | --- |
| 巡检机 | `<巡检机 IP>`(`<主机名>`,Ubuntu,systemd 255,Python 3.12.3,系统时区 UTC) |
| 网关地址 | `<SUB2API_BASE_URL>` |
| 低额度阈值 | `1000`(美元) |
| 飞书群 | 内部群(webhook 只存目标机 env,见下方权限要求) |

## 安装 admin skill

巡检脚本直接调 admin API,不依赖 skill;skill 用在人工或 AI 交互式排查——查某个账号为什么被停调度、批量改 key 分组、看上游报错原文这类一次性动作。两者共用同一套 admin API 和 Key。

skill 在本目录的 `skills/sub2api-admin`,以软链方式装到用户级 skill 目录,不复制文件,改仓库即生效:

```bash
cd docs/运维巡检/sub2api
mkdir -p ~/.zcode/skills ~/.agents/skills
ln -sfn "$PWD/skills/sub2api-admin" ~/.zcode/skills/sub2api-admin
ln -sfn "$PWD/skills/sub2api-admin" ~/.agents/skills/sub2api-admin
```

验证:

```bash
export SUB2API_BASE_URL='<SUB2API_BASE_URL>'
export SUB2API_ADMIN_API_KEY='<管理员 API Key>'
node ~/.zcode/skills/sub2api-admin/scripts/sub2api-admin.js accounts list --page-size 5
```

能列出账号即安装成功。skill 的完整命令表在 [skills/sub2api-admin/references/admin-cli.md](skills/sub2api-admin/references/admin-cli.md)。

## 部署巡检脚本

### 1. 放脚本

```bash
sudo install -d -m 755 /opt/sub2api-patrol
sudo install -m 755 sub2api_patrol.py /opt/sub2api-patrol/
```

### 2. 配环境变量

```bash
sudo install -d -m 700 /etc/sub2api-patrol
sudo install -m 600 conf/sub2api-patrol.env.example /etc/sub2api-patrol/sub2api-patrol.env
sudo vi /etc/sub2api-patrol/sub2api-patrol.env
```

三个必填项:`SUB2API_BASE_URL`、`SUB2API_ADMIN_API_KEY`、`FEISHU_WEBHOOK`。机器人开了签名校验再加 `FEISHU_SECRET`。阈值和窗口按需覆盖 `LOW_BALANCE_THRESHOLD`、`ERROR_WINDOW_MINUTES`。

自动启停相关:`AUTO_SUSPEND`(默认 true,置 false 只观察不写)、`AUTO_SUSPEND_THRESHOLD`(默认 99)、`AUTO_RESUME_THRESHOLD`(默认 90)、`AUTO_SUSPEND_STATE`(默认 `/var/lib/sub2api-patrol/auto_suspend.json`)。状态文件由脚本自动创建,权限 644,内容只有账号名、窗口和用量,不含 Key。

### 3. 手动跑一轮

```bash
sudo -i
set -a; . /etc/sub2api-patrol/sub2api-patrol.env; set +a
python3 /opt/sub2api-patrol/sub2api_patrol.py --dry-run
```

终端会打印账号、低额度用户、报错三段的文字摘要;加 `--json` 还能看到卡片原文,确认无误再去掉 `--dry-run` 真发一次。

退出码:0 正常,2 配置缺失,3 采集有失败项,4 飞书推送失败。发现账号异常不影响退出码,异常体现在卡片颜色和正文里。

### 4. 装定时器

```bash
sudo install -m 644 conf/sub2api-patrol.service /etc/systemd/system/
sudo install -m 644 conf/sub2api-patrol.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now sub2api-patrol.timer
```

### 5. 验证

```bash
systemctl list-timers sub2api-patrol.timer
sudo systemctl start sub2api-patrol.service
journalctl -u sub2api-patrol -n 50 --no-pager
```

`list-timers` 的 `NEXT` 应落在下一个整点(9–18 点之间);`journalctl` 末尾出现「已推送飞书卡片」即成功。

## 飞书机器人

群里点「设置 → 群机器人 → 添加机器人 → 自定义机器人」,起个名字(如 `sub2api 巡检`),安全设置勾「签名校验」并保存密钥,复制 webhook 地址填进 env 的 `FEISHU_WEBHOOK`,`FEISHU_SECRET` 填密钥。

签名算法按飞书自定义机器人文档:以 `timestamp + "\n" + secret` 为 key、空串为消息做 HMAC-SHA256,结果 Base64 后随 `timestamp` 一起放进请求体。脚本已实现,不需要额外处理。

机器人被移出群或 webhook 被重置后,旧地址立即失效,需要重新复制。

## 定时节奏

timer 的日历是 `*-*-* 09..18:00:00 Asia/Shanghai`,9 点到 18 点整点各一次,一天十轮。

不用 systemd 时,cron 等价写法:

```cron
0 9-18 * * * cd /opt/sub2api-patrol && set -a && . /etc/sub2api-patrol/sub2api-patrol.env && set +a && /usr/bin/python3 sub2api_patrol.py >> /var/log/sub2api-patrol.log 2>&1
```

cron 的默认时区取系统时区,机器是 UTC 时要显式 `CRON_TZ=Asia/Shanghai`。systemd timer 自带时区,优先用它。

## 排障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 接口返回 401 / `INVALID_ADMIN_KEY` | Key 失效或被重置 | 后台重新生成,更新 env 后重启 timer |
| 飞书返回 `code=19021` | 签名不匹配;或机器人未开签名却填了 `FEISHU_SECRET` | 密钥与机器人设置对齐,不用就留空 |
| 日志说已推送,群里没有 | 机器人被移出群、webhook 被重置 | 重新复制 webhook |
| 卡片时间差 8 小时 | 机器是 UTC,timer 少了时区 | 检查 `OnCalendar` 的 `Asia/Shanghai` 与 unit 的 `TZ` |
| 采集失败项里出现 5xx | 网关自身异常或重启中 | 查网关容器状态与 `/admin/ops/system-logs` |
| systemd 启动失败 | `EnvironmentFile` 权限或 python 路径不对 | `journalctl -u sub2api-patrol` 看具体报错 |
| 卡片里有「自动启停(预览,未写入)」 | 本轮是 `--dry-run` 或 `--no-suspend`,或 `AUTO_SUSPEND=false` | 去掉参数/改回 true 再跑 |
| 状态文件写不进去 | `/var/lib/sub2api-patrol` 权限或磁盘满 | 卡片「采集异常」会列出原因,`ls -ld` 该目录 |
| 卡片里账号数比后台首页少 | 首页按状态算,巡检排除了停调度账号 | 属预期口径,见第 1 篇 |

## 安全边界

管理员 Key 等同于后台管理员权限,只落在目标机 `/etc/sub2api-patrol/sub2api-patrol.env`(600、root),不进仓库、不发聊天。卡片里带同事邮箱和余额,webhook 只发内部群。巡检脚本只读,不调用任何写接口。
