# 双桶隔离方案：公开桶与私有桶设计说明

## 1. 背景与决策

在单桶隔离方案（通过 `public/` 和 `private/` 路径前缀区分权限）中，Bucket Policy 的编写和运维存在以下风险：
- **策略复杂度高**：需要在同一条 Bucket Policy 中同时处理 Allow 和 Deny，路径前缀的正则匹配容易出错。
- **人为失误风险大**：一次策略修改错误可能导致全桶数据暴露，或导致公共文件无法访问。
- **权限边界模糊**：IAM Policy 与 Bucket Policy 叠加后，调试权限问题困难。
- **运维耦合度高**：公共文件与私有文件共享同一套生命周期、备份、监控配置，难以独立调整。

**决策：采用双桶隔离方案。**

使用两个独立的 S3 存储桶：
- **公开桶（Public Bucket）**：存放头像、商品图、Logo 等可公开访问的资源。
- **私有桶（Private Bucket）**：存放合同、隐私照片、内部文档等必须通过服务端授权才能访问的资源。

---

## 2. 方案对比

| 对比项 | 单桶路径隔离 | 双桶隔离（推荐） |
|--------|-------------|-----------------|
| **权限边界** | 依赖路径前缀，边界模糊 | 物理隔离，边界天然清晰 |
| **Bucket Policy 复杂度** | 高（需同时处理 public/private） | 低（公开桶只需一条 Allow） |
| **人为失误影响范围** | 可能导致全桶暴露 | 仅影响单个桶 |
| **IAM Policy 粒度** | 需精确到路径 | 精确到桶即可 |
| **CDN 配置** | 统一域名，需配置路径回源规则 | 独立域名，配置简单 |
| **生命周期管理** | 共享规则，需按路径过滤 | 独立规则，灵活配置 |
| **监控与审计** | 混合日志，需额外过滤 | 独立日志，天然隔离 |
| **成本** | 一个桶，费用最低 | 两个桶，费用略增（可忽略） |
| **运维复杂度** | 高（策略调试困难） | 低（策略独立、简单） |

## 3. 双桶设计

### 3.1 桶命名规范

| 桶类型 | 示例命名 | 说明 |
|--------|---------|------|
| 公开桶 | `ipuff-public-assets-{env}` | 环境变量区分 prod/dev/test |
| 私有桶 | `ipuff-private-assets-{env}` | 环境变量区分 prod/dev/test |

> 命名建议：使用组织前缀 + 业务语义 + 环境标识，避免与其他项目冲突。

## 4. 权限配置

### 4.1 公开桶：Bucket Policy

公开桶允许匿名读取所有对象，但禁止匿名写入/删除。

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowPublicRead",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::ipuff-public-assets-prod/*"
    }
  ]
}
```

同时，确保公开桶的 **Block Public Access** 设置中，仅关闭 "Block public access to buckets and objects granted through new public bucket policies"，允许通过 Bucket Policy 开放公共读取。

### 4.2 私有桶：Bucket Policy

私有桶不配置任何允许匿名访问的 Bucket Policy，默认拒绝所有未授权请求。

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyAllUnauthenticatedAccess",
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:*",
      "Resource": [
        "arn:aws:s3:::ipuff-private-assets-prod",
        "arn:aws:s3:::ipuff-private-assets-prod/*"
      ],
      "Condition": {
        "StringNotEquals": {
          "aws:PrincipalType": "Account"
        }
      }
    }
  ]
}
```

> 更简单的做法：私有桶完全不配置 Bucket Policy，S3 默认拒绝所有匿名请求。上述 Deny 策略仅作为安全加固，防止未来误操作。

### 4.3 私有桶：Block Public Access

私有桶必须启用全部四项 Block Public Access：
- Block new public ACLs and uploading public objects
- Remove public access granted through public ACLs
- Block new public bucket policies
- Block public and cross-account access to buckets and objects through any public bucket policies

### 4.4 业务端 IAM Policy

为 Java 服务端应用创建独立的 IAM 用户：

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicBucketPutAndGet",
      "Effect": "Allow",
      "Action": [
        "s3:PutObject",
        "s3:GetObject"
      ],
      "Resource": "arn:aws:s3:::ipuff-public-assets-prod/*"
    },
    {
      "Sid": "PrivateBucketPutAndGet",
      "Effect": "Allow",
      "Action": [
        "s3:PutObject",
        "s3:GetObject"
      ],
      "Resource": "arn:aws:s3:::ipuff-private-assets-prod/*"
    }
  ]
}
```

### 4.5 管理后台 IAM Policy

管理后台需要额外删除权限：

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicBucketFullAccess",
      "Effect": "Allow",
      "Action": [
        "s3:PutObject",
        "s3:GetObject",
        "s3:DeleteObject",
        "s3:ListBucket"
      ],
      "Resource": [
        "arn:aws:s3:::ipuff-public-assets-prod",
        "arn:aws:s3:::ipuff-public-assets-prod/*"
      ]
    },
    {
      "Sid": "PrivateBucketFullAccess",
      "Effect": "Allow",
      "Action": [
        "s3:PutObject",
        "s3:GetObject",
        "s3:DeleteObject",
        "s3:ListBucket"
      ],
      "Resource": [
        "arn:aws:s3:::ipuff-private-assets-prod",
        "arn:aws:s3:::ipuff-private-assets-prod/*"
      ]
    }
  ]
}
```

> **最小权限原则**：生产环境中，业务端与管理后台应使用不同的 IAM 用户，AK/SK 严格隔离。业务端不应持有 `s3:DeleteObject` 权限。

## 5. CORS 配置

两个桶都需要配置 CORS，允许前端域名的 `PUT` 和 `GET` 请求。

```xml
<CORSConfiguration>
  <CORSRule>
    <AllowedOrigin>https://your-domain.com</AllowedOrigin>
    <AllowedOrigin>https://admin.your-domain.com</AllowedOrigin>
    <AllowedMethod>PUT</AllowedMethod>
    <AllowedMethod>GET</AllowedMethod>
    <AllowedHeader>*</AllowedHeader>
    <MaxAgeSeconds>3000</MaxAgeSeconds>
  </CORSRule>
</CORSConfiguration>
```

> 公开桶和私有桶的 CORS 配置可以相同，也可以分别限制（如私有桶只允许 admin 域名）。

## 6. 双桶的 Java 代码层适配思路

以下为实现双桶隔离的代码设计建议（仅供参考，后续迭代实现）。

### 6.1 配置属性类扩展

```java
@Data
@ConfigurationProperties(prefix = "s3")
public class S3Properties {
    private String accessKey;
    private String secretKey;
    private String region = "ap-southeast-1";
    private String endpoint;

    /** 公开桶名称 */
    private String publicBucket;

    /** 私有桶名称 */
    private String privateBucket;

    /** 公开桶 CDN 域名 */
    private String publicCdnDomain;
}
```

### 6.2 文件可见性枚举

```java
public enum VisibilityEnum {
    PUBLIC,   // 公开桶
    PRIVATE   // 私有桶
}
```

### 6.3 上传请求 DTO

```java
@Data
public class PresignedUploadRequestDTO {
    @NotBlank
    private String fileName;

    @NotBlank
    private String contentType;

    /** 文件类型（IMAGE / DOCUMENT / VIDEO / AUDIO / GENERIC） */
    private String fileType;

    /** 可见性：PUBLIC（公开桶）或 PRIVATE（私有桶） */
    private VisibilityEnum visibility;
}
```

### 6.4 服务端生成 objectKey 时选择桶

```java
public PresignedUploadResponseDTO getUploadUrl(PresignedUploadRequestDTO requestDTO) {
    FileTypeEnum fileType = FileTypeEnum.fromName(requestDTO.getFileType());

    // Content-Type 校验
    if (!fileType.matchesContentType(requestDTO.getContentType())) {
        throw new IllegalArgumentException("Content-Type 不匹配");
    }

    // 确定使用哪个桶
    VisibilityEnum visibility = requestDTO.getVisibility();
    if (visibility == null) {
        visibility = fileType.isDefaultPublic() ? VisibilityEnum.PUBLIC : VisibilityEnum.PRIVATE;
    }

    String bucket = visibility == VisibilityEnum.PUBLIC
            ? s3Properties.getPublicBucket()
            : s3Properties.getPrivateBucket();

    String objectKey = fileType.getPathPrefix() + LocalDate.now() + "/"
            + UUID.randomUUID() + "-" + requestDTO.getFileName();

    String presignedUrl = s3PresignedService.generateUploadUrl(
            bucket, objectKey,
            fileType.getExpireMinutes(),
            requestDTO.getContentType(),
            fileType.getMaxSize()
    );

    PresignedUploadResponseDTO response = new PresignedUploadResponseDTO();
    response.setPresignedUrl(presignedUrl);
    response.setObjectKey(objectKey);
    response.setBucket(bucket);
    response.setVisibility(visibility);
    return response;
}
```

### 6.5 下载时区分桶类型

```java
public String getDownloadUrl(String bucket, String objectKey, int expireMinutes) {
    if (bucket.equals(s3Properties.getPublicBucket())) {
        // 公开桶：直接返回 CDN/源站 URL
        return buildPublicUrl(objectKey);
    }
    // 私有桶：生成预签名 URL
    return s3PresignedService.generateDownloadUrl(bucket, objectKey, expireMinutes);
}

public String buildPublicUrl(String objectKey) {
    if (s3Properties.getPublicCdnDomain() != null && !s3Properties.getPublicCdnDomain().isBlank()) {
        return s3Properties.getPublicCdnDomain() + "/" + objectKey;
    }
    return "https://" + s3Properties.getPublicBucket() + ".s3."
            + s3Properties.getRegion() + ".amazonaws.com/" + objectKey;
}
```

## 8. CDN 配置建议

| 项 | 公开桶 | 私有桶 |
|----|--------|--------|
| **CDN 加速** | 必须配置，提升全球访问速度 | 不建议配置（或配置 signed URL） |
| **回源鉴权** | 可选（Origin Access Identity） | 必须（防止绕过 CDN 直访源站） |
| **缓存策略** | 长期缓存（图片/视频不变） | 短期缓存或不缓存 |
| **HTTPS** | 强制 HTTPS | 强制 HTTPS |

### 8.1 AWS CloudFront + S3 公开桶配置

1. 创建 CloudFront Distribution，Origin 指向公开桶。
2. 配置 OAI（Origin Access Identity），只允许 CloudFront 回源。
3. 公开桶的 Bucket Policy 中，只允许 OAI 的 ARN 访问。
4. 前端访问 `https://d1234567890.cloudfront.net/images/avatars/...`

## 9. 安全与最佳实践

| 实践项 | 说明 |
|--------|------|
| **双桶命名不可预测** | 桶名称包含随机后缀或环境标识，降低被恶意扫描的风险。 |
| **私有桶启用全部 Block Public Access** | 彻底杜绝任何公共访问入口。 |
| **业务端与管理端 AK/SK 隔离** | 业务端 IAM 用户不持有 `s3:DeleteObject`，管理后台独立 IAM 用户持有完整权限。 |
| **服务端控制桶选择和路径** | 客户端只传 `visibility` 和 `fileType`，具体桶名和路径前缀由服务端决定。 |
| **预签名 URL 短时效** | 上传 URL 5 分钟，下载 URL 30 分钟。 |
| **操作审计** | 开启 S3 Server Access Logging 或 Event Notification，两个桶独立审计。 |
| **生命周期管理** | 公开桶可配置长期归档（如图片 1 年后转 Glacier）；私有桶的临时文件（如 temp/）可配置 7 天自动删除。 |
| **跨区域复制（可选）** | 公开桶可开启跨区域复制，提升可用性；私有桶根据合规要求决定是否复制。 |

## 10. 流程总结

```
上传流程：
  客户端 -> 服务端申请上传 URL（携带 fileType + visibility=PUBLIC/PRIVATE）
  服务端 -> 根据 visibility 选择 public-bucket 或 private-bucket
  服务端 -> 生成 objectKey（如 images/2026-05-09/uuid-file.png）
  服务端 -> 生成预签名 PUT URL 返回
  客户端 -> 直传到对应的桶

下载流程（公开桶）：
  客户端 -> 直接访问 CDN URL（如 https://cdn.example.com/images/avatars/...）

下载流程（私有桶）：
  客户端 -> 向服务端申请下载 URL（携带 bucket + objectKey）
  服务端 -> 识别为私有桶，生成预签名 GET URL
  客户端 -> 使用预签名 URL 下载（有时效限制）
```

## 11. 运维检查清单

部署前请确认以下配置已完成：

- [ ] 创建公开桶 `ipuff-public-assets-{env}` 和私有桶 `ipuff-private-assets-{env}`
- [ ] 公开桶配置 Bucket Policy（仅允许 GetObject）
- [ ] 私有桶启用全部四项 Block Public Access
- [ ] 两个桶都配置 CORS（限定前端域名）
- [ ] 创建业务端 IAM 用户（仅 PutObject + GetObject）
- [ ] 创建管理后台 IAM 用户（PutObject + GetObject + DeleteObject + ListBucket）
- [ ] 公开桶配置 CDN 加速（CloudFront / 其他 CDN）
- [ ] 公开桶配置 OAI 回源鉴权
- [ ] 配置 S3 Server Access Logging 或 Event Notification
- [ ] 配置生命周期规则（公开桶归档、私有桶临时文件清理）
- [ ] 测试公开文件是否可直接访问
- [ ] 测试私有文件是否只能通过预签名 URL 访问
- [ ] 测试匿名用户是否无法访问私有桶
