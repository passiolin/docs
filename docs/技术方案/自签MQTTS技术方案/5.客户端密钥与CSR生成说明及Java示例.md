# 客户端密钥与 CSR 生成说明及 Java 示例

## 一、客户端 CSR 所需信息

客户端（IoT 设备）在申请设备证书前，需在本地生成密钥对并构造 **CSR（Certificate Signing Request，证书签名请求）**。CSR 中包含设备的公钥和主体信息，由设备端私钥签名后提交给服务端，服务端校验无误后使用中间 CA 私钥签发正式证书。

### 1. Subject 主体信息（Distinguished Name）

| 字段 | OID / 缩写 | 说明 | 示例 |
|:---|:---|:---|:---|
| **Common Name** | `CN` | **设备序列号（SN）**，必须与调用 `/api/v1/cert/request` 时传入的 `sn` 完全一致 | `DEV-SN-12345678` |
| **Organization** | `O` | 组织/公司名 | `ipuff.online Inc.` |
| **Organizational Unit** | `OU` | 部门/单位（可选） | `IoT Device` |
| **Country** | `C` | 国家代码（ISO 3166-1 alpha-2） | `US` |
| **State or Province** | `ST` | 省/州（可选） | `California` |
| **Locality** | `L` | 城市（可选） | `San Francisco` |

> **重要**：CSR 中的 `CN` 必须与请求体中的 `sn` 字段**完全一致**，否则服务端会返回错误码 `40004`。

### 2. 密钥算法与长度

| 项目 | 推荐值 | 说明 |
|:---|:---|:---|
| **算法** | RSA | 兼容性最佳，推荐 |
| **密钥长度** | 2048 位 | 满足 NIST / PCI DSS 等主流合规要求 |
| **签名算法** | SHA-256 | `SHA256withRSA` 为当前主流 |

### 3. CSR 标准结构

| 组成部分 | 说明 |
|:---|:---|
| **Subject** | 设备身份信息（如上表） |
| **SubjectPublicKeyInfo** | 设备公钥 |
| **Attributes** | 可选扩展属性（如挑战密码、SAN 请求等），IoT 场景通常留空 |
| **Signature** | 使用设备私钥对整个 CSR 的签名，证明公钥归属 |

### 4. 私钥安全原则

- **设备端本地生成**：私钥在设备内部安全模块中产生，**永不出设备**
- **安全存储**：建议使用硬件安全模块（HSM）、安全元件（SE）或 TrustZone 等可信执行环境
- **不可恢复**：私钥丢失后只能重新生成密钥对并申请新证书，服务端不保存设备私钥

## 二、Java 生成密钥对与 CSR 示例

以下示例使用 **BouncyCastle** 库，在设备端生成 RSA 密钥对及 PKCS#10 格式的 CSR。

### Maven 依赖

```xml
<dependency>
    <groupId>org.bouncycastle</groupId>
    <artifactId>bcprov-jdk18on</artifactId>
    <version>1.78</version>
</dependency>
```

### 完整代码

```java
import org.bouncycastle.asn1.x500.X500Name;
import org.bouncycastle.operator.ContentSigner;
import org.bouncycastle.operator.jcajce.JcaContentSignerBuilder;
import org.bouncycastle.pkcs.PKCS10CertificationRequest;
import org.bouncycastle.pkcs.jcajce.JcaPKCS10CertificationRequestBuilder;
import org.bouncycastle.util.io.pem.PemObject;
import org.bouncycastle.util.io.pem.PemWriter;

import java.io.StringWriter;
import java.security.*;

public class DeviceCsrGenerator {

    public static void main(String[] args) throws Exception {
        // 1. 注册 BouncyCastle 安全提供者
        Security.addProvider(new org.bouncycastle.jce.provider.BouncyCastleProvider());

        // 2. 生成 RSA 2048 密钥对
        KeyPairGenerator keyGen = KeyPairGenerator.getInstance("RSA", "BC");
        keyGen.initialize(2048, new SecureRandom());
        KeyPair keyPair = keyGen.generateKeyPair();

        // 3. 设备序列号（SN）
        String deviceSn = "DEV-SN-12345678";

        // 4. 构建 Subject
        X500Name subject = new X500Name(
                "C=US, ST=California, L=San Francisco, O=ipuff.online Inc., OU=IoT Device, CN=" + deviceSn
        );

        // 5. 构建 CSR（PKCS#10）
        JcaPKCS10CertificationRequestBuilder csrBuilder =
                new JcaPKCS10CertificationRequestBuilder(subject, keyPair.getPublic());

        // 可选：添加自定义属性（如挑战密码），IoT 场景通常不需要
        // csrBuilder.addAttribute(PKCSObjectIdentifiers.pkcs_9_at_challengePassword,
        //         new DERPrintableString("password"));

        // 6. 使用设备私钥签名 CSR
        ContentSigner signer = new JcaContentSignerBuilder("SHA256withRSA")
                .setProvider("BC")
                .build(keyPair.getPrivate());

        PKCS10CertificationRequest csr = csrBuilder.build(signer);

        // 7. 输出 PEM
        System.out.println("========== 设备私钥 (Private Key) ==========");
        System.out.println(toPem("PRIVATE KEY", keyPair.getPrivate().getEncoded()));

        System.out.println("========== 证书签名请求 (CSR) ==========");
        System.out.println(toPem("CERTIFICATE REQUEST", csr.getEncoded()));

        // 8. 验证 CSR 自签名（确保私钥与公钥匹配）
        if (csr.isSignatureValid(
                new org.bouncycastle.pkcs.jcajce.JcaPKCS10CertificationRequestVerifierProviderBuilder()
                        .setProvider("BC")
                        .build(keyPair.getPublic()))) {
            System.out.println("CSR 自签名验证通过：公钥与私钥匹配。");
        }
    }

    private static String toPem(String type, byte[] data) throws Exception {
        StringWriter sw = new StringWriter();
        try (PemWriter pw = new PemWriter(sw)) {
            pw.writeObject(new PemObject(type, data));
        }
        return sw.toString();
    }
}
```

### 运行结果说明

程序输出两段 PEM：

1. **`PRIVATE KEY`** —— 设备私钥，**仅保存在设备端安全存储中，永不对外传输**
2. **`CERTIFICATE REQUEST`** —— CSR，包含设备公钥和主体信息，通过 HTTPS POST 提交到服务端 `/api/v1/cert/request`

### 提交示例

设备端将生成的 CSR 拼接到 JSON 请求体中：

```json
{
  "sn": "DEV-SN-12345678",
  "csr": "-----BEGIN CERTIFICATE REQUEST-----\nMIICvDCCAaQCAQAwdzELMAkGA1UEBhMCVVMxEzARBgNVBAgMCkNhbGlmb3JuaWEx\n...\n-----END CERTIFICATE REQUEST-----\n"
}
```

> 若设备端因硬件限制**无法生成 CSR**，可不传 `csr` 字段，由服务端代为生成密钥对并签发证书（详见《自签 MQTTS 技术方案》）。

### 安全建议

- **私钥永不出设备**：私钥不得通过任何网络接口、日志或调试信息泄露
- **安全存储**：在具备条件的设备上，私钥应存储在硬件安全模块（HSM）、安全元件（SE）或 TrustZone 等可信执行环境中
- **密钥隔离**：不同设备必须使用不同的密钥对，禁止多设备共用同一私钥
- **CSR 校验**：设备端可在发送前调用 `csr.isSignatureValid()` 验证 CSR 的完整性，确保私钥与公钥正确对应
