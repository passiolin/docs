# 设备证书签发说明与 Java 示例

## 一、设备证书所需信息

设备证书（通信证书）由**中间 CA 私钥**签名，用于 MQTTS 连接时的**客户端身份认证**（mTLS 双向认证）。服务端收到设备端的 SN 和 CSR 后，校验 CSR 合法性，使用中间 CA 私钥签发正式证书并返回给设备。

### 1. Subject 主体信息（来自 CSR）

| 字段 | OID / 缩写 | 说明 | 来源 |
|:---|:---|:---|:---|
| **Common Name** | `CN` | 设备序列号（SN），必须与请求体中的 `sn` 完全一致 | **从 CSR 中提取** |
| **Organization** | `O` | 组织/公司名 | 从 CSR 中提取 |
| **Organizational Unit** | `OU` | 部门/单位（可选） | 从 CSR 中提取 |
| **Country** | `C` | 国家代码 | 从 CSR 中提取 |
| **State or Province** | `ST` | 省/州（可选） | 从 CSR 中提取 |
| **Locality** | `L` | 城市（可选） | 从 CSR 中提取 |

> **重要**：服务端必须校验 CSR 中的 `CN` 与请求体中的 `sn` 是否一致，不一致则返回错误码 `40004`。

### 2. 密钥算法与长度

| 项目 | 推荐值 | 说明 |
|:---|:---|:---|
| **算法** | RSA | 由设备端 CSR 中的公钥决定 |
| **密钥长度** | 2048 位 | 由设备端 CSR 中的公钥决定 |
| **签名算法** | SHA-256 | `SHA256withRSA`，与中间 CA 保持一致 |

### 3. 标准扩展（X509v3 Extensions）

| 扩展名 | 必需 | 值 / 说明 |
|:---|:---|:---|
| **BasicConstraints** | 是 | `CA:FALSE`（明确标识为终端实体证书，不可签发其他证书） |
| **KeyUsage** | 是 | `DigitalSignature`（数字签名，用于 TLS 握手认证） |
| **ExtendedKeyUsage** | 是 | `clientAuth`（客户端身份认证） |
| **SubjectKeyIdentifier** | 是 | 主体密钥标识符，从 CSR 中公钥计算 |
| **AuthorityKeyIdentifier** | 是 | 指向签发者（中间 CA）的公钥标识 |

### 4. 有效期

- 设备证书有效期通常设为 **1 ~ 3 年**
- 应明显短于中间 CA，便于定期轮转且不影响证书链结构

### 5. 序列号

- 必须为唯一的正整数
- 建议采用随机大整数或数据库自增 ID，避免与已有证书冲突

## 二、服务端处理流程

```
接收请求 (SN + CSR)
    │
    ▼
校验 SN 格式合法性 ──否──▶ 返回 40003
    │
    ▼
查询数据库，SN 是否已登记 ──否──▶ 返回 40401
    │
    ▼
解析 CSR ──失败──▶ 返回 40002
    │
    ▼
校验 CSR.CN == SN ──否──▶ 返回 40004
    │
    ▼
读取中间 CA 私钥
    │
    ▼
签发设备证书（标记旧证为被替代）
    │
    ▼
返回：设备证书 + 中间 CA 证书（证书链）
```

> 若请求未包含 `csr`，则服务端代为生成密钥对及 CSR，再执行上述签发流程（详见《自签 MQTTS 技术方案》）。

## 三、Java 签发设备证书示例

以下示例使用 **BouncyCastle** 库，演示服务端如何解析 CSR、校验、并使用中间 CA 私钥签发设备证书。

### Maven 依赖

```xml
<dependency>
    <groupId>org.bouncycastle</groupId>
    <artifactId>bcprov-jdk18on</artifactId>
    <version>1.78</version>
</dependency>
```

### 完整代码

```java
import org.bouncycastle.asn1.x500.X500Name;
import org.bouncycastle.asn1.x509.*;
import org.bouncycastle.cert.X509v3CertificateBuilder;
import org.bouncycastle.cert.jcajce.JcaX509CertificateConverter;
import org.bouncycastle.cert.jcajce.JcaX509ExtensionUtils;
import org.bouncycastle.openssl.PEMKeyPair;
import org.bouncycastle.openssl.PEMParser;
import org.bouncycastle.openssl.jcajce.JcaPEMKeyConverter;
import org.bouncycastle.operator.ContentSigner;
import org.bouncycastle.operator.jcajce.JcaContentSignerBuilder;
import org.bouncycastle.pkcs.PKCS10CertificationRequest;
import org.bouncycastle.util.io.pem.PemObject;
import org.bouncycastle.util.io.pem.PemWriter;

import java.io.StringReader;
import java.io.StringWriter;
import java.math.BigInteger;
import java.security.*;
import java.security.cert.X509Certificate;
import java.util.Date;

public class DeviceCertIssuer {

    /**
     * 中间 CA 证书 PEM 字符串（用于提取 Issuer 和 AKI）
     */
    private static final String INTERMEDIATE_CA_CERT_PEM = """
            -----BEGIN CERTIFICATE-----
            MIIDXTCCAkWgAwIBAgIQC2Z...（请替换为实际中间 CA 证书内容）
            -----END CERTIFICATE-----
            """;

    /**
     * 中间 CA 私钥 PEM 字符串（用于签名设备证书）
     */
    private static final String INTERMEDIATE_CA_KEY_PEM = """
            -----BEGIN PRIVATE KEY-----
            MIIEvQIBADANBgkqhkiG9w0B...（请替换为实际中间 CA 私钥内容）
            -----END PRIVATE KEY-----
            """;

    /**
     * 客户端 CSR PEM 字符串
     */
    private static final String CLIENT_CSR_PEM = """
            -----BEGIN CERTIFICATE REQUEST-----
            MIICvDCCAaQCAQAwdzELMAkGA1UEBhMCVVMxEzARBgNVBAgMCkNhbGlmb3JuaWEx
            ...（请替换为实际 CSR 内容）
            -----END CERTIFICATE REQUEST-----
            """;

    public static void main(String[] args) throws Exception {
        // 1. 注册 BouncyCastle 安全提供者
        Security.addProvider(new org.bouncycastle.jce.provider.BouncyCastleProvider());

        // 2. 加载中间 CA 证书和私钥
        X509Certificate intermediateCert = loadCertificate(INTERMEDIATE_CA_CERT_PEM);
        PrivateKey intermediatePrivateKey = loadPrivateKey(INTERMEDIATE_CA_KEY_PEM);

        // 3. 解析客户端 CSR
        PKCS10CertificationRequest csr = loadCsr(CLIENT_CSR_PEM);

        // 4. 获取请求中的 SN（实际场景来自 HTTP 请求体）
        String requestSn = "DEV-SN-12345678";

        // 5. 从 CSR 中提取 Subject 和公钥
        X500Name subject = csr.getSubject();
        String csrCn = subject.getRDNs(org.bouncycastle.asn1.x500.style.BCStyle.CN)[0]
                .getFirst().getValue().toString();
        SubjectPublicKeyInfo publicKeyInfo = csr.getSubjectPublicKeyInfo();

        // 6. 校验：CSR 中的 CN 必须与 SN 一致
        if (!requestSn.equals(csrCn)) {
            throw new IllegalArgumentException(
                    "CSR 中的 CN(" + csrCn + ") 与请求 SN(" + requestSn + ") 不一致"
            );
        }
        System.out.println("✓ CSR CN 校验通过: " + csrCn);

        // 7. 构建 Issuer（中间 CA Subject）
        X500Name issuer = new X500Name(intermediateCert.getSubjectX500Principal().getName());

        // 8. 有效期：3 年
        long now = System.currentTimeMillis();
        Date notBefore = new Date(now);
        Date notAfter = new Date(now + 3L * 365 * 24 * 60 * 60 * 1000);

        // 9. 随机序列号
        BigInteger serialNumber = new BigInteger(160, new SecureRandom());

        // 10. 构造证书 Builder
        X509v3CertificateBuilder certBuilder = new X509v3CertificateBuilder(
                issuer,           // issuer = 中间 CA Subject
                serialNumber,
                notBefore,
                notAfter,
                subject,          // subject = CSR 中的 Subject（设备身份）
                publicKeyInfo     // 公钥 = CSR 中的公钥
        );

        // 11. 添加扩展
        JcaX509ExtensionUtils extUtils = new JcaX509ExtensionUtils();

        // SubjectKeyIdentifier（从 CSR 公钥计算）
        PublicKey devicePublicKey = org.bouncycastle.openssl.jcajce.JcaPEMKeyConverter
                .getPublicKey(publicKeyInfo);
        certBuilder.addExtension(
                Extension.subjectKeyIdentifier,
                false,
                extUtils.createSubjectKeyIdentifier(devicePublicKey)
        );

        // AuthorityKeyIdentifier（指向中间 CA 的公钥）
        certBuilder.addExtension(
                Extension.authorityKeyIdentifier,
                false,
                extUtils.createAuthorityKeyIdentifier(intermediateCert)
        );

        // BasicConstraints: CA = false
        certBuilder.addExtension(
                Extension.basicConstraints,
                true,
                new BasicConstraints(false)
        );

        // KeyUsage: DigitalSignature
        certBuilder.addExtension(
                Extension.keyUsage,
                true,
                new KeyUsage(KeyUsage.digitalSignature)
        );

        // ExtendedKeyUsage: clientAuth
        certBuilder.addExtension(
                Extension.extendedKeyUsage,
                false,
                new ExtendedKeyUsage(new KeyPurposeId[]{ KeyPurposeId.id_kp_clientAuth })
        );

        // 12. 使用中间 CA 私钥签名
        ContentSigner signer = new JcaContentSignerBuilder("SHA256withRSA")
                .setProvider("BC")
                .build(intermediatePrivateKey);

        X509Certificate deviceCert = new JcaX509CertificateConverter()
                .setProvider("BC")
                .getCertificate(certBuilder.build(signer));

        // 13. 输出 PEM
        System.out.println("========== 设备证书 (Device Certificate) ==========");
        System.out.println(toPem("CERTIFICATE", deviceCert.getEncoded()));

        System.out.println("========== 中间 CA 证书 (Intermediate CA) ==========");
        System.out.println(toPem("CERTIFICATE", intermediateCert.getEncoded()));

        System.out.println("========== 证书链验证 ==========");
        deviceCert.verify(intermediateCert.getPublicKey());
        System.out.println("证书链验证通过：设备证书已由中间 CA 正确签名。");
    }

    private static X509Certificate loadCertificate(String pem) throws Exception {
        try (PEMParser parser = new PEMParser(new StringReader(pem))) {
            Object obj = parser.readObject();
            return new JcaX509CertificateConverter()
                    .setProvider("BC")
                    .getCertificate((org.bouncycastle.cert.X509CertificateHolder) obj);
        }
    }

    private static PrivateKey loadPrivateKey(String pem) throws Exception {
        try (PEMParser parser = new PEMParser(new StringReader(pem))) {
            Object obj = parser.readObject();
            if (obj instanceof PEMKeyPair) {
                return new JcaPEMKeyConverter()
                        .setProvider("BC")
                        .getKeyPair((PEMKeyPair) obj)
                        .getPrivate();
            } else if (obj instanceof PrivateKey) {
                return (PrivateKey) obj;
            } else {
                throw new IllegalArgumentException("不支持的私钥格式: " + obj.getClass());
            }
        }
    }

    private static PKCS10CertificationRequest loadCsr(String pem) throws Exception {
        try (PEMParser parser = new PEMParser(new StringReader(pem))) {
            Object obj = parser.readObject();
            if (obj instanceof PKCS10CertificationRequest) {
                return (PKCS10CertificationRequest) obj;
            } else {
                throw new IllegalArgumentException("不支持的 CSR 格式: " + obj.getClass());
            }
        }
    }

    private static String toPem(String type, byte[] data) throws Exception {
        StringWriter sw = new StringWriter();
        try (PemWriter pw = new PemWriter(sw)) {
            pw.writeObject(new PemObject(type, data));
        }
        return sw.toString();
    }
}
```

### 运行结果说明

程序输出两段 PEM：

1. **`CERTIFICATE`** —— 设备证书（通信证书），下发给设备端，用于 MQTTS 连接时的客户端身份认证
2. **`CERTIFICATE`**（中间 CA）—— 证书链中的中间 CA 证书，随设备证书一并下发，帮助设备端构建完整信任链

设备端收到后，需将以下三部分组合使用：

- 设备证书 + 私钥（私钥始终在设备端本地保存）
- 中间 CA 证书（构建证书链）
- 根证书（预置在设备端，作为信任锚点）

### 安全建议

- **CSR 必须严格校验**：校验 SN 格式、数据库白名单、CSR 解析合法性、CSR.CN 与 SN 一致性，任一环节失败均拒绝签发
- **中间 CA 私钥安全存储**：建议使用加密数据库或 HSM，避免明文落盘
- **旧证标记替代**：同一 SN 申请新证书时，将旧证书标记为被替代（或加入 CRL 吊销列表），防止一机多证带来的安全风险
- **签发日志审计**：记录每次签发的 SN、序列号、签发时间、IP 地址，便于后续安全审计
- **速率限制**：对同一 SN 的证书申请接口增加频率限制，防止恶意刷证
