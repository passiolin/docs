# PVE 存储配置(10.10.10.44)

> - **适用对象**:10.10.10.44 宿主机,PVE 9.2.2,OpenZFS 2.4.2-pve1。
> - **配套**:[README](README.md) 记录拓扑与决策依据;本文只放配置与操作命令。
> - **执行前提**:4TB 盘已过 SMART 体检(README 第六节);nvme1 已清空(旧 `vgnvme` VG 删除、fstab 清理,见 README 执行顺序第 2 步)。

## 一、建池

```bash
# 一律用 by-id,sdX 字母序会漂移
ls /dev/disk/by-id/ | grep -v part

# 新盘若有旧分区表/文件系统,先清掉
sgdisk --zap-all /dev/disk/by-id/ata-HGST_HUS724040ALE641_XXXXXXXX

zpool create -o ashift=12 tank /dev/disk/by-id/ata-HGST_HUS724040ALE641_XXXXXXXX
zpool status tank
```

## 二、数据集

```bash
zfs create -o compression=zstd -o recordsize=64K -o sync=always tank/vm
zfs create -o compression=zstd -o recordsize=1M  tank/iso
zfs get compression,recordsize,sync,logbias tank/vm
```

- `recordsize=64K` 对齐 qcow2 cluster(默认 64K):guest 4K 随机写在 qcow2 内部聚成 64K 读改写,落盘块更大更整,zstd 按此粒度生效;
- `sync=always` 把普通写编入 SLOG 路径,突发写按 NVMe 确认;DB 的 fsync 本就走 SLOG,与开关无关;
- `logbias` 保持默认 `latency`——设成 throughput 会绕开 SLOG,写缓存白插;
- tank/iso 用 1M record:ISO 是大文件顺序读,不吃 sync 加速,与 VM 数据集分开管理。

## 三、加速件:SLOG + L2ARC 分区

```bash
sgdisk --zap-all /dev/nvme1n1
sgdisk -n 1:1MiB:+128GiB -t 1:BF01 /dev/nvme1n1   # SLOG 128G,1MiB 对齐
sgdisk -n 2:0:0          -t 2:BF01 /dev/nvme1n1   # 剩余全部 L2ARC(~766GiB)

zpool add -o ashift=12 tank log   /dev/disk/by-id/nvme1n1-part1
zpool add -o ashift=12 tank cache /dev/disk/by-id/nvme1n1-part2
zpool status tank    # 应出现 log 与 cache 各一条
```

尺寸速记:SLOG 是环形日志,只装"已确认未落盘"的在途写——1GB/s 超额突发顶 ~2.5 分钟,500MB/s 顶 ~6.5 分钟,日常 DB sync 写远不满;填满后任何尺寸都是 180MB/s,瓶颈在磁头,与盘容量无关。L2ARC 只收被读过的数据,RAM 头开销 1–2G。固定切分是篮子原则:SLOG 保命(崩溃一致,缓存盘挂池无损)、L2ARC 可丢,不合并动态共享。

擦写寿命:盘不会被 SLOG 局部磨坏。ZIL 是环形日志,写入在 128G 分区内顺序追加、写满回绕,逻辑地址摊得开;就算写死同一批 LBA,NVMe 主控的 FTL 磨损均衡也会把物理擦写摊到全盘 NAND——主控不认分区,766G L2ARC 和出厂预留空间一起参与均衡,L2ARC 那半写得少,腾挪余地反而更大。所以磨损全盘均匀,坏块出现时是整盘 Percentage Used 爬升、Available Spare 下降,不是 SLOG 那一小块先写穿。

真正要算的是总量:sync=always 让每笔写多过一遍 SLOG,nvme1 年写入量 ≈ 同步写流量,外加 4K 对齐和 txg 元数据的少量放大。当前负载一年几 TB,只是标称几百 TBW 的零头,只有常年上百 MB/s 的同步写才需要重算。余量盯 smartctl 的 Data Units Written(× 512,000 字节 = 累计写入),命令在第六节巡检。

## 四、PVE 存储定义

`/etc/pve/storage.cfg` 增改(目标机配置文件,非仓库路径):

```
dir: tankvm
    path /tank/vm
    content images

dir: tankiso
    path /tank/iso
    content iso,vztmpl,snippets

dir: hdd
    path /hdd
    content backup
    prune-backups keep-daily=7,keep-weekly=4,keep-monthly=3
```

hdd 定义收敛时删除原 images/rootdir 等内容类型(iKUAI 盘迁出后执行);旧 `nvme` 存储定义在数据迁完后 `pvesm remove nvme`。

## 五、克隆操作

日常:PVE 原生完整克隆,池速拷贝(40G 盘约 4 分钟,起始突发由 SLOG 顶起):

```bash
qm clone <源VMID> 139 --full
```

备用:reflink 手动克隆,秒出、语义独立(删源不伤),golden 与克隆须同数据集:

```bash
cp --reflink=always /tank/vm/golden-ubuntu.qcow2 /tank/vm/139/vm-139-disk-0.qcow2
qm set 139 -scsi0 tankvm:139/vm-139-disk-0.qcow2
```

任何方式克隆后,进 guest 清 machine-id 与 SSH host keys(golden 预置开机脚本更省事),避免同网段身份冲突。

## 六、快照与巡检

```bash
# dir+qcow2 下 PVE 界面快照是 qcow2 内部快照(大盘慢),秒级快照走 CLI:
zfs snap tank/vm@pre-test
zfs list -t snapshot
zfs destroy tank/vm@pre-test

# 巡检
zpool status -v            # 错误计数应为 0
zpool iostat -v tank 5     # log/cache 的读写分布可见
arc_summary | grep -iA3 "L2"   # L2ARC 命中率
smartctl -a /dev/nvme1     # 加速盘磨损:Percentage Used / Available Spare / Media and Data Integrity Errors / Data Units Written
```

水位纪律:tank 常态 ≤80%(~3.2T)。CoW 把随机写整编成顺序流依赖空闲连续空间,越满随机写退化越重;反复改写的文件块会渐散(读变慢),重要数据集偶尔 copy 一遍即重新顺序化。
