# PVE 存储配置(10.10.10.44)

> - **适用对象**:10.10.10.44 宿主机,PVE 9.2.2,OpenZFS 2.4.2-pve1。
> - **配套**:[README](README.md) 记录拓扑与决策依据;本文只放配置与操作命令。
> - **执行前提**:4TB 盘已过 SMART 体检(README 第五节);缓存盘(海力士 960G)已清空(旧 `vgnvme` VG 删除、fstab 清理,见 README 执行顺序第 2 步)。
> - **时效**:本文是 2026-10-10 建成的 ZFS 方案(tank)的配置记录;2026-10-16 已整体迁移为 LVM+dm-cache,现态与迁移过程见 [3.LVM缓存迁移与实测](3.LVM缓存迁移与实测.md)。

## 一、建池

```bash
# 一律用 by-id,sdX 字母序会漂移
ls /dev/disk/by-id/ | grep -v part

# 新盘若有旧分区表/文件系统,先清掉
DISK=/dev/disk/by-id/ata-HGST_HUS724040ALA640_PN1338P4H0LDLB   # 4TB HGST 7K4000,体检序列号 PN1338P4H0LDLB
sgdisk --zap-all $DISK

zpool create -o ashift=12 tank $DISK
zpool status tank
```

## 二、数据集

```bash
zfs create -o compression=zstd -o recordsize=64K -o sync=standard -o direct=disabled tank/vm
zfs create -o compression=zstd -o recordsize=1M  -o direct=disabled tank/iso
zfs get compression,recordsize,sync,logbias,direct tank/vm
```

- `recordsize=64K`:VM 随机写聚成 64K 记录落盘,zstd 按此粒度生效(压缩在 ZFS 记录层,与盘格式无关,raw 同样适用);
- **`sync=standard`(2026-10-16 复测定稿)**:guest 串行 fsync 206 IOPS,disabled 仅 117——disabled 下 ZIL 全程旁路、SLOG 流量为 0,fsync 是假确认,串行路径反被 4K→64K 磁头读改写拖住;两档其余差距:顺序写 97 vs 107MB/s(持平),4K 随机写 103 vs 261 IOPS(disabled 快,ext4 barrier 在 standard 下要等 TXG 落磁头)。DB/fsync 型负载用 standard,纯异步灌盘可临时 `zfs set sync=disabled tank/vm`;
- `logbias` 保持默认 `latency`——设成 throughput 会绕开 SLOG,写缓存白插;
- **`direct=disabled`(关键,OpenZFS ≥2.3 才有此属性)**:PVE 的 `cache=none` 磁盘与绝大多数压测工具都走 O_DIRECT,而 `direct=standard`(默认)的回退路径在本池实测把 1M 顺序写压到 4-50MB/s(2026-10-16 复测 49.5MB/s);设为 disabled 后 O_DIRECT 被忽略、恢复经典 buffered 行为,同测试复测 613MB/s(dirty=4G 蓄水确速口径)。4K fsync 延迟不受此属性影响(实测两种模式逐字节持平);
- tank/iso 用 1M record:ISO 是大文件顺序读,不吃 sync 加速,与 VM 数据集分开管理。

## 三、加速件:SLOG + L2ARC 分区

```bash
# 注意:NVMe 枚举名会漂移(2026-10-15 重插后海力士从 nvme1 变成 nvme0,系统盘变成 nvme1),
# 一律用 by-id,以下 NVME 变量指向海力士 960G(缓存盘)
NVME=/dev/disk/by-id/nvme-HFS960GD0MEE-5410A_EI6CQ0678101A1F3U

sgdisk --zap-all $NVME
sgdisk -n 1:1MiB:+128GiB -t 1:BF01 $NVME   # SLOG 128G,1MiB 对齐
sgdisk -n 2:0:0          -t 2:BF01 $NVME   # 剩余全部 L2ARC(~766GiB)

zpool add -o ashift=12 tank log   ${NVME}-part1
zpool add -o ashift=12 tank cache ${NVME}-part2
zpool status tank    # 应出现 log 与 cache 各一条
```

尺寸速记:SLOG 是环形日志,只装"已确认未落盘"的在途写——1GB/s 超额突发顶 ~2.5 分钟,500MB/s 顶 ~6.5 分钟,日常 DB sync 写远不满;填满后任何尺寸都是 180MB/s,瓶颈在磁头,与盘容量无关。L2ARC 只收被读过的数据,RAM 头开销 1–2G。固定切分是篮子原则:SLOG 保命(崩溃一致,缓存盘挂池无损)、L2ARC 可丢,不合并动态共享。

擦写寿命:盘不会被 SLOG 局部磨坏。ZIL 是环形日志,写入在 128G 分区内顺序追加、写满回绕,逻辑地址摊得开;就算写死同一批 LBA,NVMe 主控的 FTL 磨损均衡也会把物理擦写摊到全盘 NAND——主控不认分区,766G L2ARC 和出厂预留空间一起参与均衡,L2ARC 那半写得少,腾挪余地反而更大。所以磨损全盘均匀,坏块出现时是整盘 Percentage Used 爬升、Available Spare 下降,不是 SLOG 那一小块先写穿。

真正要算的是总量:sync=always 让每笔写多过一遍 SLOG,nvme1 年写入量 ≈ 同步写流量,外加 4K 对齐和 txg 元数据的少量放大。当前负载一年几 TB,只是标称几百 TBW 的零头,只有常年上百 MB/s 的同步写才需要重算。余量盯 smartctl 的 Data Units Written(× 512,000 字节 = 累计写入),命令在第六节巡检。

## 四、PVE 存储定义

`/etc/pve/storage.cfg` 现态(2026-10-16 核对实机,目标机配置文件,非仓库路径):

```
dir: local
    path /var/lib/vz
    content backup,iso,vztmpl,import

lvmthin: local-lvm
    thinpool data
    vgname pve
    content images,rootdir

dir: tankvm
    path /tank/vm
    content images

dir: tankiso
    path /tank/iso
    content iso,snippets,vztmpl
```

旧 `nvme`、`hdd` 定义已随迁移移除;备份落点仍未定案(见 README 第三节),定案后按 keep-daily=7,keep-weekly=4,keep-monthly=3 配 prune。

## 五、VM 盘格式与克隆(raw + aio=threads)

VM 盘一律 **raw**,qcow2 不用(2026-10-16 隔离实验定性):同一测试 VM、同一 tankvm、同一套盘参数下,raw 2G 直写 **988MB/s**,qcow2 仅 **146MB/s**——qcow2 的簇分配/元数据路径在 HDD 支撑的池上把写压到 1/7;NVMe 上的 raw LV(114 在 local-lvm)无此罚。qemu 引擎必须 **aio=threads**:PVE 默认 io_uring 对 ZFS 数据集文件的直写严重退化(实测 5.4MB/s)。

盘选项模板(tankvm 上的所有 VM 盘):

```bash
qm set <VMID> -scsi0 tankvm:<卷>,aio=threads,cache=none,discard=on,iothread=1,size=NNG,ssd=1
```

存量 qcow2 在线转换(镜像方式,VM 不停机,失败源卷无损):

```bash
qm move-disk 102 scsi0 tankvm --format raw --delete   # 425G 实测 ~88MB/s,约 1.5-2.5h
```

克隆(PVE 原生,raw 走池速;reflink 备用对 raw 文件同样生效):

```bash
qm clone <源VMID> 139 --full --format raw
# 备用秒级:cp --reflink=always <golden.raw> <新卷.raw> && qm set 139 -scsi0 tankvm:139/<新卷.raw>,aio=threads,...
```

zstd 对 raw 照常生效(压缩发生在 ZFS 记录层,与盘格式无关);raw 失去的只有 PVE 界面的 qcow2 内部快照,数据集级 `zfs snap` 全量覆盖。克隆后进 guest 清 machine-id 与 SSH host keys,避免同网段身份冲突。

## 六、快照与巡检

```bash
# dir+qcow2 下 PVE 界面快照是 qcow2 内部快照(大盘慢),秒级快照走 CLI:
zfs snap tank/vm@pre-test
zfs list -t snapshot
zfs destroy tank/vm@pre-test

# 巡检
zpool status -v            # 错误计数应为 0
zpool iostat -v tank 5     # log/cache 的读写分布可见
arc_summary | grep -iA3 "L2"   # L2ARC 命中率
smartctl -a /dev/disk/by-id/nvme-HFS960GD0MEE-5410A_EI6CQ0678101A1F3U   # 加速盘磨损:Percentage Used / Available Spare / Media and Data Integrity Errors / Data Units Written(勿写 nvme1——枚举漂移后那是系统盘)
```

水位纪律:tank 常态 ≤80%(~3.2T)。CoW 把随机写整编成顺序流依赖空闲连续空间,越满随机写退化越重;反复改写的文件块会渐散(读变慢),重要数据集偶尔 copy 一遍即重新顺序化。
