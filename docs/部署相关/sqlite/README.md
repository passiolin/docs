# SQLite 单机压测与容量选型(sqlite)

> - **版本基线**:SQLite **3.46.1**(2024-08-13,Ubuntu 26.04 仓库 `sqlite3` / `libsqlite3-dev`),系统默认编译选项:`DEFAULT_SYNCHRONOUS=2`、`DEFAULT_CACHE_SIZE=-2000`、`DEFAULT_PAGE_SIZE=4096`、`DEFAULT_MMAP_SIZE=0`。
> - **实测环境**:PVE 10.10.10.44 上的三台虚机 `sqlite-1c2g` / `sqlite-4c2g` / `sqlite-4c8g`(10.10.12.140/141/142,1C2G / 4C2G / 4C8G),Ubuntu 26.04 LTS,内核 7.0.0-27,盘落 local-lvm(NVMe),2026-11-18。
> - **数据规模**:1000 设备 × 365 天 × 1 / 3 / 5 个指标 = 365,000 / 1,095,000 / 1,825,000 行,库文件 20.5 / 63.5 / 106.1 MiB。
> - **结论**:2G 内存足够,单连接查询单核封顶;4C 只在并发读时有约 4 倍收益;8G 对本数据量无增量;空闲 SQLite 进程 3.8–5.8 MiB。

## 组件说明

SQLite 是嵌入式关系数据库:没有服务端进程,应用打开一个文件即用,SQL 编译、事务、页缓存都在本进程内完成。单文件、零配置、public domain,手机、浏览器与嵌入式设备里最常见的数据库引擎。并发模型是单写多读——写事务串行,读连接各持一个 page cache,读吞吐按连接数横向扩展;默认 page cache 只有 2 MB,内存上限主要由此决定,而非库文件大小。

本目录记录的是容量选型实测:同一份 IoT 测点数据,在 1C2G / 4C2G / 4C8G 三种规格下的 CPU、内存与吞吐边界,以及默认配置下的空闲内存占用。
