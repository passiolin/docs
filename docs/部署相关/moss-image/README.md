# MOSS-Image-SFT 本地文生图(moss-image)

> - **形态**:OpenMOSS 的 5B 文生图模型,目标机跑 Gradio 网页 + 命令行两条出口,22G 显存下靠 CPU offload 承载 27.23GB 权重。
> - **实测环境**:2080ti22g(10.10.12.2,RTX 2080 Ti 22G 魔改 / Xeon E5-2698B v3 28 核 / 60G 内存 / Ubuntu 26.04);Python 3.12.16、torch 2.15.0+cu132、diffusers 0.42.1、transformers 5.22.1、Gradio 6.31.0。2026-11-04。
> - **适用场景**:中文提示词出图、画面内中英文文字渲染(手写便签、海报标题)、按 JSON 布局控制文字与物体位置。

## 这个目录在讲什么

MOSS-Image 是 OpenMOSS 团队 2026 年发布的开源文生图模型,SFT 版基于 MOSS-Image-Base 微调,重点能力是画面内文字:中文手写、海报排版、便签清单这类以往扩散模型画不利索的场景。5B 的体量在一张 22G 卡上放不下,只能把文本编码器(Qwen3.5-9B,16.78GB)按需搬上搬下。

27.23GB 权重放不进 22G 显存,只能 offload,空闲时显存只剩 CUDA context;Turing 架构没有 bf16 张量核心,模型卡要求的 bf16 在本机是 fp32 模拟,换 fp16 后单图快 3.7 倍,中文手写便签的笔画依然可读。

同机的 [llamacpp](../llamacpp/README.md) 部署原先常驻 20.7GB 显存,两者不能同时跑,显存让渡的处理见第 1 篇末尾。
