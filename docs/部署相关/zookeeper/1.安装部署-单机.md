# 0. 安装部署-单机

> **实测状态**:✅ 已实测 —— ZooKeeper 3.9.5 standalone(kafka-3 / 10.10.12.130 上独立数据目录与端口),2026-10-01。存活、znode、ephemeral、四字命令与 HTTP admin 全验证。

## 什么时候用单机

给单个中间件(老版本 Kafka、小工具)做协调、开发测试。无容错;客户端连上即可用,协议面与集群零差异。

## 部署(实测命令)

zoo.cfg 与集群版的差异 = **去掉 server.N 拓扑段**(其余全同 [conf/zoo.cfg](conf/zoo.cfg)):

```bash
mkdir -p /data/zk-single/{data,datalog,conf}
cat > /data/zk-single/conf/zoo.cfg <<'EOF'
tickTime=2000
initLimit=10
syncLimit=5
dataDir=/data
dataLogDir=/datalog
clientPort=2181
4lw.commands.whitelist=ruok,mntr,srvr,stat
autopurge.snapRetainCount=3
autopurge.purgeInterval=24
maxClientCnxns=60
EOF
docker run -d --name zookeeper --restart=always --net=host \
  -v /data/zk-single/conf/zoo.cfg:/conf/zoo.cfg \
  -v /data/zk-single/data:/data \
  -v /data/zk-single/datalog:/datalog \
  zookeeper:3.9.5
```

## 验证(实测输出)

```bash
echo ruok | timeout 3 bash -c 'exec 3<>/dev/tcp/127.0.0.1/2181; cat >&3; timeout 2 head -c4 <&3'
# imok
echo srvr | ... | grep Mode      # Mode: standalone   ← 单机的角色标识
echo mntr | ... | head -2
# zk_version 3.9.5-...
# zk_server_state  standalone

docker exec zookeeper zkCli.sh -server 127.0.0.1:2181 create /app v1   # Created /app
docker exec zookeeper zkCli.sh -server 127.0.0.1:2181 create -e /app/eph e1
docker exec zookeeper zkCli.sh -server 127.0.0.1:2181 ls /app          # [eph]
```

## 实测发现:docker 镜像默认开了 HTTP admin server

`http://<host>:8080/commands/mntr` 直接返回 JSON 指标(实测有输出)——**与巡检文档在 Ubuntu 打包版上的结论相反**(打包版未开放,需 zoo.cfg 显式开)。两种部署形态的监控通道因此不同:

- docker 镜像:8080 HTTP(`/commands/mntr` JSON)与 2181 四字命令双通道;
- 打包版:只有四字命令(HTTP 需 `admin.enableServer=true`)。

端口注意:8080 与常见 Web 服务撞名,单机混部时用 `admin.serverPort=` 改掉或 `admin.enableServer=false` 关闭。

## 已知坑(实测)

| 坑 | 现象 | 解 |
| --- | --- | --- |
| 启动 12 秒内四字命令空 | 首启未完成,像白名单没配 | 等到日志 Started 再验 |
| zkCli 建子节点报 `Node does not exist: <子路径>` | 父节点不存在(文案误导,见第 4 篇) | 先建父 |
