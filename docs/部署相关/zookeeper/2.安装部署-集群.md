# 2. 安装部署-集群

> **实测状态**:✅ 已实测 —— ZooKeeper 3.9.5,三节点 ensemble(zk-1/2/3,`--net=host`),2026-09-30。从启动到选出 leader 约 20 秒。

## 拓扑

```
zk-1 10.10.12.131  follower(ZOO_MY_ID=1)
zk-2 10.10.12.132  follower/leader(ZOO_MY_ID=2)
zk-3 10.10.12.133  follower(ZOO_MY_ID=3)
端口:2181 客户端;2888 follower→leader;3888 选举
```

三节点是起步配置(容忍 1 台故障);五节点容忍 2 台,只有在大规模客户端或更高容错要求时才值得。

## 部署

配置模板见 [conf/zoo.cfg](conf/zoo.cfg)(三台内容完全一致),节点差异只有 `ZOO_MY_ID`:

```bash
mkdir -p /data/zookeeper/{data,datalog,conf}
cp zoo.cfg /data/zookeeper/conf/zoo.cfg
docker run -d --name zookeeper --restart=always --net=host \
  -e ZOO_MY_ID=1 \
  -v /data/zookeeper/conf/zoo.cfg:/conf/zoo.cfg \
  -v /data/zookeeper/data:/data \
  -v /data/zookeeper/datalog:/datalog \
  zookeeper:3.9.5
```

要点:
- `ZOO_MY_ID` 必须与 zoo.cfg 里 `server.N` 的 N 对应(镜像据此写 myid 文件)——**配错不报错,表现为节点互相找不到形成不了 ensemble**(实测排查时优先核对这项);
- 数据目录 `/data` 与事务日志 `/datalog` 分开挂载(生产建议落不同磁盘);
- 三台依次启动,约 20 秒内完成选举。

## 验证(实测输出)

```bash
# 存活(四字命令,需 zoo.cfg 白名单放行,见第 3 篇):
echo ruok | timeout 3 bash -c 'exec 3<>/dev/tcp/127.0.0.1/2181; cat >&3; timeout 2 head -c4 <&3'
# imok

# 角色核对(逐节点):
echo srvr | timeout 3 bash -c 'exec 3<>/dev/tcp/127.0.0.1/2181; cat >&3; timeout 2 grep -m1 Mode <&3'
# 实测:131 Mode: follower / 132 Mode: leader / 133 Mode: follower
```

## 已知坑

1. **四字命令白名单**:官方镜像默认只放行 `srvr`,`ruok/mntr` 直接空响应——zoo.cfg 里 `4lw.commands.whitelist` 必须显式写(巡检 Z01/Z02 的前提);
2. myid 与 server.N 不一致 → ensemble 组不起来,日志只有连接超时,没有明确报错;
3. 2181/2888/3888 三个端口都要在节点间放行,漏 3888 的现象是"能选上但选举慢/反复";
4. **reconfig 权限(2026-10-09 实测)**:`reconfigEnabled=true` 只是开关,执行时还要求 ADMIN——需服务端注入 `-Dzookeeper.DigestAuthenticationProvider.superDigest=super:<base64(sha1("super:super"))>`(JVMFLAGS)+ 客户端 `addauth digest super:super`,否则报 `Insufficient permission`;**observer 节点的 zoo.cfg 也要同样开 reconfigEnabled**,否则 FLE 版本不匹配、永远 LOOKING;
5. **zkCli 管道模式输出首行带 prompt 前缀**(`[zk: …] server.1=…`),脚本化解析别用 `^server\.` 锚行首。
