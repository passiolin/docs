# 3. 数据与命令面

> **实测状态**:✅ 已实测 —— ZooKeeper 3.9.5,znode CRUD、复制一致性、ephemeral 语义全验证(2026-09-30)。

## zkCli(docker 内)

```bash
docker exec zookeeper zkCli.sh -server 127.0.0.1:2181 <命令>
# zkCli 日志刷屏,结果行按"去掉时间戳行"提取,例如:
# docker exec zookeeper zkCli.sh -server 127.0.0.1:2181 get /app/config 2>&1 | grep -v "^2026\|^\[" | grep -v "^$" | tail -2
```

## CRUD 实测与一个必踩的坑

```bash
create /app ""            # Created /app
create /app/config v1     # Created /app/config
get /app/config           # v1
set /app/config v2
create -e /app/lock001 holder   # 临时节点
ls /app                   # [config, lock001]
```

**实测坑:父节点必须先存在**,而 3.9 的报错文案**只报子节点路径**——`create /app/config` 在 `/app` 不存在时报 `Node does not exist: /app/config`,极易误读为"这个节点怎么不存在,我这不正在建吗"(本实验真实踩到,排查了一圈)。层级数据先建父再建子。

## 复制一致性(实测)

在 leader 上 `create /app/config v1` 后,到 **follower 上 get 立即可见 v1**(ZAB 提交后全局可见,线性一致读)。

## ephemeral 语义(实测)

`create -e` 创建的节点**随创建会话结束自动删除**:zkCli 退出后再 `ls /app`,lock001 已消失(只剩 [config])。这就是服务注册/分布式锁的基础语义——客户端断连,节点自动注销。

## 数据文件层

- `/data`(dataDir):快照(snapshot.xxx)+ myid;
- `/datalog`:事务日志(log.xxx);
- 备份 = 停机冷拷 dataDir+datalog(或用官方快照工具);ZK 数据通常小而关键,变更走"记录每次改动的脚本"比备份恢复更常用。
