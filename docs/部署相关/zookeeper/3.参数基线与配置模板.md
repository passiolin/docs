# 3. 参数基线与配置模板

> **实测状态**:✅ 已实测 —— ZooKeeper 3.9.5,模板见 [conf/zoo.cfg](conf/zoo.cfg),已在三节点集群实际应用。

## 按"值由谁拍板"分组

| 组 | 拍板人 | 参数(默认 → 基线) |
| --- | --- | --- |
| 一、节拍与超时 | 网络质量 | tickTime(2000 保持)、initLimit(10 保持)、syncLimit(5 保持) |
| 二、目录 | 部署形态 | dataDir/dataLogDir(分离)、clientPort(2181) |
| 三、拓扑 | 架构 | server.1/2/3(2888:3888) |
| 四、可观测 | 巡检依赖 | **4lw.commands.whitelist(默认仅 srvr → 放行 ruok,mntr,srvr,stat...)** |
| 五、磁盘纪律 | 磁盘 | autopurge.snapRetainCount=3、purgeInterval=24h(**默认不清理!**) |
| 六、连接配额 | 业务 | maxClientCnxns=60 |

**两个默认值必须动的**:

1. **四字命令白名单**:官方镜像默认只放行 `srvr`。巡检主路径(ruok/mntr/stat)全靠它——实测不放行时命令返回空,像挂了一样。按巡检实际用到的命令最小集放行,不要写 `*`。
2. **autopurge 默认关闭**:dataDir 会无限膨胀直到写满盘(巡检 K07 同款问题在 ZK 侧的翻版)。基线 24h 清一次、留 3 份快照。

**可以不动的常识**:tickTime=2000(2 秒节拍)适配绝大多数内网;initLimit/syncLimit 只在网络很差或快照很大时才需要调大。

## 参数的生效方式

ZK 无动态改参通道(3.9 无 SET 等价物):**改 zoo.cfg → 逐台滚动重启**(一次一台,确认 ensemble 恢复再下一台;三节点环境单台重启零感知)。

## 应用与验证

```bash
# 模板即 zoo.cfg,三台一致;节点差异只有 ZOO_MY_ID(第 2 篇)
# 验证白名单生效:
echo mntr | timeout 3 bash -c 'exec 3<>/dev/tcp/127.0.0.1/2181; cat >&3; timeout 2 head -3 <&3'
# zk_version  3.9.5-...
# zk_peer_state  following - broadcast
```
