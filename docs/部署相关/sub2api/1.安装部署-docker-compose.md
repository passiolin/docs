# 安装部署-docker-compose

sub2api 是开源中转网关（GitHub Wei-Shaw/sub2api，LGPL v3）：把订阅制 AI 账号挂到平台后面统一认证、调度、按 token 计费，对外发平台自己的 API Key。Docker Hub `weishaw/sub2api` 累计拉取 186 万次，最新版 0.2.15（2026-10-09），更新节奏是两三天一个版本——本文档以 0.2.x 的 compose 形态为基线，线上入口 `https://sub2api.ipuff.online`，`/health` 返回 `{"status":"ok"}`（2026-10-12 实测）。

## 一、部署形态

三容器一套，应用 + PostgreSQL + Redis，官方 compose 文件直接用本地目录而不是命名卷——整个部署目录 `tar` 起来就能迁走，笔者的两台机器（阿里云国内 + 新加坡）之间就是这么搬的：

```text
sub2api-deploy/
├── docker-compose.yml    # 官方 local 目录版（conf/docker-compose.yml 有模板）
├── .env                  # 全部配置，413 行 .env.example 见 conf/env.example
├── data/                 # 应用数据：config.yaml、日志、模型定价缓存、插件
├── postgres_data/        # PGDATA 整目录
└── redis_data/           # RDB + AOF
```

| 容器 | 镜像 | 端口暴露 |
| --- | --- | --- |
| sub2api | `weishaw/sub2api:<版本>` | `${SERVER_PORT:-8080}:8080` |
| sub2api-postgres | `postgres:18-alpine` | 不暴露（仅内网） |
| sub2api-redis | `redis:8-alpine` | 不暴露（仅内网） |

三个容器都带 healthcheck（`/health`、`pg_isready`、`redis-cli ping`），应用 `depends_on: service_healthy`，PG/Redis 没就绪不启动应用。compose 里 `restart: unless-stopped`、`ulimits nofile 100000` 默认已带。

## 二、前置

Docker 20.10+ 与 compose v2；国内机器提前配好镜像加速——笔者第一台机器 `registry-1.docker.io` 直连不通，改 DNS（`nameserver 223.5.5.5`）加 daemon.json 加速后才拉下来：

```bash
# daemon.json 关键两项（该机数据盘在 /data，顺手把 data-root 挪过去）
{ "log-driver": "json-file",
  "log-opts": { "max-size": "100m", "max-file": "1" },
  "data-root": "/data/docker" } > /etc/docker/daemon.json
```

## 三、配置 .env

从 [conf/env.example](conf/env.example) 复制为 `.env`（`chmod 600`），必填/必改的就这几项，其余保持默认能跑：

```bash
POSTGRES_PASSWORD=<openssl rand -hex 32 生成>
JWT_SECRET=<openssl rand -hex 32 生成>          # 留空则每次重启随机生成，全员掉线
TOTP_ENCRYPTION_KEY=<openssl rand -hex 32 生成> # 留空则重启后所有 2FA 失效
ADMIN_EMAIL=<管理员邮箱>
ADMIN_PASSWORD=<留空则首启随机生成、打印在日志里>
SERVER_PORT=8080
TZ=Asia/Shanghai
```

`JWT_SECRET` 和 `TOTP_ENCRYPTION_KEY` 这两个"留空 = 重启后随机"的坑 compose 注释里专门标了 WARNING：首次部署图省事留空，表现为改天重启后所有人登录态失效、开了 2FA 的人进不去——建站时一次生成、写进 `.env` 就完事。

其余按需再动的三组：

- `RUN_MODE`：`standard` 全量 SaaS（计费/余额校验），`simple` 隐藏 SaaS 功能、跳过计费——纯内部共用选 simple，要对外发 Key 收费用 standard；
- 数据库连接池：`DATABASE_MAX_OPEN_CONNS`（默认 256）总和要小于 PG 侧 `POSTGRES_MAX_CONNECTIONS`（默认 1024）的七八成；
- `GATEWAY_MAX_CONNS_PER_HOST` 等上游连接池参数：流式转发高并发时按账号数调大。

## 四、启动与首登

```bash
cd sub2api-deploy
docker compose up -d
docker compose logs -f sub2api
```

应用启动时自动跑数据库迁移；`ADMIN_PASSWORD` 留空时首次启动从日志取随机密码：

```bash
docker compose logs sub2api | grep "Generated admin"
```

浏览器开 `http://<服务器IP>:8080` 登录后台。`AUTO_SETUP=true` 已在 compose 里写死，初始化向导正常走——上游 README 特意提醒：若手工预建了 `data/config.yaml`，向导会被跳过导致首登失败，标准部署别预建这个文件。

## 五、反向代理与外网访问

线上形态是 nginx（实测 `server: nginx/1.30.4`）终结 TLS 后 `proxy_pass` 到 8080，证书用通配符 `*.ipuff.online`（Let's Encrypt，2026-08-26 签发、11-24 到期，90 天例行续期）。网关类服务对长连接有要求，nginx 侧三个不能少：

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;   # 流式响应
    proxy_set_header Connection "upgrade";
    proxy_buffering off;                      # 不缓冲，SSE 才能逐字吐
    proxy_read_timeout 600s;                  # 长生成不超时
}
```

客户端接入地址两层：管理后台登录页是站点域名本身，模型调用是 `https://sub2api.ipuff.online/v1`（OpenAI 兼容入口，配平台签发的 `sk-` Key）。

## 六、升级与迁移

```bash
# 升级：拉新镜像重建，数据在本地目录里原样保留
docker compose pull && docker compose up -d

# 整体迁移：停 → 打包 → 对端解包 → 起
docker compose down
cd .. && tar czf sub2api-complete.tar.gz sub2api-deploy/
# 对端解包后
cd sub2api-deploy && docker compose up -d
```

迁移时 `.env` 一并带着走，`JWT_SECRET` 不变、登录态不掉。后台左上角还有 "Check for Updates" 在线更新按钮（走 `UPDATE_PROXY_URL` 访问 GitHub，国内机器配代理），带回滚；compose 用户直接 pull 即可，两条路别混用。

## 七、已知坑

| 现象 | 原因与解法 |
| --- | --- |
| `docker pull` 卡死/超时 | 国内直连 Docker Hub 不通：配 daemon.json 镜像加速或改 DNS，参照第二节 |
| 重启后全员掉线 | `JWT_SECRET` 留空被随机生成——首启就写死 |
| 开了 2FA 的人突然登不进 | `TOTP_ENCRYPTION_KEY` 留空被随机生成，已有 TOTP 全部失效 |
| 首登提示账号不存在 | 手工预建了 `data/config.yaml` 跳过向导——删掉让它重建 |
| 后台在线更新/定价拉取失败 | GitHub 访问不通：`UPDATE_PROXY_URL` 配 `http://127.0.0.1:7890` 或 `socks5://...` |
| compose 起来但应用反复重启 | 看 `docker compose logs sub2api`：迁移失败（凭据错、checksum 不匹配）会快速退出，PG 未就绪类错误应用会自动退避重试 |

## 八、管理面

后台网页之外，管理 API 用 Admin Key（`x-api-key`）或管理员 JWT（`POST /api/v1/auth/login` 拿 `access_token`）都通，账号/分组/兑换码/错误规则全可脚本化——批量上下线账号、按 ID 改并发这类操作适合写成脚本跑，避免网页上逐个点。笔者把这套管理 API 封装成了 [sub2api-admin](../../skills/sub2api-admin/SKILL.md) skill（只读先行、写前确认目标、导出走文件不刷屏），可按 [巡检 skill 的启用方式](../../skills/巡检/README.md) symlink 到 `~/.zcode/skills/` 供 AI 调用。
