# 1. 安装部署-docker

> **实测状态**:✅ 已实测 —— Valkey 8.1.10(`valkey/valkey:8.1`),valkey-1(10.10.12.121),2026-09-30。与 Redis 容器部署的差异点全部标注。

## 部署

配置文件与 Redis 完全同语法(本仓库 [conf/common.conf](conf/common.conf) 即 Redis 基线改密码而来),启动命令把 `redis-server` 换成 `valkey-server`:

```bash
mkdir -p /data/valkey/{conf,data} && chown -R 999:999 /data/valkey/data
cp common.conf /data/valkey/conf/valkey.conf
docker run -d --name valkey \
  --restart=always --stop-timeout=180 --net=host \
  --health-cmd="valkey-cli ping | grep -q PONG" \
  --health-interval=10s --health-timeout=5s --health-retries=6 \
  -e REDISCLI_AUTH=Valkey@2026 \
  -v /data/valkey/data:/data -v /data/valkey/conf:/conf \
  valkey/valkey:8.1 valkey-server /conf/valkey.conf
```

验证:

```bash
docker exec -e REDISCLI_AUTH=Valkey@2026 valkey valkey-cli INFO server | grep -E "^redis_version|^server_name|^valkey_version"
# redis_version:7.2.4          ← 对外协议兼容层报告的"Redis 等价版本"
# server_name:valkey
# valkey_version:8.1.10
# valkey_release_stage:ga
```

`redis_version:7.2.4` 是**兼容性语义的关键数字**:Valkey 8.1 自述等价 Redis 7.2 协议层,这解释了第 2 篇实测矩阵里所有"通/不通"的分界。

## 与 Redis 容器的差异清单(实测)

| 项 | Redis | Valkey |
| --- | --- | --- |
| 二进制 | redis-server / redis-cli | valkey-server / valkey-cli |
| 环境变量 | REDISCLI_AUTH | **仍读 REDISCLI_AUTH**(实测 VALKEYCLI_AUTH 无效) |
| 配置文件语法 | redis.conf | 完全相同(requirepass/replicaof/ACL...) |
| 数据目录/属主 | /data,uid 999 | 相同(uid 999,chown 纪律同) |
| INFO 字段 | redis_version | 多了 server_name / valkey_version |
| 镜像仓库 | library/redis | valkey/valkey |

## 已知坑(实测)

1. **VALKEYCLI_AUTH 环境变量不生效**——valkey-cli 仍认 `REDISCLI_AUTH`(兼容名),写错会得到 NOAUTH 的假象;
2. health-cmd 用 `valkey-cli`(镜像里没有 redis-cli);
3. 其余坑(目录属主 999、docker exec 继承环境变量等)与 Redis 完全一致,见 [../redis/1.安装部署-单机docker.md](../redis/1.安装部署-单机docker.md)。
