# 2. 与 Redis 兼容性实测

> **实测状态**:✅ 已实测 —— Valkey 8.1.10 ↔ Redis 8.0.6,2026-09-30。每格都有实测证据。

## 客户端协议矩阵(全通)

| 客户端 | 服务端 | 实测 |
| --- | --- | --- |
| valkey-cli | valkey | ✅ 全命令正常 |
| valkey-cli | redis 8.0 | ✅ `GET hello:redis → v1` |
| redis-cli(官方 redis 镜像) | valkey | ✅ SET/GET `from:redis-cli → ok` |
| redis-cli + valkey 上建的 ACL 账号 | valkey | ✅ `--user app --pass ... SET app:k1 → cross-ok` |

**ACL 完全同构**:valkey 上 `ACL SETUSER`(on/密码/~key 模式/+命令)创建的账号,redis 官方客户端用 `--user/--pass` 正常鉴权操作。

**RESP3**:`valkey-cli -3 PING → PONG` ✅。

结论:**应用层(RESP 协议、ACL、命令)双向兼容**,业务代码与主流客户端库(Jedis/Lettuce/go-redis 等)无需修改即可切换——客户端根本感知不到对面是 valkey 还是 redis。

## RDB 快照互导矩阵(单向死)

| 方向 | 实测结果 |
| --- | --- |
| valkey dump.rdb → redis 8.0 加载 | ✅ `Done loading RDB, keys loaded: 3`;GET 取回数据 |
| redis 8.0 dump.rdb → valkey 加载 | ❌ **`Can't handle RDB format version 12` → Fatal error exiting** |

根因:Redis 8.0 起 RDB 格式升到 **version 12**,Valkey 8.1 只认到 v11(等价 Redis 7.x)。注意这个边界随双方版本演进会移动——跨版本搬运前先看本文矩阵的实测日期,必要时在实验机重测这一格。

## INFO 与命令语义

- `INFO` 各段(section)结构与字段名一致,巡检 redis.md 的 R01~R13 命令面对 valkey 直接可用(实测 INFO server/memory/replication 字段一致);
- 巡检侧识别服务端类型用 `server_name` 字段:`redis` / `valkey`(redis 无此字段,出现即 valkey)。
