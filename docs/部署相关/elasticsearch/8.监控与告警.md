# 8. 监控与告警

> **实测状态**:✅ 已实测 —— ES 8.19.14:监控走**自带 REST API 面板**(无需额外 exporter),`_cluster/health` / `_cat/*` 输出均已实测;Prometheus exporter 已实测(v1.7.0,指标名见"告警规则"节,2026-10-09)。

## 分工:巡检(命令面)与监控(API 面板)同一套 ES 编号

ES 的监控形态与前几章不同:**它自己就是指标源**(REST API),命令面巡检与监控面板读同一批端点,不存在第二套真源:

| 巡检项 | API | 关键字段(实测输出) |
| --- | --- | --- |
| ES01/ES02 集群状态与节点数 | `_cluster/health` | `"status":"green"`、`number_of_nodes:3` |
| ES03 未分配分片 | health + `_cat/shards?state=UNASSIGNED` | `unassigned_shards` |
| ES04/ES05 堆与磁盘 | `_cat/nodes?v` | `heap.percent`、`disk.used_percent` |
| ES10 单节点分片数 | `_cat/nodes?h=name,shard.count`… `_cat/shards` 聚合 | 分片计数 |
| ES11 快照状态 | `_snapshot/<repo>/_all` | 最近 SUCCESS 时间 |

实测样例:

```
curl -s localhost:9200/_cluster/health | grep -oE '"status":"[a-z]+"|"number_of_nodes":[0-9]+'
"status":"green"  "number_of_nodes":3

curl -s "localhost:9200/_cat/nodes?h=name,heap.percent,disk.used_percent,master"
es-3  7  31 *
es-1  5  31 -
```

## 告警规则(语义,与巡检阈值对齐)

无 exporter 时,用定时任务轮询 API 产告警(或接入我们既有监控的自定义探针);Prometheus 化已实测(`prometheuscommunity/elasticsearch_exporter` **v1.7.0 二进制直跑**,2026-10-09):

```yaml
- alert: ESStatusNotGreen        # ES01
  # 实测指标:elasticsearch_cluster_health_status{cluster,color},one-hot 编码
  # (healthy 时 color="green"=1,color="red"/"yellow"=0)——不是老假设的 0=green/1=yellow/2=red 单值映射!
  expr: elasticsearch_cluster_health_status{color!="green"} == 1
  for: 5m
- alert: ESNodesLost             # ES02 / P0
  # 实测指标:elasticsearch_cluster_health_number_of_nodes{cluster} = 3
  expr: elasticsearch_cluster_health_number_of_nodes < 3
  for: 1m
- alert: ESHeapHigh              # ES04 / P1,P0
  # 实测指标(v1.7.0 改名):elasticsearch_jvm_memory_used_bytes / _max_bytes,按 area="heap" 过滤、按 name 分节点
  # 没有"现成的百分比"指标,用 used/max 自算
  expr: sum by (name) (elasticsearch_jvm_memory_used_bytes{area="heap"})
      / sum by (name) (elasticsearch_jvm_memory_max_bytes{area="heap"}) > 0.75
  for: 10m
```

### exporter 实测记录(2026-10-09,v1.7.0)

- **部署姿势**:镜像源全 403,GitHub release 二进制直跑最省事(`--es.uri=http://localhost:9200 --web.listen-address=:9114`;`--es.all --es.indices` 才有分节点/索引级指标);
- **实测在的指标**:`elasticsearch_cluster_health_status{color}`(one-hot)、`..._number_of_nodes`、`..._unassigned_shards`、`..._active_(primary_)shards`、`elasticsearch_jvm_memory_used/max_bytes{area="heap",name}`、`elasticsearch_jvm_gc_collection_seconds_{count,sum}`、`elasticsearch_indices_docs{name}`、`elasticsearch_thread_pool_queue_count`;
- **实测没有的**:**磁盘占用指标不存在**(只有 `elasticsearch_filesystem_io_stats_device_*` 的 IO 计数)——ES 节点磁盘水位告警必须靠 **node_exporter**,不能指望这个 exporter;
- 老资料里的 `es_node_stats_jvm_mem_heap_used_percent` 等**在 v1.7.0 已不存在**,抄指标名前先 `/metrics` 抓一遍对名。

## 面板建议

Grafana 用 ES 数据源直连或 exporter;核心四张图:status 时间线、节点数、各节点 heap%、各节点磁盘%——正好覆盖巡检 P0/P1 的全部触发面。
