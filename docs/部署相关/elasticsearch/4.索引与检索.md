# 4. 索引与检索

> **实测状态**:✅ 已实测 —— ES 8.19.14 三节点,建索引/批量写入/范围检索/分片分布,2026-10-01(输出实录);**ILM 生命周期一轮(缩短周期),2026-10-09**。

## 建索引(三要素:分片/副本/mapping)

```bash
curl -s -X PUT "localhost:9200/device-events" -H 'Content-Type: application/json' \
  -d '{"settings":{"number_of_shards":3,"number_of_replicas":1}}'
# {"acknowledged":true}
```

- 分片数**建后不可改**(副本数可动态调);按数据量规划,单分片 10~50GB 经验区间,小集群别过度分片(每个分片都是 Lucene 实例,巡检 ES10 的 1000 上限);
- 副本 1 是可用性基线(节点挂了数据仍在,第 6 篇实测)。

## 写入与检索(实测)

```bash
# 单条写入(refresh=wait_for 保证立即可查,压测/批量别用):
curl -s -X POST "localhost:9200/device-events/_doc?refresh=wait_for" -H 'Content-Type: application/json' \
  -d '{"device":"dev-1","temp":21,"ts":"2026-10-01T01:00:00Z"}'

# 计数:
curl -s localhost:9200/device-events/_count          # "count":9

# 范围检索(temp>25,URI query 形式):
curl -s "localhost:9200/device-events/_search?q=temp:%3E25&filter_path=hits.total,hits.hits._source.device"
# {"hits":{"total":{"value":4,...},[dev-6,dev-7,dev-8,dev-9]}}
```

**实测细节**:写入 10 条只有 9 条可查——第 10 条的 `ts` 字段串是非法日期(`T010:00:00Z`),**ES 拒收非法字段值且默认不中断批量**。生产前定 mapping(显式字段类型)能把这个变成显式报错,而不是静默少数据。

## 分片分布(实测,教科书式均衡)

```
curl -s "localhost:9200/_cat/shards/device-events?v&h=shard,prirep,state,node"
shard prirep state   node
0     p      STARTED es-2
0     r      STARTED es-1
1     p      STARTED es-1
1     r      STARTED es-3
2     r      STARTED es-2
2     p      STARTED es-3
```

主分片 0/1/2 各落不同节点,副本绝不与主同宿——这是 green 的结构保证。

## 索引即资产的纪律

- `action.auto_create_index: false`(模板注释里有,按需放开):杜绝手滑写错索引名自动建索引;
- 生命周期:时序数据用 ILM(hot/warm/delete 按天数滚动)——**已于 2026-10-09 实测走通一轮(缩短周期)**,实录见下。

### ILM 一轮实测(2026-10-09,缩短周期:rollover 2m / warm 3m / delete 5m)

```bash
# ① 策略(hot rollover → warm forcemerge → delete):
PUT _ilm/policy/device-lab-policy
{ "policy": { "phases": {
    "hot":   { "min_age": "0ms", "actions": { "rollover": { "max_age": "2m" } } },
    "warm":  { "min_age": "3m",  "actions": { "forcemerge": { "max_num_segments": 1 } } },
    "delete":{ "min_age": "5m",  "actions": { "delete": {} } } } } }

# ② 模板绑定策略 + rollover 别名;③ 首索引 000001 + is_write_index 别名;④ 写入
```

**实测时序(UTC)**:000001 创建 11:31:13 → **rollover 11:33:36**(+2m23s,000002 出现,写入自动切过去)→ warm 进入 11:36:45 → forcemerge 完成 ~11:56 → **delete 11:56:24**(000001 消失,`_cat/indices` 验收)。`_ilm/explain` 全程可观测,步骤链:`check-rollover-ready → check-ts-end-time-passed → forcemerge → segment-count → delete`。

**三个实测要点**:

1. **`indices.lifecycle.poll_interval` 默认 10 分钟**,ILM 每 10 分钟才动一次——缩短周期演练**必须先** `PUT _cluster/settings -d '{"persistent":{"indices.lifecycle.poll_interval":"30s"}}'`,否则每个阶段都被轮询粒度支配(本次实测前半程就是这么被拖慢的,调 30s 后 90 秒内走完剩余阶段);
2. **min_age 从 lifecycle date 起算 = rollover 完成时刻**,不是索引创建时刻(实测差 2 分 23 秒);
3. forcemerge 动作自带 `check-ts-end-time-passed` 前置(等索引确认不再写入才合并),别把它当成卡死。

生产上按天滚动只需把 `max_age`/`min_age` 换成 `1d` 量级,结构不变。
