# 2. 安装部署-三节点

> **实测状态**:✅ 已实测 —— Elasticsearch 8.19.14,es-1/2/3(`--net=host`),2026-10-01。含两个真实踩过的部署坑(config 目录、宿主前置)。

## 拓扑

```
es-1 10.10.12.134  master-eligible
es-2 10.10.12.135  master-eligible
es-3 10.10.12.136  master-eligible
端口:9200 HTTP;9300 transport(节点间)
```

三节点全角色(小集群惯例);大规模再拆 dedicated master/data。

## 宿主前置(实测)

```bash
# ① vm.max_map_count(ES 启动硬检查):
sysctl -w vm.max_map_count=262144
echo "vm.max_map_count=262144" >> /etc/sysctl.conf
# ② 数据目录属主(容器 uid 1000):
mkdir -p /data/elasticsearch/{data,logs} && chown -R 1000:1000 /data/elasticsearch
```

## 第一步:config 必须全量提取(实测大坑)

**只挂 elasticsearch.yml + jvm.options 两个文件会 crash 循环**——config 目录被整体替换,丢了 `log4j2.properties` 等镜像自带文件:

```
ERROR: Missing logging config file at /usr/share/elasticsearch/config/log4j2.properties, exit code 78
```

正确做法(docker cp 全量提取,再覆盖生成的 yml):

```bash
docker create --name esconf elasticsearch:8.19.14
docker cp esconf:/usr/share/elasticsearch/config /data/es-conf && docker rm esconf
# 校验提取成功(实测 135 栽过静默失败):
test -f /data/es-conf/log4j2.properties || echo "提取失败!"
cp /root/elasticsearch.yml /data/es-conf/elasticsearch.yml   # gen 生成的节点版
cp /root/jvm.options    /data/es-conf/jvm.options
chown -R 1000:1000 /data/es-conf
```

## 第二步:启动

```bash
docker run -d --name elasticsearch --restart=always --net=host \
  --ulimit nofile=65535:65535 --ulimit memlock=-1:-1 \
  -e ES_JAVA_OPTS="-Xms2g -Xmx2g" \
  -v /data/es-conf:/usr/share/elasticsearch/config \
  -v /data/elasticsearch/data:/usr/share/elasticsearch/data \
  -v /data/elasticsearch/logs:/usr/share/elasticsearch/logs \
  elasticsearch:8.19.14
```

首启要 2~3 分钟(JVM + 索引模板注册);**新节点加入在线集群也走同样等待**,不是挂了。

## 第三步:验证(实测输出)

```bash
curl -s localhost:9200/_cluster/health?pretty | grep -E '"status"|"number_of_nodes"'
# "status" : "green" / "number_of_nodes" : 3
curl -s "localhost:9200/_cat/nodes?v&h=name,ip,heap.percent,node.role,master"
# es-3 10.10.12.136  7 cdfhilmrstw *
# es-1 10.10.12.134  5 cdfhilmrstw -
```

## 安全形态(重要决策,显式写清)

- **本基线:内网明文**(`xpack.security.enabled: false`)。8.x 默认是**开**(TLS+认证),关掉的条件:网络隔离可信 + 接入侧有别的控制;巡检文档在 deb 环境实测过"默认开"的探测姿势(`https:// -k -u`);
- 开启路径(未在本环境实测,列为待办):`elasticsearch-certutil` 生成 CA/节点证书 → transport 层 TLS 必配 → http 层 TLS 可选 → 内建用户密码(`elasticsearch-setup-passwords`)→ 巡检 ES12(证书有效期)随之生效;
- 两种形态的切换 = 重启级变更,走变更窗口,别在滚动操作中途改主意。

## 已知坑(实测)

| 坑 | 现象 | 解 |
| --- | --- | --- |
| 只挂两个配置文件 | crash 循环 "Missing log4j2.properties" | 全量提取 config(本文第一步) |
| 数据目录 root 属主 | 启动失败 access denied | chown 1000:1000 |
| vm.max_map_count 低 | 启动即退 | 前置 sysctl |
| 首启/新节点 3 分钟无响应 | 误判挂了反复重启 | 等 9200,别急 |
