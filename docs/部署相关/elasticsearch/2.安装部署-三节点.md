# 2. 安装部署-三节点

## 拓扑

```
es-1 10.10.12.134  master-eligible
es-2 10.10.12.135  master-eligible
es-3 10.10.12.136  master-eligible
端口:9200 HTTP;9300 transport(节点间)
```

三节点全角色(小集群惯例);大规模再拆 dedicated master/data。

## 宿主前置(实测)

```bash
# ① vm.max_map_count(ES 启动硬检查):
sysctl -w vm.max_map_count=262144
echo "vm.max_map_count=262144" >> /etc/sysctl.conf
# ② 数据目录属主(容器 uid 1000):
mkdir -p /data/elasticsearch/{data,logs} && chown -R 1000:1000 /data/elasticsearch
```

## 第一步:config 必须全量提取(实测大坑)

**只挂 elasticsearch.yml + jvm.options 两个文件会 crash 循环**——config 目录被整体替换,丢了 `log4j2.properties` 等镜像自带文件:

```
ERROR: Missing logging config file at /usr/share/elasticsearch/config/log4j2.properties, exit code 78
```

正确做法(docker cp 全量提取,再覆盖生成的 yml):

```bash
docker create --name esconf elasticsearch:8.19.14
docker cp esconf:/usr/share/elasticsearch/config /data/es-conf && docker rm esconf
# 校验提取成功(实测 135 栽过静默失败):
test -f /data/es-conf/log4j2.properties || echo "提取失败!"
cp /root/elasticsearch.yml /data/es-conf/elasticsearch.yml   # gen 生成的节点版
cp /root/jvm.options    /data/es-conf/jvm.options
chown -R 1000:1000 /data/es-conf
```

## 第二步:启动

```bash
docker run -d --name elasticsearch --restart=always --net=host \
  --ulimit nofile=65535:65535 --ulimit memlock=-1:-1 \
  -e ES_JAVA_OPTS="-Xms2g -Xmx2g" \
  -v /data/es-conf:/usr/share/elasticsearch/config \
  -v /data/elasticsearch/data:/usr/share/elasticsearch/data \
  -v /data/elasticsearch/logs:/usr/share/elasticsearch/logs \
  elasticsearch:8.19.14
```

首启要 2~3 分钟(JVM + 索引模板注册);**新节点加入在线集群也走同样等待**,不是挂了。

## 第三步:验证(实测输出)

```bash
curl -s localhost:9200/_cluster/health?pretty | grep -E '"status"|"number_of_nodes"'
# "status" : "green" / "number_of_nodes" : 3
curl -s "localhost:9200/_cat/nodes?v&h=name,ip,heap.percent,node.role,master"
# es-3 10.10.12.136  7 cdfhilmrstw *
# es-1 10.10.12.134  5 cdfhilmrstw -
```

## 安全形态(重要决策,显式写清)

- **本基线:内网明文**(`xpack.security.enabled: false`)。8.x 默认是**开**(TLS+认证),关掉的条件:网络隔离可信 + 接入侧有别的控制;巡检文档在 deb 环境实测过"默认开"的探测姿势(`https:// -k -u`);
- **TLS 形态已于 2026-10-09 在本环境实测**(流程见下),测后回退明文基线;两种形态的切换 = **全集群停机级变更**(不能滚动:明文节点与 TLS 节点 transport 互不相认),走变更窗口。

### TLS 实测记录(2026-10-09,三节点)

```bash
# ① 生成证书(容器内执行;certutil 在 /usr/share/elasticsearch/bin):
ES=/usr/share/elasticsearch
$ES/bin/elasticsearch-certutil ca --silent --out /tmp/certs/elastic-ca.p12 --pass labca
$ES/bin/elasticsearch-certutil cert --silent --ca /tmp/certs/elastic-ca.p12 --ca-pass labca \
  --out /tmp/certs/elastic-nodes.p12 --pass labpass --name es-node \
  --dns es-1 --dns es-2 --dns es-3 --ip 10.10.12.134 --ip 10.10.12.135 --ip 10.10.12.136
# 证书 bundle 三节点共用一份;有效期默认 3 年(实测 2026-10-09 → 2029-10-08,巡检 ES12 就盯它)
# docker cp 到宿主 /data/es-conf/certs/ 并 chown 1000:1000

# ② yml 追加(三节点一致):
xpack.security.enabled: true
xpack.security.transport.ssl.enabled: true
xpack.security.transport.ssl.verification_mode: certificate
xpack.security.transport.ssl.keystore.path: certs/elastic-nodes.p12
xpack.security.transport.ssl.truststore.path: certs/elastic-nodes.p12
xpack.security.http.ssl.enabled: true
xpack.security.http.ssl.keystore.path: certs/elastic-nodes.p12

# ③ p12 密码进 keystore(三节点各执行;密码必须进 keystore,否则起不来):
K=$ES/bin/elasticsearch-keystore
for s in xpack.security.transport.ssl.keystore.secure_password \
         xpack.security.transport.ssl.truststore.secure_password \
         xpack.security.http.ssl.keystore.secure_password; do
  echo labpass | $K add -f -x "$s"
done

# ④ 全集群停机 → 全部改完 → 拉起(实测 3 节点 0 ERROR)
# ⑤ 内建账号密码(reset-password 自动生成并打印,替代已废弃的 setup-passwords):
bin/elasticsearch-reset-password -u elastic --batch
# 实测输出:Password for the [elastic] user successfully reset. / New value: R24h…

# ⑥ 验证:
curl -sk https://localhost:9200/_cluster/health          # 匿名 → 401 security_exception
curl -sk -u elastic:*** https://localhost:9200/_cluster/health   # green,3 节点
curl -s --cacert es-ca.pem -u elastic:*** https://10.10.12.134:9200/   # CA 真校验通过
```

实测要点:

- **SAN 必须覆盖客户端实际使用的名字**:证书 SAN 是 es-1/2/3 + 三个 IP,用 `localhost` 访问即使 CA 正确也报 `no alternative certificate subject name matches`——要么 IP 访问,要么生成时加 `--dns localhost`;
- **回退** = yml 换回明文版 + `elasticsearch-keystore remove` 三个 secure_password + 全集群重启(实测回退后 http green,数据无损)。

## 已知坑(实测)

| 坑 | 现象 | 解 |
| --- | --- | --- |
| 只挂两个配置文件 | crash 循环 "Missing log4j2.properties" | 全量提取 config(本文第一步) |
| 数据目录 root 属主 | 启动失败 access denied | chown 1000:1000 |
| vm.max_map_count 低 | 启动即退 | 前置 sysctl |
| 首启/新节点 3 分钟无响应 | 误判挂了反复重启 | 等 9200,别急 |
| certutil 相对路径(TLS 实测) | docker exec 默认 workdir 不在 ES_HOME,"No such file or directory" | 全路径 `/usr/share/elasticsearch/bin/` |
| p12 密码没进 keystore(TLS 实测) | 节点起不来 | `elasticsearch-keystore add` 三个 secure_password(见 TLS 实测记录) |
| 明文↔TLS 想滚动切换 | 节点间 transport 互不相认,集群散 | 全集群停机窗口内统一切换 |
