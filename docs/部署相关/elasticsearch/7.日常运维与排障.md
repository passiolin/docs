# 7. 日常运维与排障

## 日常操作速查

```bash
curl -s localhost:9200/_cluster/health?pretty             # 总健康(ES01/ES02)
curl -s "localhost:9200/_cat/nodes?v"                     # 节点/堆/磁盘(ES04/ES05/ES09)
curl -s "localhost:9200/_cat/indices?v&health=yellow,red" # 异常索引(ES03)
curl -s "localhost:9200/_cat/shards?v&state=UNASSIGNED"   # 未分配分片(ES03)
docker logs -f elasticsearch                              # 节点日志(JSON 行)
```

## 排障字典(实测错误集 + 巡检处置路径)

| 现象 | 根因 | 处置 |
| --- | --- | --- |
| crash 循环 `Missing log4j2.properties` | config 目录只挂了部分文件 | 全量 docker cp 提取(第 2 篇) |
| 启动失败 access denied | 数据目录属主非 1000 | chown(第 2 篇) |
| 首启/加入 3 分钟无响应 | JVM 正常启动时长 | 等 9200,别重启 |
| status yellow | 副本未凑齐(节点挂/维护中) | 先看 number_of_nodes 对不对(第 6 篇) |
| status red | 主分片全灭/分配保护 | `allocation/explain` 定位,勿急重启(巡检 ES01) |
| 写入静默少数据 | 非法字段值被拒(实测:非法日期) | 显式 mapping;`?filter_path=errors` 看拒绝详情 |
| 磁盘水位告警 | ≥80% 触发迁分片,≥95% flood-stage 只读锁 | 清索引/调 ILM;解锁:`PUT <idx>/_settings {"index.blocks.read_only_allow_delete":null}`(巡检 ES08) |
| 注册快照仓库报错 | path.repo 未白名单 | 第 5 篇 |
| 节点版本不齐 | 滚动升级进行中 | 尽快收尾(ES09);跨大版本查官方升级矩阵 |

## 纪律互链

- 滚动重启一次一台,green 再下一台(第 3 篇);
- 维护节点先 allocation exclude 排干(第 6 篇);
- 慢查询治理:先配 slowlog(巡检 ES07:未配置本身记 P2),再谈优化——同 MySQL 第 8 篇 slow log 的思路。
