# 1. 安装部署-单机

## 什么时候用单机

开发测试、日志小规模自用。与集群篇的**明文内网基线**不同,单机篇走 **8.x 默认安全形态**(认证 + ELASTIC_PASSWORD)——补上"安全开启长什么样"的实测拼图(巡检文档在 deb 环境遇到的就是这个形态)。

## 部署(实测命令)

```bash
# 宿主前置(同集群篇):
sysctl -w vm.max_map_count=262144 && echo "vm.max_map_count=262144" >> /etc/sysctl.conf
# config 全量提取(只挂 yml 会 crash,集群篇第 2 篇同款坑):
docker create --name confsrc elasticsearch:8.19.14
docker cp confsrc:/usr/share/elasticsearch/config /data/es-single/conf && docker rm confsrc
mkdir -p /data/es-single/{data,logs}

cat > /data/es-single/conf/elasticsearch.yml <<'EOF'
cluster.name: es-single
node.name: es-single
network.host: 127.0.0.1          # ★ 见坑 1
discovery.type: single-node
path.data: /usr/share/elasticsearch/data
path.logs: /usr/share/elasticsearch/logs
xpack.security.enabled: true
EOF
chown -R 1000:1000 /data/es-single

docker run -d --name es-single --restart=always --net=host \
  --ulimit nofile=65535:65535 \
  -e ES_JAVA_OPTS="-Xms1g -Xmx1g" \
  -e ELASTIC_PASSWORD=EsSingle@2026 \
  -v /data/es-single/conf:/usr/share/elasticsearch/config \
  -v /data/es-single/data:/usr/share/elasticsearch/data \
  -v /data/es-single/logs:/usr/share/elasticsearch/logs \
  elasticsearch:8.19.14
```

远程访问:127.0.0.1 绑定下用 SSH 隧道(`ssh -L 9200:127.0.0.1:9200`);要直接对外时先解决坑 1。

## 验证(实测输出)

```bash
curl -s http://127.0.0.1:9200 -u elastic:EsSingle@2026 | grep -E "cluster_name|tagline"
# "cluster_name" : "es-single" / "You Know, for Search"
curl -s -X PUT "http://127.0.0.1:9200/single-idx/_doc/1?refresh=wait_for" \
  -u elastic:EsSingle@2026 -H 'Content-Type: application/json' \
  -d '{"device":"dev-1","temp":25}' -o /dev/null -w "%{http_code}"    # 201
curl -s "http://127.0.0.1:9200/single-idx/_search?q=temp:25&filter_path=hits.hits._source" \
  -u elastic:EsSingle@2026
# {"hits":{"hits":[{"_source":{"device":"dev-1","temp":25}}]}}
curl -s http://127.0.0.1:9200 -u elastic:WRONG -o /dev/null -w "%{http_code}"   # 401
curl -s http://127.0.0.1:9200 -o /dev/null -w "%{http_code}"                    # 401
```

## 三个实测坑(本文核心资产)

1. **绑非回环地址 + 安全开启 → 启动被 TLS bootstrap check 卡死**:报
   `Transport SSL must be enabled if security is enabled`。单机快速路径 = 绑 127.0.0.1(该检查对回环地址放行为 WARN);对外服务就要正经配证书(集群篇第 2 篇"安全形态"节)。
2. **ELASTIC_PASSWORD 只在"干净的首次启动"生效**:数据目录已存在时环境变量被忽略。
3. **陈旧 keystore 藏在挂载的 config 目录里**(最隐蔽,实测踩):首启失败会把随机 bootstrap 密码写进 `config/elasticsearch.keystore`;之后清 data 重来,密码仍然 401——**必须把 keystore 一起删**:`rm /data/es-single/conf/elasticsearch.keystore` 再重启。判别方法:正确密码也 401 = 密码源另有其处。
