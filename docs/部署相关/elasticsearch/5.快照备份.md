# 5. 快照备份

> **实测状态**:✅ 已实测 —— ES 8.19.14,fs 仓库注册 + 全量快照 SUCCESS(2026-10-01)。**恢复演练已实测**(2026-10-09):rename 换名恢复 + 条数对账 + 抽样核对全部通过,实测记录见下。
> ⚠️ **断电事故附带发现(2026-10-01~09)**:三节点 fs 仓库各挂**本地目录**(非共享存储),断电后仓库被 ES 禁用——这是本篇最大的坑,见"已知坑"表与文末补记。

## 前置:path.repo 白名单(实测必踩)

yml 不设 `path.repo` 时注册 fs 仓库直接报错——快照目录必须显式白名单:

```yaml
path.repo: ["/usr/share/elasticsearch/snapshots"]   # 容器内路径,挂宿主
```

基线模板已内置(第 3 篇);漏配的表现是 `repository_exception ... path not in repo whitelist`。

## 注册仓库 + 快照(实测)

```bash
# 宿主目录挂载到 /usr/share/elasticsearch/snapshots(见第 2 篇 docker run)
curl -s -X PUT "localhost:9200/_snapshot/lab-repo" -H 'Content-Type: application/json' \
  -d '{"type":"fs","settings":{"location":"/usr/share/elasticsearch/snapshots/lab-repo"}}'

# 全量快照(等完成):
curl -s -X PUT "localhost:9200/_snapshot/lab-repo/snap-1?wait_for_completion=true" \
  | grep -oE '"state":"[A-Z]+"'
# 实测输出:"state":"SUCCESS"
```

- 快照是**集群级一致性**的(进行中写入按 segment 快照点处理);
- 生产改 S3/OSS 仓库(type:s3 + 我们的对象存储体系),命令结构相同;
- 定时:`PUT _slm/policy/...` 快照生命周期策略(每日 + 保留 N 份,与 ILM 联动),巡检 ES11 的"近 7 天无 SUCCESS 快照 P1"靠它兜底。

## 恢复(已实测,2026-10-09)

```bash
# 查看快照内容:
curl -s "localhost:9200/_snapshot/lab-repo/snap-1?pretty"
# 恢复(换索引名,避免覆盖在线索引):
curl -s -X POST "localhost:9200/_snapshot/lab-repo/snap-1/_restore?wait_for_completion=true" \
  -H 'Content-Type: application/json' \
  -d '{"indices":"device-events","rename_pattern":"(.+)","rename_replacement":"restored-$1"}'
# 实测输出:{"snapshot":{"snapshot":"snap-1","indices":["restored-device-events"],
#            "shards":{"total":3,"failed":0,"successful":3}}}
```

**对账实录(2026-10-09)**:

| 步骤 | 结果 |
| --- | --- |
| `_count` 对账 | live `device-events` = 9,restored = 9 ✅ |
| 抽样核对 | dev-1 两边一致:`{temp:21, ts:2026-10-01T01:00:00Z}` ✅ |
| 分片落点 | 恢复分片重排后 3 主 3 副全 STARTED,集群 green ✅ |
| 清理 | `DELETE restored-device-events` 恢复原状 ✅ |

**验收纪律**:备份策略的验收 = 恢复演练通过(数据条数对账 + 抽样值核对),不是"快照 SUCCESS"。改仓库/策略后必演练。

## fs 仓库在多节点上必须真共享存储(断电实测教训)

2026-10-01 断电重启后实测踩坑全记录:三节点的 `/data/elasticsearch/snapshots` 各自是**本地目录**,却注册成了同一个 fs 仓库。后果链:

1. **写入即分散**:快照元数据(`index-0`/`index.latest`/`snap-*.dat`)只落**当时的主节点 es-3**;分片数据文件按主分片落点分散——es-1 只有 shard 1、es-2 只有 shard 0、es-3 只有 shard 2。当时快照照样返回 SUCCESS;
2. **断电后禁用**:重启后主节点(es-1)读自己本地的仓库目录,缺 `index-0` → `repository_exception ... contents were found not to match its expected state`,**整个仓库被 ES 自动禁用**,快照列表都拉不出来;
3. **注册校验过不了**:重新注册时,校验是"master 写一个测试文件、其他节点立刻读"(`repository_verification_exception ... not shared between this node and the master node`)——本地目录必挂;
4. **实验场修复路径(实测可用)**:把 es-3 的完整内容并上其余分片文件,三节点分发成**逐字节一致**的副本,再以 `readonly: true` 重注册——只读仓库不写 generation 文件,一致视图成立,恢复演练照常走通(本篇演练即用此法);
5. **边界**:只读一致副本只能支撑**恢复**;要继续**写快照**,必须上真共享存储(NFS/共享盘)或改 S3 仓库(type:s3)。

**生产铁律:fs 仓库 = 共享存储,或者干脆用 S3/OSS。**"快照 SUCCESS"不等于"可恢复",恢复演练才是验收。

## 已知坑

| 坑 | 现象 | 解 |
| --- | --- | --- |
| path.repo 未配 | repository_exception 白名单报错 | yml 配置 + 滚动重启(第 3 篇) |
| 快照目录属主 | 注册成功但写入失败 | chown 1000:1000 |
| 恢复到原索引名 | 与在线索引冲突 | rename_replacement 换名恢复 |
| **fs 仓库非共享(多节点)** | 快照 SUCCESS 假象;断电后仓库被禁用;重注册校验失败 | 真共享存储 / S3;实验场用一致副本 + readonly 注册(见上节) |
