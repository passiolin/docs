# 安装部署-单节点

k3s 的最短路径:一条命令、20 秒、单二进制 76M。本篇实测于 k3s-server-01(10.10.12.144,PVE 虚机,Ubuntu 26.04,2C/4G/40G),2026-10-11。单节点验证完默认形态后按第 2 篇重建为 HA——卸载/重装本身就是 k3s 的验证项(实测 5 秒全清)。

## 一、系统前置(与 RKE2 完全一致)

swap 关闭、overlay/br_netfilter 模块、ip_forward 与 bridge-nf sysctl、chrony 时间同步——完整命令见 [kubernetes/1.安装部署-单节点.md](../kubernetes/1.安装部署-单节点.md) 第一节,两发行版通用。

国内镜像安装(k3s 同样走 rancher-mirror):

```bash
curl -sfL https://rancher-mirror.rancher.cn/k3s/k3s-install.sh | INSTALL_K3S_MIRROR=cn sh -
systemctl enable --now k3s
```

实测:**安装 20 秒**,首次轮询节点即 Ready——对比 RKE2 同流程的数分钟(安装+镜像拉取),单二进制免去镜像分发的优势在小节点上非常直观。

## 二、默认形态盘点(实测,均为 k3s 内置)

| 组件 | 形态 | 对照 RKE2 v1.35 |
| --- | --- | --- |
| coredns | Deployment | 一致 |
| **local-path-provisioner** | Deployment + **默认 StorageClass** | **RKE2 v1.35 已移除,需自装** |
| **traefik** | helm-install + hostPort 80/443 | RKE2 用 ingress-nginx |
| **ServiceLB(klipper-lb)** | 随 LoadBalancer Service 按需出 svclb Pod | **RKE2 v1.35 已移除,需自装 MetalLB** |
| metrics-server | Deployment | 一致 |

结论:微服务场景的"开箱即用三件套"(存储/入口/负载均衡)k3s 全内置——这正是"k3s 满足微服务大部分需求"论断的组件级证据。资源实测:单节点全栈内存占用 1.1Gi,单二进制 76M,数据目录 1.1G。

## 三、kubectl 与日常

```bash
export KUBECONFIG=/etc/rancher/k3s/k3s.yaml   # 建议写入 /etc/profile.d/k3s.sh
kubectl get nodes   # kubectl 为 /usr/local/bin/kubectl(k3s 内置符号链接)
```

注意:k3s 的 kubectl 在 `/usr/local/bin`,与 RKE2 的 `/var/lib/rancher/rke2/bin` 不同;`crictl` 同理。

## 四、镜像加速

`/etc/rancher/k3s/registries.yaml` 与 RKE2 同格式同字段(见 [kubernetes/conf/registries.yaml](../kubernetes/conf/registries.yaml)),改后 `systemctl restart k3s` 生效。

## 五、卸载(实测)

```bash
/usr/local/bin/k3s-uninstall.sh    # server;agent 用 k3s-agent-uninstall.sh
```

实测 5 秒全清:数据目录、二进制、systemd 单元、iptables 规则一次干净——重装验证的迭代成本极低。
