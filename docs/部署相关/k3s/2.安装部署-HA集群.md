# 安装部署-HA 集群

k3s HA 的推荐形态:**3 台 server + 内嵌 etcd**(`--cluster-init` 首台,后续 `--server` 加入)+ kube-vip 承载 API VIP。本篇实测于 k3s-server-01/02/03(10.10.12.144-146),VIP 10.10.12.150,2026-10-11。

## 一、首台 server(cluster-init)

```bash
mkdir -p /etc/rancher/k3s
cat > /etc/rancher/k3s/config.yaml <<EOF
token: <TOKEN>
cluster-init: true
flannel-backend: none
disable-network-policy: true
EOF
curl -sfL https://rancher-mirror.rancher.cn/k3s/k3s-install.sh | \
  INSTALL_K3S_MIRROR=cn INSTALL_K3S_EXEC="--cluster-init --flannel-backend=none --disable-network-policy" sh -
systemctl enable --now k3s
```

实测:安装 22 秒(含 etcd 初始化)。`flannel-backend: none` + `disable-network-policy` 是给 Calico 让位——**必须在首台安装前定死**,与 RKE2 的 canal/calico 互删教训同理:全集群只能有一个 CNI 的意志。

Calico 安装在首台 Ready 前后皆可(节点在 CNI 缺位时短暂 NotReady 属预期),见 [第 3 篇](3.Calico安装与网络验证.md)。

## 二、后续 server 加入

`/etc/rancher/k3s/config.yaml`:

```yaml
token: <TOKEN>
server: https://10.10.12.144:6443     # 首台或 VIP;kube-vip 就绪后建议 VIP
flannel-backend: none
disable-network-policy: true
```

同一条安装命令,实测各 38/41 秒安装完成。**三个 server 的 CNI/网段配置必须严格一致**——RKE2 上的教训在此完全适用。

验证:三节点 Ready(control-plane,etcd)+ 内嵌 etcd 仲裁。注意 k3s 的 etcd **内嵌在 k3s 进程里,无独立 Pod 也无 etcdctl**——与 RKE2 的静态 Pod 形态是显性差异;健康检查用 `k3s etcd-snapshot list`(能列出即 etcd 活着)+ 三节点 Ready 判定。

## 三、kube-vip(实测,与 RKE2 手法一致)

v2.12 起的教训全部适用:静态 Pod 放 **`/var/lib/rancher/k3s/agent/pod-manifests/`**(k3s 的 kubelet staticPodPath,实测确认),挂载路径换成 k3s 的 kubeconfig,leader 选举锁名换 `plndr-k3s-lock` 区分:

```bash
# 完整清单见 kubernetes/conf/kubevip.yaml,差异仅三处:
#   vip_address: 10.10.12.150   hostPath: /etc/rancher/k3s/k3s.yaml   leasename: plndr-k3s-lock
```

实测:三台各起一个 `kube-vip-k3s-server-0N` 静态 Pod,leader 持 VIP 10.10.12.150,`https://10.10.12.150:6443` 应答 401(TLS 层可达=通路正常)。

## 四、镜像加速与重启

`/etc/rancher/k3s/registries.yaml`(与 RKE2 同格式)改动后需 `systemctl restart k3s` 生效;三台滚动重启后全部 Ready(实测,含 etcd 集群自动恢复)。

## 五、HA 后的单节点形态去哪了

第 1 篇的单节点(sqlite)与 HA(etcd)**不可原地互转**——k3s 官方路径是 etcd 快照迁移(`--cluster-reset` 恢复 etcd 快照)。本系列的实测路径:单节点验证完组件盘点后直接 `k3s-uninstall.sh`(5 秒)再按本篇重建,迭代成本趋近于零——这也是 k3s 适合反复实验的原因。
