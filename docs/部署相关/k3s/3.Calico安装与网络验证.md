# Calico 安装与网络验证

k3s 上实装 Calico(tigera-operator 形态,与 RKE2 同款组件不同交付方式),并完成 NetworkPolicy 与带宽的实测验证。2026-10-11,三节点。

## 一、安装(实测)

前置:首台 server 以 `--flannel-backend=none --disable-network-policy` 安装(见 [第 2 篇](2.安装部署-HA集群.md))——CNI 缺位期间节点短暂 NotReady 属预期。

```bash
curl -sfL --max-time 60 https://raw.githubusercontent.com/projectcalico/calico/v3.32.0/manifests/tigera-operator.yaml -o tigera-operator.yaml
kubectl apply -f tigera-operator.yaml
```

**关键实测发现:calico v3.32 的 `kubernetesProvider` 不支持 `K3S` 值**——支持列表为空/EKS/GKE/AKS/OpenShift/DockerEnterprise/RKE2/TKG/Kind(有 RKE2 没 K3S)。网上流传的 k3s 教程带 `kubernetesProvider: K3S` 的写法会直接被 CRD 校验拒绝,k3s **留空即可**。

```yaml
apiVersion: operator.tigera.io/v1
kind: Installation
metadata:
  name: default
spec:
  calicoNetwork:
    ipPools:
    - blockSize: 26
      cidr: 10.42.0.0/16          # k3s 默认 Pod 网段
      encapsulation: VXLANCrossSubnet
      natOutgoing: Enabled
      nodeSelector: all()
```

注意:Installation CR 必须等 tigera-operator.yaml 里的 CRD **established 之后再 apply**(同一次 apply 会在"no matches for kind"上失败,重放即可)。实测 CRD 建好后约 3 分钟组件全 Running(controller/node/typha/csi-node-driver,形态与 RKE2 相同)。

## 二、NetworkPolicy 实测(全过)

在 `np-test` 命名空间验证策略闭环,三步全过:

1. **default-deny**(Ingress+Egress 双向):default 命名空间 Pod → np-test Pod 被拦截;np-test Pod 出网(非白名单)被拦截
2. **放行 egress DNS**(namespaceSelector 全部 + `k8s-app: kube-dns` 的 53 端口):nslookup 恢复。注意策略应用瞬间旧连接可能仍被拦,复测间隔几秒
3. **放行指定 namespace 的 ingress**(namespaceSelector 匹配 default):跨 ns 访问恢复

calico 的策略引擎在 k3s 上与 RKE2 行为一致——NetworkPolicy 能力来自 calico 本体,与发行版无关。

## 三、封装与带宽

本集群显式选 `VXLANCrossSubnet`(与 RKE2 实测口径一致)。**跨节点 Pod 带宽数据待重测**:首轮 iperf 因两个 Pod 调度到同一节点得到无效高值(7.67G,超过宿主裸速 5.28G 即为证据),钉节点复测时又撞上 traefik 端口抖动窗口——RKE2 侧同场景实测 0.6-1.8G(平均 1.4G,见 [kubernetes/3](../kubernetes/3.网络模型与CNI选型.md)),k3s 侧预期同量级(calico 本体相同),补测时必须 `nodeName` 钉死两端且错开集群负载。

## 四、已知限制与坑(实测)

| 现象 | 根因与处置 |
| --- | --- |
| Installation apply 报 no matches for kind | CRD 未 established,重放 apply |
| `kubernetesProvider: K3S` 被拒 | v3.32 不支持该值,k3s 留空 |
| CNI 缺位期节点 NotReady | 无 CNI 时 Pod 无网络,属预期;装完自愈 |
| calico 镜像直拉 docker.io 偏慢 | registries.yaml 配 mirror 后重启 k3s |

## 五、与 RKE2 的 Calico 差异小结

| 维度 | RKE2 | k3s |
| --- | --- | --- |
| 交付方式 | 内置 chart(`cni: calico`) | 手动 tigera-operator manifest |
| 组件命名空间 | calico-system(tigera-operator) | 相同(operator 形态) |
| 镜像 | rancher/mirrored-calico-* | docker.io/calico/* 直取 |
| 默认封装 | VXLAN(installation 实测) | manifest 默认 IPIP(本篇显式改 VXLAN) |
| kubernetesProvider | RKE2(受支持) | 不支持 K3S 值,留空 |
