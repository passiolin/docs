# 9. 监控与告警

> **实测状态**:✅ 已实测 —— mysqld_exporter **v0.15.1**(`prom/mysqld-exporter`),三节点各一实例,2026-09-30。指标名与数值全部来自实测抓取(每节点 1075 个 mysql_ 指标)。Prometheus/Grafana/Alertmanager 侧的接入沿用机房既有设施,本文只给出 PromQL 与告警规则。

## 分工:巡检(命令面)与监控(指标面)用同一套编号

| 巡检项 | 命令面(巡检) | 指标面(本文 PromQL) | 阈值(同源) |
| --- | --- | --- | --- |
| M01 存活 | mysqladmin ping | `mysql_up` | 0 = P0 |
| M02 连接利用率 | SHOW GLOBAL STATUS | `mysql_global_status_threads_connected / mysql_global_variables_max_connections` | ≥0.8 P1 / ≥0.95 P0 |
| M03 活跃线程 | SHOW GLOBAL STATUS | `mysql_global_status_threads_running` | ≥核数 P1 |
| M04 慢查询 | Slow_queries 差值 | `rate(mysql_global_status_slow_queries[5m])` | 突增 P1 |
| M05 异常连接 | Aborted_* 差值 | `rate(mysql_global_status_aborted_connects[5m])` | 持续增长 P1 |
| M08 缓冲池命中 | 计算命中率 | `1 - rate(mysql_global_status_innodb_buffer_pool_reads[5m]) / rate(mysql_global_status_innodb_buffer_pool_read_requests[5m])` | <0.95 P2 / <0.90 P1 |
| M06/M07/M09 | 命令面为主 | 磁盘类归 node_exporter(inspect-server 域) | — |

阈值唯一真源是巡检文档的清单表;本文告警规则引用它,不另立标准。

## exporter 部署(v0.15.1 实测,三个坑)

**坑 1:v0.15 起不再支持 `DATA_SOURCE_NAME` 环境变量**(日志报 "no user specified"),改为挂载 my.cnf 风格配置:

```bash
cat > /data/mysql/exporter.cnf <<EOF
[client]
user=monitor
password=Monitor@2026
host=127.0.0.1
port=3306
EOF
# 坑 2:容器以非 root(uid 65534)运行,配置文件属主必须是它,600 权限即可
chown 65534:65534 /data/mysql/exporter.cnf

docker run -d --name mysqld-exporter --restart=always --net=host \
  -v /data/mysql/exporter.cnf:/cfg/.my.cnf \
  prom/mysqld-exporter:v0.15.1 --config.my-cnf=/cfg/.my.cnf
# 验证:curl -s localhost:9104/metrics | grep -c '^mysql_'  → 1075
```

顺带:密码写在 cnf 文件里**不需要 URL 编码**(第 3/5 篇 URI 场景里 `@` 才要写成 `%40`)。

**坑 3(实测巡检价值最高的一个)**:成员出错退组后,即使重新入组成功,`offline_mode` 可能仍保持 ON——此时 root 能连,但**普通账号(含 exporter)全部 ERROR 3032 "server is currently in offline mode"**,exporter 表现为 `mysql_up 0`。处置:

```sql
SET GLOBAL offline_mode=OFF;   -- 或重启该成员 mysqld
```

账号用第 3 篇的 monitor(SELECT / PROCESS / REPLICATION CLIENT,实测够用)。

## 实测指标样例(2026-09-30 抓取)

```
mysql_up 1
mysql_global_status_threads_connected 1
mysql_global_variables_max_connections 500
mysql_global_status_threads_running 2
mysql_global_status_slow_queries 6
mysql_global_status_innodb_buffer_pool_read_requests 102195
mysql_global_status_innodb_buffer_pool_reads 926        ← 命中率 99.09%
```

**MGR 成员角色指标的实测结论:v0.15.1 默认采集面里没有 member_role / member_status 类指标**(只有 `mysql_global_variables_group_replication_*` 配置项指标与 commands_total)。所以"谁是主、成员是否 ONLINE"仍归命令面(巡检 M06 查 `performance_schema.replication_group_members`),指标面不重复建设。

## 告警规则示例(与巡检阈值对齐)

```yaml
groups:
- name: mysql
  rules:
  - alert: MySQLDown                    # M01 / P0
    expr: mysql_up == 0
    for: 30s
  - alert: MySQLConnUtilizationHigh     # M02 / P1,P0
    expr: mysql_global_status_threads_connected / mysql_global_variables_max_connections > 0.8
    for: 5m
  - alert: MySQLSlowQueriesSurge        # M04 / P1
    expr: rate(mysql_global_status_slow_queries[5m]) > 1
    for: 10m
  - alert: MySQLBufferPoolHitLow        # M08 / P1(样本充足时)
    expr: 1 - rate(mysql_global_status_innodb_buffer_pool_reads[5m])
          / clamp_min(rate(mysql_global_status_innodb_buffer_pool_read_requests[5m]), 1) < 0.95
    for: 30m
```

`clamp_min` 防 0 除;M08 的 30m for 对应巡检"样本充足才判"的纪律。

## Grafana 与边界

- 面板:导入 mysqld exporter 的社区面板起步,按上面 M 编号清单裁剪(连接利用率、活跃线程、慢查询速率、命中率四张核心图);
- **宿主机 CPU/内存/磁盘、容器运行时**(docker daemon、容器重启次数、磁盘写满预测)归 node_exporter + [inspect-server](../../skills/巡检/inspect-server/SKILL.md) 域,不在本文重复;
- 慢查询明细治理(pt-query-digest)是排障动作不是监控指标,见[第 8 篇](8.日常运维与排障.md)。
