# 2. 参数基线与配置模板

## 分组哲学:按"值由谁拍板"分,不按手册章节分

MySQL 系统变量 500+,巡检和基线只需要其中**需要做决策的 ~30 个**。分组依据是"这个参数的值由谁拍板"——每组由此天然知道定值方法:

| 组 | 拍板人 | 核心参数 |
| --- | --- | --- |
| 一、内存与 InnoDB | 机器内存/容器配额 | buffer_pool_size、redo_log_capacity、tmp_table_size |
| 二、连接与线程 | 业务并发模型 | max_connections、wait_timeout、max_allowed_packet |
| 三、持久化与 IO | 安全等级 + 磁盘类型 | 双1、flush_method、io_capacity |
| 四、binlog 与复制 | 部署架构 | binlog 保留、GTID、server_id |
| 五、安全 | 合规,不随业务变 | authentication_policy、密码组件(第 3 篇) |
| 六、字符集与可观测 | 定一次不再动 | utf8mb4、slow log、时区 |

**模板分三层**,单机与 MGR 是继承关系而非两份配置:

```
conf/
├── common.cnf           # 六组基线,所有角色共享
├── role-standalone.cnf  # 单机增量(实测为空——binlog/GTID 已在 common 前置)
└── role-mgr.cnf         # MGR 增量(组参数,见第 5 篇)
```

## 决策参数表(30 项,默认值为 8.4.11 实测)

| 参数 | 默认(实测) | 基线值 | 生效方式 | 拍板 |
| --- | --- | --- | --- | --- |
| innodb_buffer_pool_size | 128M | 专机内存 50~70%(8G 机→4G) | 动态(在线 resize) | 硬件 |
| innodb_redo_log_capacity | 100M | 写密集 1G~4G | **动态**(实测在线改 2G 成功) | 硬件 |
| tmp_table_size / max_heap_table_size | 16M(官方文档值) | 64M(取小者生效) | 动态 | 业务 |
| max_connections | **151** | 按公式(见下) | 动态 | 业务 |
| wait_timeout / interactive_timeout | **28800**(8h) | 600 | 动态 | 业务 |
| max_allowed_packet | 64M | 64M(默认即可) | 动态 | 业务 |
| skip_name_resolve | OFF | ON | **需重启** | 业务 |
| thread_cache_size | auto(官方文档值) | 32 | 动态 | 业务 |
| innodb_flush_log_at_trx_commit | 1 | **1(保持默认)** | 动态 | 安全 |
| sync_binlog | 1 | **1(保持默认)** | 动态 | 安全 |
| innodb_flush_method | O_DIRECT(本镜像默认) | O_DIRECT | **需重启**(实测 read only) | 磁盘 |
| innodb_io_capacity / _max | 200 / 2000(官方文档值) | SSD:2000/4000 | 动态 | 磁盘 |
| log_bin | ON(8.0 起默认开) | ON | — | 架构 |
| binlog_expire_logs_seconds | 2592000(30 天) | 604800(7 天,按磁盘预算) | 动态 | 架构 |
| gtid_mode | **OFF** | **ON(单机就开,演进前置)** | 需重启 | 架构 |
| enforce_gtid_consistency | OFF | ON | 需重启 | 架构 |
| server_id | 1 | 单机 1;集群每台不同 | **需重启** | 架构 |
| character-set-server / collation-server | utf8mb4 / utf8mb4_0900_ai_ci | 显式声明同默认(便于审计) | 需重启 | 一次 |
| default-time-zone | SYSTEM(容器内 UTC) | "+08:00" | 需重启 | 一次 |
| slow_query_log | OFF(镜像默认) | ON | 动态 | 一次 |
| long_query_time | 10 | 1 | 动态 | 一次 |
| log_error_verbosity | 2 | 2 | 动态 | 一次 |

**max_connections 定值公式**:`每连接内存预算(实测 1~2M 常规连接) × max_connections < 总内存 − buffer_pool − 性能schema等开销`。8G 机、4G buffer pool 下,500 留有余量;上限不是越大越好,连接堆积时宁可让应用报错重试,也别让内存先爆。

## 各组要点

**一、内存**:大头给 buffer pool;反面教材是 sort_buffer/join_buffer/read_buffer 这类**每连接乘数**参数——调大 10 倍是每连接多 10 倍,高并发直接内存放大,保持默认、按会话覆盖才是对的。容器配了 `--memory` 时 MySQL 不感知 cgroup 限额,必须手动留余量。

**二、连接**:wait_timeout 600 之外,`skip_name_resolve=ON` 要求账号 host 全用 IP/网段(`root@%`、`app@10.10.12.%`),建号纪律见第 3 篇。

**三、持久化**:双1 是基线也是默认,别动;真正要动的是 io_capacity(SSD 2000 起)和确认 flush_method 为 O_DIRECT。

**四、binlog/GTID**:**单机就把 GTID 开上**——实测 8.4 默认 `gtid_mode=OFF`,而它必须重启切换(运行时切换要走 OFF→ON_PERMISSIVE→ON 三步,等效停机);单机开它零成本,不开则将来进主从/MGR 必须安排一次重启窗口。binlog 保留期默认 30 天,磁盘按这个数预留,收紧到 7 天联动巡检 M07。

**六、可观测**:slow log 开着是巡检 M04 的前提;error log 走 stderr 用 `docker logs` 看。

## 生效方式与漂移纪律(实测实录)

三种生效方式,实测行为:

```sql
-- 1)需重启的参数,SET GLOBAL 直接报错(实测报错原文):
SET GLOBAL innodb_flush_method = fsync;
-- ERROR 1238 (HY000): Variable 'innodb_flush_method' is a read only variable

-- 2)动态参数,立即生效但不持久:
SET GLOBAL max_connections = 600;        -- 重启后回到 my.cnf 的 500

-- 3)SET PERSIST 会写进数据目录的 mysqld-auto.cnf:
SET PERSIST max_connections = 650;
-- 实测:/var/lib/mysql/mysqld-auto.cnf 出现,内容含该参数,重启后仍为 650
```

**8.4.11 实测坑:`RESET PERSIST ALL` 报语法错**(ERROR 1064 near 'ALL'),清空全部持久化用不带参数的:

```sql
RESET PERSIST;              -- ✓ 实测成功;文件保留空壳 {"Version": 2}
RESET PERSIST if exists max_connections;   -- ✓ 删除单个
```

**纪律**:基线一律进 `conf/common.cnf`;`SET PERSIST` 只用于应急;因此漂移检查就是看 `mysqld-auto.cnf` 的内容——**空壳 `{"Version": 2}` 为正常,出现参数即为漂移(巡检 M11 增量)**:

```bash
docker exec mysql cat /var/lib/mysql/mysqld-auto.cnf 2>/dev/null
```

## information_schema 统计缓存坑(联动巡检 M09)

8.0 起 `information_schema.tables` 统计默认缓存 86400 秒(`information_schema_stats_expiry`),**data_length/table_rows 可能是一天前的旧值**。实测对比:

```sql
SELECT table_rows FROM information_schema.tables
 WHERE table_schema='demo' AND table_name='t';        -- 96(此时缓存生成)
INSERT INTO demo.t(pad) SELECT pad FROM demo.t;        -- 行数翻倍
SELECT table_rows FROM information_schema.tables
 WHERE table_schema='demo' AND table_name='t';        -- 仍是 96(旧缓存)
SET SESSION information_schema_stats_expiry = 0;
SELECT table_rows FROM information_schema.tables
 WHERE table_schema='demo' AND table_name='t';        -- 192(实时)
```

巡检 M09 查容量时,若结果用于"增速对比",同一条命令前要带 `SET SESSION information_schema_stats_expiry=0`,否则拿到的是陈旧基线。

## 应用与验证

```bash
# 把 common.cnf(+角色文件)放到配置目录,重启
cp common.cnf role-standalone.cnf /data/mysql/conf/
docker restart mysql    # 实测 6 秒完成(buffer pool 4G)

# 验证(实测输出)
docker exec mysql mysql -uroot -p'Root@2026' -N -e "
SELECT @@innodb_buffer_pool_size, @@innodb_redo_log_capacity;  -- 4294967296  1073741824
SELECT @@max_connections, @@wait_timeout, @@skip_name_resolve;  -- 500  600  1
SELECT @@gtid_mode, @@enforce_gtid_consistency;                 -- ON  ON
SELECT @@binlog_expire_logs_seconds;                            -- 604800"
```
