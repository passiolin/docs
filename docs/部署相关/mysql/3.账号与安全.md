# 3. 账号与安全

> **实测状态**:✅ 已实测 —— MySQL 8.4.11(docker `mysql:8.4`),VM mysql-1,2026-09-30。报错原文均摘自实测。

## 认证插件(8.4 的第一大坑)

8.4 起 `mysql_native_password` **默认禁用**,全部账号使用 `caching_sha2_password`(`authentication_policy='*,,'`,`default_authentication_plugin` 参数已移除)。实测:

```sql
-- 默认建号即 caching_sha2_password:
SELECT user, host, plugin FROM mysql.user;
-- root   %         caching_sha2_password
-- (内置三账号 mysql.infoschema/session/sys 同为 caching_sha2_password)

-- 想建 native password 账号,直接被拒:
CREATE USER oldclient@'%' IDENTIFIED WITH mysql_native_password BY '...';
-- ERROR 1524 (HY000): Plugin 'mysql_native_password' is not loaded
```

**兼容性实测结论**(比传言乐观):

- `mysql:5.7` 镜像(5.7.44 客户端)连 8.4 **实测成功**——较新的 5.7 客户端已支持 caching_sha2;
- 真正连不上的是老栈:5.6 及更早客户端、老版本 PHP/Java 驱动(JDBC 8.0.9 之前)等。

确有老应用改不动时,启动参数重新启用(docker 在镜像名后追加 mysqld 参数即可),实测有效:

```bash
docker run -d ... mysql:8.4 --mysql-native-password=ON
# 实测:之后 CREATE USER ... IDENTIFIED WITH mysql_native_password 成功
# mysql.user 里 plugin 列显示 mysql_native_password
```

该参数是过渡手段,官方已宣布移除方向,老应用应排期升级驱动。

## 账号规划:root 只留本机,三类服务账号最小权限

镜像初始化的 `root@%`(任意来源 + 全权限)是最大的暴露面,收敛原则:**root 仅留 `root@localhost`,按用途建最小权限账号**:

| 账号 | host | 权限 | 用途 |
| --- | --- | --- | --- |
| root@localhost | localhost | 全权限 | 本机管理(容器内 `docker exec`) |
| monitor | % | `SELECT, PROCESS, REPLICATION CLIENT` | 巡检(命令面)与 exporter(指标面) |
| app | `10.10.12.%` | `SELECT,INSERT,UPDATE,DELETE ON appdb.*` | 业务,限库限网段,只给 DML |

```sql
-- 巡检/监控账号(联动巡检 M01~M11 与第 9 篇 exporter)
CREATE USER monitor@'%' IDENTIFIED BY 'Monitor@2026';
GRANT SELECT, PROCESS, REPLICATION CLIENT ON *.* TO monitor@'%';

-- 业务账号(网段 + 单库 + DML)
CREATE USER app@'10.10.12.%' IDENTIFIED BY 'App@2026';
GRANT SELECT, INSERT, UPDATE, DELETE ON appdb.* TO app@'10.10.12.%';

-- root@% 收敛(确认管理路径畅通后再执行):
-- DROP USER root@'%';
```

**最小权限的边界实测**(从 10.10.12.116 发起):

```sql
-- monitor 能做:SHOW REPLICA STATUS(空=非从库)、读 performance_schema、
--               看 information_schema.processlist 全部线程(PROCESS 权限);
-- app 越权,全部被拒(实测报错):
SELECT user FROM mysql.user;                        -- ERROR 1142: SELECT command denied
SELECT COUNT(*) FROM performance_schema.replication_group_members;
                                                    -- ERROR 1142: SELECT command denied
CREATE TABLE appdb.t1(...);                         -- ERROR 1142: CREATE command denied(业务号无 DDL)
SHOW PROCESSLIST;                                   -- 只能看到自己的连接(无 PROCESS 权限)
```

两个容易踩的点:
1. host 匹配是**连接来源 IP**决定的:从 127.0.0.1 连,`app@'10.10.12.%` 根本匹配不上,直接 `ERROR 1045 Access denied`——测试网段账号要从对应网段的机器发起;
2. 业务账号不给 DDL:表结构变更走迁移工具/DBA(第 8 篇的大表 DDL 流程)。

## 密码策略:组件 + 失败锁定 + 有效期

**密码强度组件**(8.4 用 component,不是老 plugin):

```sql
INSTALL COMPONENT 'file://component_validate_password';   -- 默认 MEDIUM 策略

CREATE USER weak@'%' IDENTIFIED BY '123456';
-- ERROR 1819 (HY000): Your password does not satisfy the current policy requirements
```

**失败锁定**(8.0.19+,防爆破,建议全账号默认):

```sql
CREATE USER lockt@'%' IDENTIFIED BY '...' FAILED_LOGIN_ATTEMPTS 3 PASSWORD_LOCK_TIME 2;
```

实测行为:错 1、2 次返回普通 `ERROR 1045`;第 3 次起返回 `ERROR 3955: Account is blocked for 2 day(s) remaining`,**期间正确密码也进不来**。注意锁定按"账号+来源主机"计数,服务器重启不解除,只能等或 `ALTER USER` 重置。

**密码有效期**:

```sql
ALTER USER app@'10.10.12.%' PASSWORD EXPIRE INTERVAL 90 DAY;
-- 实测 mysql.user.password_lifetime = 90
```

服务账号(应用连库用的)建议 `PASSWORD EXPIRE NEVER` 并把轮换交给配置中心,避免到期后应用批量拒连。

## 与部署形态的关系

- 密码只出现在两处:`docker run -e MYSQL_ROOT_PASSWORD`(仅首次初始化)与密码管理源;**不进 shell history 的做法**:`-e MYSQL_ROOT_PASSWORD` 改用 `--env-file` 或从 vault 注入;
- 内网部署当前未启用 TLS(`require_secure_transport=OFF`);跨机房/接入不可信网络时开启 TLS 并 `require_secure_transport=ON`(官方 8.4 手册:https://dev.mysql.com/doc/refman/8.4/en/encrypted-connections.html );
- 巡检联动:账号安全检查项(空密码账号、`%`+高权限账号、native password 账号存量)并入巡检 M11 基线。
