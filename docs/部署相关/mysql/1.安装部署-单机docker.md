# 1. 安装部署-单机 docker

## 目标与前置

一台干净的 Linux 机器上,用 docker 跑起一个生产可用的单机 MySQL 8.4:开机自启、健康检查、优雅停止、数据落盘在宿主机目录、远程可连。

前置:机器可上外网(apt 源可用);内存 ≥2G(实验环境 4C/8G);`/data` 分区空间足够。

## 第一步:安装 docker 并配置国内镜像加速

Ubuntu 直接用仓库里的 `docker.io`,不必加 Docker 官方源:

```bash
apt-get update
apt-get install -y docker.io
systemctl enable --now docker
docker version --format 'client={{.Client.Version}} server={{.Server.Version}}'
# 实测输出:client=29.1.3 server=29.1.3
```

配置镜像加速(daocloud 加速器实测可用;Docker Hub 直连在公司网络经常拉不动):

```bash
mkdir -p /etc/docker
echo '{ "registry-mirrors": ["https://docker.m.daocloud.io"] }' > /etc/docker/daemon.json
systemctl restart docker
docker info | grep -A2 "Registry Mirrors"
```

## 第二步:目录规划与最小配置

沿用 kafka 等组件的惯例,数据全部落在 `/data`,目录与配置分离:

```bash
mkdir -p /data/mysql/{data,conf}
```

写一个最小 `my.cnf`(完整参数基线见[第 2 篇](2.参数基线与配置模板.md),这里只放"不设就会踩坑"的几项):

```bash
cat > /data/mysql/conf/my.cnf <<'EOF'
[mysqld]
# 字符集(8.4 默认即 utf8mb4,显式声明便于审计)
character-set-server = utf8mb4
collation-server     = utf8mb4_0900_ai_ci
# 时区(默认 SYSTEM 跟容器内 UTC,业务侧时间会差 8 小时)
default-time-zone    = "+08:00"
# 慢查询(巡检 M04 依赖;镜像默认不开)
slow_query_log       = ON
long_query_time      = 1
EOF
```

## 第三步:启动容器

```bash
docker run -d \
  --name mysql \
  --restart=always \
  --stop-timeout=300 \
  --ulimit nofile=1000000 \
  --health-cmd="mysqladmin ping -h127.0.0.1 -uroot -p\"\$MYSQL_ROOT_PASSWORD\" --silent" \
  --health-interval=15s --health-timeout=5s --health-retries=10 \
  -p 3306:3306 \
  -v /data/mysql/data:/var/lib/mysql \
  -v /data/mysql/conf:/etc/mysql/conf.d \
  -e TZ=Asia/Shanghai \
  -e MYSQL_ROOT_PASSWORD=Root@2026 \
  mysql:8.4
```

逐行说明:

| 参数 | 作用 | 不设的后果 |
| --- | --- | --- |
| `--restart=always` | 宕机/重启自拉起 | 宿主机重启后 MySQL 不起来 |
| `--stop-timeout=300` | `docker stop` 发 SIGTERM 后最多等 300s 再 KILL | 默认 10s 后 SIGKILL,大 buffer pool 刷脏没做完就被杀,重启走崩溃恢复,时间不可控 |
| `--ulimit nofile=1000000` | 文件句柄上限 | 默认值(实测 1048576 需显式,不同环境默认可能低到 1024)高连接数下报 "Too many open files" |
| `--health-cmd=...` | 容器健康检查(密码读容器内环境变量,不落明文) | `docker ps` 里看不到健康状态,编排/巡检无法判断 |
| `-p 3306:3306` | 端口映射 | 单机够用;**组 MGR 时必须换 `--net=host`**(见第 5 篇) |
| `-v /data/mysql/data:/var/lib/mysql` | 数据目录落宿主机 | 数据在容器 layer 里,容器删了数据就没了 |
| `-v /data/mysql/conf:/etc/mysql/conf.d` | 配置挂载 | 改参数要重建镜像 |
| `-e TZ=Asia/Shanghai` | 容器时区 | `docker logs` 时间戳为 UTC,排障对不上业务时间 |

注意:
- **`--stop-grace-period` 不是 `docker run` 的参数**(那是 docker-compose 的 `stop_grace_period`),实测直接报 `unknown flag`。docker 侧对应的就是 `--stop-timeout`;
- `MYSQL_ROOT_PASSWORD` 只在**数据目录为空的首次初始化**时生效,之后改密码要进 SQL 改(见[第 3 篇](3.账号与安全.md));生产环境把密码换成密码管理源的值,不要明文进 shell history;
- 生产建议把镜像钉到 digest(`mysql:8.4@sha256:6ea90827b110...`),避免 tag 漂移。

## 第四步:验证

**等健康检查通过**(首次初始化约 20~30 秒):

```bash
for i in $(seq 1 40); do
  st=$(docker inspect --format '{{.State.Health.Status}}' mysql)
  [ "$st" = "healthy" ] && break
  sleep 3
done
docker inspect --format 'Health={{.State.Health.Status}} StopTimeout={{.Config.StopTimeout}} RestartPolicy={{.HostConfig.RestartPolicy.Name}}' mysql
# 实测输出:Health=healthy StopTimeout=300 RestartPolicy=always
```

**看启动日志**(error log 默认走 stderr,即 `docker logs`,这也是不额外挂 logs 卷的原因):

```bash
docker logs mysql 2>&1 | grep -i "ready for connections" | tail -1
# 实测输出:... [System] [MY-010931] [Server] /usr/sbin/mysqld: ready for connections.
#           Version: '8.4.11'  socket: '/var/run/mysqld/mysqld.sock'  port: 3306  ...
```

**本机连通性**:

```bash
docker exec mysql mysqladmin ping -h127.0.0.1 -uroot -pRoot@2026
# 实测输出:mysqld is alive
docker exec mysql mysql -uroot -pRoot@2026 -N -e "SELECT VERSION();"
# 实测输出:8.4.11
```

**远程连通性**(推荐方式:用同一个镜像当客户端,宿主机不用装 mysql-client):

```bash
docker run --rm mysql:8.4 mysql -h<MySQL机器IP> -P3306 -uroot -p'Root@2026' \
  -e "SELECT VERSION(), CURRENT_USER(), NOW();"
# 实测输出(从另一台 VM 连入):
# 8.4.11   e2113f8e90ef   root@%   2026-09-30 21:00:34
```

输出里三处值得注意:`@@hostname` 是**容器 ID** 不是宿主机名(排障时要意识到);`root@%` 表示镜像初始化的 root 允许任意来源(治理见第 3 篇);`NOW()` 是 +08:00 时区生效的证据。

## 日常操作

```bash
docker logs -f mysql              # 跟踪 error log
docker restart mysql              # 重启(stop 阶段受 stop-timeout 保护)
docker stop mysql && docker start mysql   # 等价,语义更清楚
docker exec -it mysql mysql -uroot -p     # 交互式进 SQL
docker inspect --format '{{json .State.Health}}' mysql | python3 -m json.tool | tail -8   # 最近几次健康检查输出
```

**容器可以随手删,数据不会丢**(数据在宿主机 `/data/mysql/data`):

```bash
docker rm -f mysql                # 删容器
# 重新 docker run(同一条命令),数据原地续用,MYSQL_ROOT_PASSWORD 不再生效
```

## 已知坑

1. **`--stop-grace-period` 不存在**:docker run 的参数是 `--stop-timeout`(实测验证,见上);
2. **首次启动 `MYSQL_ROOT_PASSWORD` 含特殊字符要用引号包整段**:`-e MYSQL_ROOT_PASSWORD='Roo&t@2026'`,否则 `&`、`$` 会被 shell 解释;
3. **数据目录非空时初始化跳过**:从别的机器搬来的 data 目录直接挂上,`MYSQL_ROOT_PASSWORD` 不生效,密码是搬来目录里原来那套;
4. **`innodb_buffer_pool_size` 镜像默认只有 128M**(实测 134217728),必须显式设,见第 2 篇;
5. 8.4 的 `default_authentication_plugin` 参数已移除,取而代之 `authentication_policy='*,,'`(默认插件 caching_sha2_password)——老客户端连不上的处理见第 3 篇;
6. 容器内存若配了 `--memory` 上限,MySQL **不会自动感知 cgroup 限额**,buffer pool 等内存参数必须手动留余量,否则 OOM kill 循环。
