# 日常运维与排障

接手这套 RKE2 集群后的日常动作与故障字典。所有命令在 2026-10-10/11 的三节点集群实测过;每条排障给出真实出处,细节链到对应篇。

## 一、每日体检(两分钟)

```bash
kubectl get nodes                                   # 三台 Ready
kubectl get pods -A | grep -vE "Running|Completed"  # 应为空
kubectl get ippools.crd.projectcalico.org           # default-ipv4-ippool 在(没有=IPAM 瘫,见第 7 篇)
kubectl get helmchart -n kube-system                # 只有 rke2-calico,无 rke2-canal(CNI 冲突前兆)
ls /var/lib/rancher/rke2/server/db/snapshots/ | tail -3   # 快照在按时落
kubectl get certificate -A                          # 业务证书 READY
```

判别顺序:节点 → 系统Pod → IPPool → HelmChart → 快照。任何一项异常,先查 [第 7 篇](7.容灾实测.md) 的对应段落再动手。

## 二、证书

有效期 12 个月,剩余不足 90 天时服务重启即自动轮换;审计命令:

```bash
for cert in /var/lib/rancher/rke2/server/tls/serving-kube-apiserver.crt; do
  openssl x509 -in $cert -noout -enddate
done
```

主动轮换(实测流程见 [第 2 篇](2.安装部署-集群.md) 第 2 节,加 tls-san 后必须做):`systemctl stop rke2-server && rke2 certificate rotate && systemctl start rke2-server`。禁止手工删 server/tls/ 下的证书文件。

## 三、备份与恢复

快照默认每小时落盘、保留 5 份;变更前手动 `rke2 etcd-snapshot save --name <用途>`。全量恢复(cluster-reset + 对端清 db 重加入)的完整流程与踩坑在 [第 7 篇](7.容灾实测.md),要点只有三条:恢复节点先起、对端必须删 server/db、残留 VIP 要手工清。

## 四、版本升级

原则:**K8S 不支持降级**,升级失败只能走快照恢复;升级前 `rke2 etcd-snapshot save --name pre-upgrade`;逐台 server 滚动(同一版本号三台一致);换版本号重跑安装脚本即可,无需先 stop。

```bash
curl -sfL https://rancher-mirror.rancher.cn/rke2/install.sh | \
  INSTALL_RKE2_MIRROR=cn INSTALL_RKE2_VERSION=<新版本+rke2r1> sh -
```

节点多后的自动化用 system-upgrade-controller(待实测)。插件升级走各自 helm:`helm upgrade`(metallb/kps)与 manifest 重 apply(cert-manager)。

## 五、节点维护

```bash
kubectl cordon k8s-server-02
kubectl drain k8s-server-02 --ignore-daemonsets --delete-emptydir-data
# ...维护/重启(rke2 完整停机 = systemctl stop + rke2-killall,见第 2 篇)...
kubectl uncordon k8s-server-02
```

漂移保护已实测:单台完整停止,VIP 20 秒内切走,业务无感;local-path 的卷钉在宿主节点,该节点下线前先迁移对应有状态负载。

## 六、排障字典(全部实测)

| 现象 | 原因 | 处置 | 出处 |
| --- | --- | --- | --- |
| 新 Pod 全部 FailedCreatePodSandBox: cannot find a qualified ippool | canal/calico chart 互删把 IPPool 删了 | 查 helmchart 是否混入 rke2-canal;修不了走快照恢复 | 第 7 篇第 2 节 |
| Pod 卡 ContainerCreating 十分钟以上 | mirror 拉镜像慢 | describe 看 Pulling 行,等;镜像名核 registries.yaml | 第 1 篇 |
| Pod `0/1 Running` | 探针不过(如空 PVC 盖掉默认页 403) | 修探针路径或让应用自产首页 | 第 6 篇第 5 节 |
| ImagePullBackOff | 节点缺 registries.yaml 或改后未重启 | 补配置 + restart rke2-server/agent | 第 2 篇 |
| 经 VIP 访问 API 证书报错 | tls-san 缺 VIP 且未轮换 | 补 tls-san + certificate rotate | 第 2 篇第 2 节 |
| LoadBalancer Service 一直 Pending | v1.35 无 ServiceLB,MetalLB 未装或池/公告没配 | 装 [plugins/metallb](plugins/metallb/README.md),池+L2Advertisement 缺一不可 | 实测 |
| agent 加不上集群 | token 不一致/server 不可达/主机名重复 | journalctl -u rke2-agent 逐项排 | 第 1 篇 |
| systemctl stop 后节点"假活" | shim 与容器存活 | 完整停机加 rke2-killall.sh | 第 2 篇第 6 节 |
| 经 VIP 的 9345/6443 时通时断 | 非优雅停机残留 VIP,双节点同持一 IP | 残留节点 ip addr del + 重启 kube-vip 容器 | 第 7 篇第 4 节 |
| helm 报 release name still in use | 旧 release secret 未清 | 按第 7 篇第 4 节次序清理后重装 | 第 7 篇第 4 节 |
| calico 封装/端口对不上资料 | RKE2 calico v3.32 默认 VXLAN(4789/udp),非 IPIP | 以 installation 对象为准 | 第 3 篇 |
| kubectl get cs 报错或信息不可信 | 组件状态接口已废弃 | 用 kubectl get pods -A 直接看静态 Pod | 第 1 篇 |
