# 监控与告警

kube-prometheus-stack 一套装齐:Prometheus(采集+存储)、Grafana(看板)、Alertmanager(告警)、prometheus-operator(生命周期)、kube-state-metrics + node-exporter(数据源)。2026-10-11 在三节点集群实测安装,8 个 Pod 约 10 分钟全部 Running(大镜像经 mirror 拉取为主)。

## 1. 安装

helm 安装(需 [第 2 篇](2.安装部署-集群.md) 的 helm 与 KUBECONFIG):

```bash
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm repo update
helm install kps prometheus-community/kube-prometheus-stack -n monitoring --create-namespace \
  --set prometheus.prometheusSpec.retention=7d \
  --set grafana.service.type=LoadBalancer
```

两个值的取舍:retention 默认 10d,实验室盘小改 7d;Grafana 用 LoadBalancer 暴露的前提是集群有 MetalLB([plugins/metallb](plugins/metallb/README.md)),实测自动从地址池分到 10.10.12.241。生产建议 Grafana 走 ingress + cert-manager 证书,不必占池内地址。

## 2. 验证(实测)

```bash
kubectl -n monitoring get pods            # 8 个:operator/prometheus-0/alertmanager-0/grafana/
                                          # kube-state-metrics/3×node-exporter,全部 Running
# 抓取健康度:up==1 的目标数(实测 23 个,含控制面/节点/组件)
curl -s "http://<prometheus-svc-IP>:9090/api/v1/query?query=count(up==1)"

# Grafana 从集群外可达(302 → 登录页)
curl -o /dev/null -w "%{http_code}\n" http://10.10.12.241/

# 管理员凭据(chart 随机生成,不入库不进文档)
kubectl -n monitoring get secret kps-grafana \
  -o jsonpath="{.data.admin-user}" | base64 -d; echo
kubectl -n monitoring get secret kps-grafana \
  -o jsonpath="{.data.admin-password}" | base64 -d
```

Grafana 内置看板即够用:Node Exporter Full(节点全景)、Kubernetes / Compute Resources(命名空间与工作负载)、Prometheus Stats。导入 ID 在 grafana.com dashboards 检索,数据源 `Prometheus` 已自动配好。

## 3. 关键监控对象(速查)

| 对象 | 核心指标/来源 | 关注点 |
| --- | --- | --- |
| 节点 | node-exporter(每台一个 DS) | CPU/内存/磁盘 IO/网络;`kube_pod_container_resource_limits` 对照 |
| 控制面 | kube-apiserver/etcd 内置抓取 | etcd 延迟与 leader 变更、apiserver 5xx 率 |
| 工作负载 | kube-state-metrics | 副本满足度、Pod 重启、PVC 容量 |
| 证书 | kube-state-metrics 的 cert 距离过期天数 | RKE2 节点证书 1 年轮换(第 8 篇),业务证书走 cert-manager 续期 |
| ingress/ LB | ingress-nginx 指标、metallb speaker | 499/5xx 比例、地址池水位 |

## 4. 告警

stack 自带一组默认规则(etcd、K8S 组件、节点 NotReady 等),Alertmanager Web UI 确认规则已加载。对外通知渠道(飞书/钉钉 webhook)尚未接——Alertmanager 的 `alertmanager.config` values 段配置 receiver,待实测后回填。

## 5. 日志

指标之外的日志由 Loki + promtail 承担,装好后自动注册为本篇 Grafana 的数据源,安装与验证见 [plugins/loki](plugins/loki/README.md)。

## 6. 卸载

```bash
helm uninstall kps -n monitoring && kubectl delete ns monitoring
# CRD 与 PV 不随 helm 删除,残留按需清理:kubectl get crd | grep -E "monitoring|prometheus"
```
