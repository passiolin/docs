# 安装部署-单节点

RKE2 的最短可用路径:一台 server 拉起全套控制面,集群即可跑业务。本篇实测于 k8s-server-01(10.10.12.141,PVE 虚机,Ubuntu 26.04 LTS,4C/8G/60G),RKE2 v1.35.6+rke2r1,2026-10-10。单节点与三节点集群的差别只在 config.yaml 的 tls-san 和后续加入的节点——第 2 篇的集群化以本篇为前缀,要高可用可从单节点平滑升级,不必推倒重来。

## 1. 系统前置(每台节点)

```bash
hostnamectl set-hostname k8s-server-01    # 全集群唯一

# 节点互达:hosts 或内网 DNS
cat >> /etc/hosts <<'EOF'
10.10.12.140 k8s-vip
10.10.12.141 k8s-server-01
10.10.12.142 k8s-server-02
10.10.12.143 k8s-server-03
EOF

# 关 swap(cloud 镜像默认带 /swap.img)
swapoff -a && sed -i '/swap.img/d' /etc/fstab

cat > /etc/modules-load.d/rke2.conf <<'EOF'
overlay
br_netfilter
EOF
modprobe overlay; modprobe br_netfilter

cat > /etc/sysctl.d/rke2.conf <<'EOF'
net.ipv4.ip_forward = 1
net.bridge.bridge-nf-call-iptables = 1
net.bridge.bridge-nf-call-ip6tables = 1
EOF
sysctl --system

# 时间同步:etcd 与证书都对时钟敏感
apt install -y chrony && systemctl enable --now chrony   # RHEL 系包名/服务名均为 chronyd
timedatectl set-timezone Asia/Shanghai
```

## 2. 镜像加速(每台节点,启动 rke2 之前写好)

系统镜像(docker.io/rancher/*)与业务镜像全部经此走国内 mirror,worker 节点同样需要。全文见 [conf/registries.yaml](conf/registries.yaml):

```bash
mkdir -p /etc/rancher/rke2
scp conf/registries.yaml root@<节点>:/etc/rancher/rke2/registries.yaml
```

改动后 `systemctl restart rke2-server`(或 rke2-agent)生效。crictl pull 验证:`/var/lib/rancher/rke2/bin/crictl --config /var/lib/rancher/rke2/agent/etc/crictl.yaml pull docker.io/library/nginx:alpine`。

`system-default-registry`(系统镜像整体换前缀)不再配置:mirror 已覆盖拉取,少一层变量。

## 3. config.yaml

```bash
mkdir -p /etc/rancher/rke2
openssl rand -hex 24    # 生成 token,三台一致;入配置文件,不写进文档
```

单节点版本(完整注释版见 [conf/config-server.yaml](conf/config-server.yaml)):

```yaml
# /etc/rancher/rke2/config.yaml
token: <TOKEN>
cni: calico
cluster-cidr: 10.42.0.0/16      # Pod 网段
service-cidr: 10.43.0.0/16     # Service 网段
tls-san:
  - 10.10.12.141                # 本机 IP;将来集群化时再补 VIP 一行并轮换证书(见第 2 篇)
```

cluster-cidr 是 Pod 网段、service-cidr 是 Service 网段;两个 /16 与节点所在的 10.10.12.0/24 不冲突即可,建集群后不可改。

## 4. 安装与启动

```bash
curl -sfL https://rancher-mirror.rancher.cn/rke2/install.sh | \
  INSTALL_RKE2_MIRROR=cn INSTALL_RKE2_VERSION=v1.35.6+rke2r1 sh -
systemctl enable --now rke2-server
journalctl -u rke2-server -f
```

实测记录(2026-10-10):下载解包约 1 分钟,服务拉起后系统镜像经 mirror 分批拉取,节点 Ready 约 5 分钟、全部 Pod Running 约 8 分钟;最慢的是 `rancher/mirrored-calico-kube-controllers`。首次启动期个别组件会短暂出现 `FailedScheduling: untolerated taint(s)` 事件——那是节点 NotReady 期间的历史事件,节点 Ready 后自动调度成功,不用处理。

版本升级直接换版本号重跑安装脚本(幂等),无需先 stop。完全断网或 mirror 失效走离线包:从 rancher-mirror.rancher.cn/rke2/releases/ 取对应版本的 `rke2.linux-amd64.tar.gz`、`rke2-images.linux-amd64.tar.zst` 与校验文件放同一目录,以 `INSTALL_RKE2_ARTIFACT_PATH=<目录>` 跑同一条命令(未实测)。

## 5. 工具配置

```bash
cat > /etc/crictl.yaml <<'EOF'
runtime-endpoint: unix:///run/k3s/containerd/containerd.sock
image-endpoint: unix:///run/k3s/containerd/containerd.sock
EOF

cat > /etc/profile.d/rke2.sh <<'EOF'
export KUBECONFIG=/etc/rancher/rke2/rke2.yaml
export PATH=$PATH:/var/lib/rancher/rke2/bin
EOF
source /etc/profile.d/rke2.sh

kubectl completion bash > /etc/bash_completion.d/kubectl
crictl completion bash > /etc/bash_completion.d/crictl
```

## 6. 装后验证

```bash
kubectl get nodes -o wide        # STATUS=Ready;ROLES=control-plane,etcd
kubectl get pods -A              # 全部 Running/Completed;get cs 已废弃,不要用
kubectl top node                 # metrics-server 为 RKE2 内置,直接可用

# DNS(busybox 才有 nslookup;pause 镜像没有 shell)
kubectl run dns-test --rm -it --image=busybox:1.36 --restart=Never -- \
  nslookup kubernetes.default.svc.cluster.local

# Service 连通:用 TCP 探测;ICMP 到 ClusterIP 不通属正常,kube-proxy 不转发 ICMP
kubectl run net-test --rm -it --image=busybox:1.36 --restart=Never -- \
  nc -zv -w2 10.43.0.1 443
```

实测注意两点:calico 的组件在 `calico-system` 命名空间(tigera-operator 形态),验证用 `kubectl get pods -n calico-system`,旧资料里 `-n kube-system -l k8s-app=calico-node` 的查法不适用;etcd 快照目录 `/var/lib/rancher/rke2/server/db/snapshots/` 默认每个整点落一份,想立即验证可手动触发:

```bash
rke2 etcd-snapshot save --name manual-test
# 实测输出:Snapshot manual-test-k8s-server-01-<时间戳> saved. 约 17M
```

## 7. 卸载(重装/回收节点)

```bash
/usr/local/bin/rke2-uninstall.sh      # server;agent 用 rke2-agent-uninstall.sh
```

脚本在 `/usr/local/bin`,不在 data-dir/bin;uninstall 自带 killall,单用 `rke2-killall.sh` 只清进程不清数据。

## 8. 单节点踩坑实录

| 现象 | 结论(2026-10-10 实测) |
| --- | --- |
| Pod 卡 ContainerCreating 十分钟 | mirror 拉镜像慢,看 `kubectl describe pod` 的 Pulling 行等它;不是故障 |
| 启动期 FailedScheduling 事件 | 节点 NotReady 阶段的残留事件,节点 Ready 后自愈 |
| crictl 命令不存在 | 未做第 5 节工具配置;或用全路径 /var/lib/rancher/rke2/bin/crictl |
| RKE2 v1.35 没有 StorageClass | v1.35 不再内置 local-path-provisioner,存储要自装,见第 5 篇 |
