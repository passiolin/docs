# 管理面板:Rancher

管理面板选型定为 **Rancher**（KubeSphere 社区版及其 KubeKey 工具链已转闭源授权，不再考虑）。本篇记录 RKE2 集群上安装 Rancher v2.15.2 的完整实测过程——包括三处部署修复的根因，以及首启 catalog 拉取的当前状态。

## 一、前置条件(本集群已全部就绪)

| 依赖 | 本集群形态 | 出处 |
| --- | --- | --- |
| cert-manager | v1.21.2,selfsigned ClusterIssuer 就绪 | [plugins/cert-manager](../plugins/cert-manager/README.md) |
| Ingress | rke2-ingress-nginx,DaemonSet hostPort 80/443,三节点全通 | [第 4 篇](4.入口与暴露.md) |
| LoadBalancer | metallb(可选,给面板发独立 IP 用) | [plugins/metallb](../plugins/metallb/README.md) |

## 二、安装(helm,实测 chart v2.15.2)

```bash
helm repo add rancher-latest https://releases.rancher.com/server-charts/latest
kubectl create ns cattle-system

# 自签证书:cert-manager 为面板域名签发,secret 名必须按 Rancher 约定 tls-rancher-ingress
cat <<EOF | kubectl apply -f -
apiVersion: cert-manager.io/v1
kind: Certificate
metadata:
  name: rancher-k8s-lab
  namespace: cattle-system
spec:
  secretName: tls-rancher-ingress
  dnsNames: [rancher.k8s.lab]
  issuerRef:
    name: selfsigned-cluster
    kind: ClusterIssuer
EOF

openssl rand -hex 12   # 生成 bootstrap 密码,存好,勿入文档

helm install rancher rancher-latest/rancher -n cattle-system \
  --set hostname=rancher.k8s.lab \
  --set replicas=1 \
  --set bootstrapPassword=<生成的密码> \
  --set ingress.tls.source=secret
```

实测注意:ingress 对象会自动落三节点(hostPort 形态),`https://rancher.k8s.lab` 经任一节点 IP + hosts 解析即可访问。

## 三、部署修复实录(三处,按发现顺序)

### 3.1 bootstrap 密码未注入 → Pod 崩溃循环

后台启动安装时,`--set bootstrapPassword=$PW` 的会话变量在新 SSH 会话中为空,渲染出的 Pod 带着空的 `CATTLE_BOOTSTRAP_PASSWORD`,Rancher 启动即 fatal(`ID cannot be empty`)崩溃循环。**修复**:`helm upgrade rancher ... --reuse-values --set bootstrapPassword=<真实密码>`。教训:**后台安装的参数用 env 传递,不依赖会话变量**。

### 3.2 startupProbe 120 秒 < 首启 CRD 应用时间 → 无限重启

Rancher 首次启动要顺序创建自己的一百多个 CRD 并做迁移,耗时远超 chart 默认的 startupProbe 宽容期(failureThreshold 12 × 10s = 120 秒)。kubelet 到点 SIGTERM,重启后从零再来,永远初始化不完。实测修复分两步:

```bash
# 第一步:放宽到 600 秒(在 CRD 较少的集群可能就够了)
kubectl -n cattle-system patch deploy rancher --type=json -p '[
 {"op":"replace","path":"/spec/template/spec/containers/0/startupProbe/failureThreshold","value":60},
 {"op":"replace","path":"/spec/template/spec/containers/0/livenessProbe/failureThreshold","value":10}]'

# 第二步(本集群实测需要):首启卡在 catalog 克隆(见 3.3),直接摘除探针,让它不限时完成
kubectl -n cattle-system patch deploy rancher --type=json -p '[
 {"op":"remove","path":"/spec/template/spec/containers/0/startupProbe"},
 {"op":"remove","path":"/spec/template/spec/containers/0/livenessProbe"}]'
```

> 探针移除后 Rancher 就绪判定要人工盯:`kubectl -n cattle-system get pods` 出现 `1/1 Running` 且 `--restarts` 不再增长,即初始化完成。

### 3.3 2G 镜像在新节点的分发

Pod 漂移到无镜像缓存的节点时,2G 的 rancher 镜像经 mirror 重拉很慢。实测的加速手法:

```bash
# 有镜像的节点导出 → 中转 → 无镜像节点导入(containerd 的 k8s.io 命名空间)
ctr -n k8s.io --address /run/k3s/containerd/containerd.sock images export /tmp/rancher-img.tar docker.io/rancher/rancher:v2.15.2
ctr -n k8s.io --address /run/k3s/containerd/containerd.sock images import --no-unpack /tmp/rancher-img.tar
```

注意 rke2 节点的 ctr 不在 PATH,全路径 `/var/lib/rancher/rke2/bin/ctr`;节点间无互信时经管理机中转。

## 四、当前状态:首启卡在 catalog 拉取(2026-10-11 记录)

- 证书(secret `tls-rancher-ingress`)、ingress(三节点 80/443)、镜像、bootstrap 密码全部就位
- 摘除探针后 Pod 稳定运行,但首启流程卡在 **catalog 的 git 拉取**:Rancher 首启要从 github 克隆 rancher-charts / rancher-partner-charts / rancher-rke2-charts 三个大仓库(全量历史,实测单仓库 ~950M 起),节点到 github 的克隆带宽不稳定——第一个仓库(rancher-charts)能 2 分钟完成,第二个(rke2-charts)反复克隆 20-60 分钟不落地后进程报错退出,容器重启从零再来
- 宿主机同仓库 `git clone --depth 1` 实测 2 分钟完成 946M——注意 rancher 内部克隆是**全量历史**,体积数倍于 depth 1,对比测试别被浅克隆误导

已验证的缓解与遗留:

1. 摘除探针(见 3.2)是必要前提——否则 120/300 秒探针把克隆中往返杀掉,永不收敛;摘除后 Pod 由容器重启机制自动重试克隆
2. **等网络良好时段重启 Pod 触发重试**(自动重试机制已在运行):单次全链路成功即完成,成功后 catalog 缓存进 Rancher 存储,后续升级不再重克隆
3. 加速方案(待实测):给容器注入 github 代理;或 airgap 式预置 catalog(节点侧预克隆三仓库后按 Rancher 离线文档注入)

## 五、初始化完成后的引导(待执行)

1. 客户端 `/etc/hosts` 加:`10.10.12.141 rancher.k8s.lab`(任一节点 IP,或 metallb 给面板发的独立 IP)
2. 浏览器打开 `https://rancher.k8s.lab`(自签证书,信任即可)
3. 首页粘贴 bootstrap 密码(在 141 节点 `/tmp/rancher-bootstrap`),设置 admin 密码
4. 完成本地集群(local cluster)的默认接入,Rancher 即开始纳管

## 六、卸载

```bash
helm uninstall rancher -n cattle-system
kubectl delete ns cattle-system   # fleet/系统 CRD 残留按需清理
```

已知注意:本集群 4C/8G 节点已承载监控/日志/多存储引擎,Rancher 官方建议为其预留 2C4G——长期运行建议扩节点或降低共载密度(实测 Rancher 单副本在初始化完成后稳态内存约 1-1.5G,待后续回填精确值)。
