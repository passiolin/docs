# llama.cpp 本地推理(coder390)

> - **形态**:llama.cpp 的 `llama-server` 承载 **Qwen3.8-27B-Coder390** GGUF(Q3LynnStyle-Q8MTP,17.5G),对外暴露 OpenAI 兼容 API,128K 上下文,systemd 开机自启。
> - **实测环境**:2080ti22g(10.10.12.2,PVE 虚拟机,RTX 2080 Ti 22G 魔改,内存 122G,SSD 750G);llama.cpp 自编 CUDA 13.4,只编 sm_75;2026-10-10。
> - **当前状态**:2026-11-04 起 `coder390.service` 已 `stop` 并 `disable`,20.7GB 显存让给 [MOSS-Image-SFT](../moss-image/README.md);恢复命令与共存限制见第 1 篇 3.3。
> - **适用场景**:编码 agent 的本地推理后端,文本 + 图像输入,生成约 25 tok/s。

## 这个目录在讲什么

2080ti22g 上原本跑的是本地代码大模型服务,选型落在稠密 27B 的 Q3 量化档:同一模型的 Q3/Q6/Q8 在 GPQA/MMLU/LCB 上打平,显存放得下的档位就够用,不必为了 MoE 的内存分层去牺牲速度。

上下文定在 128K。KV 缓存随上下文线性增长,22G 卡扣掉 16.3GiB 权重与视觉编码器后只剩约 4G,K 用 q4_0、V 留 q8 才留出 1.7G 余量。2026-11 起这张卡改跑文生图,原服务已停用,配置与踩坑保留在第 1 篇。
