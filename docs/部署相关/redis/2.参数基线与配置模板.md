# 2. 参数基线与配置模板

> **实测状态**:✅ 已实测 —— Redis 8.0.6,基线配置已在 redis-1/2/3 实际应用验证。模板见 [conf/](conf/):`common.conf` + 四种角色文件 + `gen-node-conf.sh`。

## 分组:按"值由谁拍板"

Redis 参数远少于 MySQL,但"默认值能不能上生产"的判别同样重要:

| 组 | 拍板人 | 核心参数(默认 → 基线) |
| --- | --- | --- |
| 一、内存 | 机器内存 + 业务语义 | maxmemory(0 → 2gb)、maxmemory-policy(noeviction → allkeys-lru) |
| 二、持久化 | 数据等级 | save(默认 3600 1/300 100/60 10000 保持)、appendonly(no → yes)、appendfsync(everysec 保持) |
| 三、网络与连接 | 业务并发 | maxclients(10000 保持)、tcp-backlog(511 保持)、timeout(0 保持) |
| 四、复制 | 架构 | masterauth(基线前置)、repl-backlog-size(1mb → 64mb) |
| 五、安全 | 合规 | requirepass(空 → 必设)、protected-mode(yes 保持) |
| 六、可观测 | 定一次 | slowlog-log-slower-than(10000 保持)、latency-monitor-threshold(0 → 100) |

**默认值里两个必须改的**(巡检 R02/R04 直接挂钩):

1. `maxmemory=0` 不限内存——实例会吃到把宿主 OOM 为止,必须显式设上限(专机 50~70%,给 fork COW 和副本同步留余量);
2. `maxmemory-policy=noeviction`——写满后**所有写命令报错**。缓存场景换 allkeys-lru;当存储用才保留 noeviction,且必须监控 evicted_keys(R09)。

**一个可以不改的常识**:appendfsync=everysec 是性能与安全的默认折中(最多丢 1 秒),always 只在极特殊合规要求下用。

## 模板分层与节点差异

```
conf/
├── common.conf           # 六组基线,所有角色共享
├── role-standalone.conf  # 单机(空,占位统一部署路径)
├── role-replica.conf     # 从库(replicaof 由脚本注入)
├── role-sentinel.conf    # 哨兵(独立进程的配置)
├── role-cluster.conf     # Cluster 实例(端口/announce 由脚本注入)
└── gen-node-conf.sh      # 四种角色的拼接生成器
```

## 参数的动态语义与漂移纪律(与 MySQL 相反的方向)

Redis 的 `CONFIG SET` 立即生效但**重启即失**;持久化靠 `CONFIG REWRITE`(只回写配置文件中已存在的键)。纪律:

- **基线一律进 `conf/common.conf`**(`CONFIG GET` 对照巡检,对应巡检 R02/R04 的检查方式);
- `CONFIG SET` 只用于应急调参(如实测中临时把 slowlog 阈值降到 1 采样后改回 10000);
- 长效变更走"改模板 → 重启生效"或 `CONFIG REWRITE` 后**把改动回抄进模板**,防止下次重建容器丢参数。

实测的临时调参样例(慢日志采样):

```bash
redis-cli CONFIG SET slowlog-log-slower-than 1   # 抓 1µs 以上
redis-cli KEYS '*'                               # 制造慢命令
redis-cli CONFIG SET slowlog-log-slower-than 10000   # 改回基线
redis-cli SLOWLOG GET 1                          # 采样结果(密码参数已 redacted)
```

## 应用与验证(实测输出)

```bash
./gen-node-conf.sh 10.10.12.118 standalone /root/redisconf
docker restart redis
docker exec -e REDISCLI_AUTH=Redis@2026 redis redis-cli CONFIG GET maxmemory maxmemory-policy appendonly
# 2147483648 / allkeys-lru / yes
```
