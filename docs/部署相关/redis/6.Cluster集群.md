# 6. Cluster 集群

> **实测状态**:✅ 已实测 —— Redis 8.0.6,三主三从六实例(跨 3 台 VM,每台 2 实例),2026-09-30。建群、槽分配、MOVED 重定向、杀主接管、旧主回归降级全流程验证。

## 什么时候用 Cluster

数据量或写入量超过单机内存上限、且业务能接受 Cluster 的约束(多 key 命令要求同槽、无跨槽事务、客户端要支持集群协议)。只是要高可用而不缺容量,主从+哨兵(第 5 篇)更轻。

## 拓扑

```
redis-1 10.10.12.118 : 7001(主→经历切换后为从) 7002(从→主)
redis-2 10.10.12.119 : 7003(主)                7004(从→主)
redis-3 10.10.12.127 : 7005(主)                7006(从)
```

实例端口 7001~7006,每实例另有总线端口 = 实例端口 + 10000(17001~17006)。生产建议 6 实例分摊到 6 台机器;本实验 3 台×2 验证协议行为。

## 部署

**每实例配置**(gen 注入端口与 announce 三件套):

```bash
./gen-node-conf.sh 10.10.12.118 cluster /root/redisconf 7001
mkdir -p /data/redis-cluster/7001
cp /root/redisconf/redis-7001.conf /data/redis-cluster/7001/
chown -R 999:999 /data/redis-cluster        # 实测必须:root 属主会让实例 crash 循环
#   报错:Can't open nodes.conf in order to acquire a lock: Permission denied
docker run -d --name redis-cluster-7001 --restart=always --net=host \
  -v /data/redis-cluster/7001:/data \
  -v /data/redis-cluster/7001/redis-7001.conf:/conf/redis.conf \
  redis:8.0 redis-server /conf/redis.conf
```

`--net=host` + `cluster-announce-ip/port/bus-port` 是 docker 下组群的关键(同 MySQL MGR 的 report_host 思路):不显式通告,节点间互相发现到的地址是错的。

**建群**:

```bash
redis-cli --cluster create \
  10.10.12.118:7001 10.10.12.118:7002 10.10.12.119:7003 \
  10.10.12.119:7004 10.10.12.127:7005 10.10.12.127:7006 \
  --cluster-replicas 1 -a Redis@2026 --no-auth-warning --cluster-yes
# 实测输出:[OK] All nodes agree about slots configuration.
#           >>> Check slots coverage...
#           [OK] All 16384 slots covered.

redis-cli -p 7001 CLUSTER INFO | grep -E "cluster_state|cluster_known_nodes|cluster_size"
# cluster_state:ok / cluster_known_nodes:6 / cluster_size:3
```

## 客户端语义实测

```bash
# 普通客户端:key 不在本节点返回重定向(实测原文):
redis-cli -p 7003 SET a v
# (error) MOVED 15495 10.10.12.127:7005

# 集群客户端(-c)自动跟随:
redis-cli -c -p 7003 SET user:1001 alice    # OK
redis-cli -c -p 7003 GET user:1001          # "alice"
redis-cli -p 7003 CLUSTER KEYSLOT user:1001 # (integer) 5712
```

多 key 命令要求同槽:`SET k1 v k2 v` 跨槽报 CROSSSLOT;用 hash tag `{user:1001}.name` / `{user:1001}.tags` 可强制同槽——业务建模时就定好。

## 杀主接管实测

`docker stop` 一个主实例:该分片从库被提升,期间该分片短暂不可写,其余分片不受影响;恢复后 cluster_size 回到 3,写入正常(实测 `SET user:3003 carol → OK / GET → carol`)。**被杀的主回归后自动降级为从库**(实测 `role:slave`)。节点超时判定 `cluster-node-timeout`(基线 15s)决定接管速度。

运维要点:

```bash
redis-cli --cluster check 10.10.12.119:7003 -a ...     # 槽覆盖与副本状态体检
redis-cli --cluster reshard ...                         # 在线迁槽(扩缩容/均衡)
redis-cli --cluster add-node / del-node ...             # 增删节点
```

## 已知坑(实测)

| 坑 | 现象 | 解 |
| --- | --- | --- |
| 实例目录 root 属主 | crash 循环,日志 "Can't open nodes.conf ... Permission denied" | `chown -R 999:999` 数据目录 |
| 不设 announce 三件套 | 节点互相发现错误地址,建群卡住 | role-cluster.conf + gen 注入 |
| 跨多机的实例从单机探活 | 某台 docker exec 查别的机器端口,永远空 | 命令发到实例所在机器执行 |
| 应用用普通客户端 | 一半写入 MOVED 报错 | 客户端启用集群模式(-c / 驱动 cluster 模式) |
