# 1. 安装部署-单机 docker

> **实测状态**:✅ 已实测 —— Redis 8.0.6(官方镜像 `redis:8.0`),宿主 Ubuntu 26.04 + docker 29.1.3,2026-09-30(redis-1 / 10.10.12.118)。

## 目标与前置

一台干净的 Linux 机器上跑起生产可用的单机 Redis:开机自启、健康检查、数据落宿主机、密码与 ACL 就位。前置:docker 已装并配好国内加速(daocloud 实测可用,见 MySQL 篇第 1 篇同节)。

## 第一步:目录与配置

```bash
mkdir -p /data/redis/{conf,data}
# 用 conf/ 模板生成单机配置(见第 2 篇参数说明)
./gen-node-conf.sh 10.10.12.118 standalone /root/redisconf
cp /root/redisconf/redis.conf /data/redis/conf/
```

**注意属主**:容器以 uid 999(redis)运行,`/data/redis/data` 若是手工 mkdir 的 bind 目录,必须 `chown -R 999:999 /data/redis/data`,否则 RDB/AOF 写入报权限错(实测 Cluster 场景直接 crash 循环,见第 6 篇)。

## 第二步:启动

```bash
docker run -d --name redis \
  --restart=always --stop-timeout=180 \
  --net=host \
  --health-cmd="redis-cli ping | grep -q PONG" \
  --health-interval=10s --health-timeout=5s --health-retries=6 \
  -e REDISCLI_AUTH=Redis@2026 \
  -v /data/redis/data:/data \
  -v /data/redis/conf:/conf \
  redis:8.0 redis-server /conf/redis.conf
```

逐行说明:

| 参数 | 作用 | 不设的后果 |
| --- | --- | --- |
| `--net=host` | 直接用宿主网络 | 单机也可用 `-p 6379:6379` 端口映射;但哨兵/Cluster 的自动发现依赖真实地址,host 网络省一整类坑(第 5/6 篇) |
| `--stop-timeout=180` | stop 时给保存 RDB 留时间 | 默认 10s 后 SIGKILL,大 RDB 没存完就被杀 |
| `--health-cmd` | 存活探针 | 编排/巡检看不到健康状态 |
| `-e REDISCLI_AUTH` | 容器内 redis-cli 自动带密码 | 无碍服务;但 docker exec 排障时**它会自动生效**(见第 3 篇的坑) |
| `-v /data/redis/data:/data` | 数据落宿主机(RDB/AOF 都在) | 容器删了数据就没了 |

## 第三步:验证(实测输出)

```bash
docker exec -e REDISCLI_AUTH=Redis@2026 redis redis-cli PING   # PONG
docker exec -e REDISCLI_AUTH=Redis@2026 redis redis-cli INFO server | grep redis_version
# redis_version:8.0.6
docker exec -e REDISCLI_AUTH=Redis@2026 redis redis-cli CONFIG GET maxmemory maxmemory-policy appendonly
# maxmemory → 2147483648(2GB);policy → allkeys-lru;appendonly → yes
docker exec -e REDISCLI_AUTH=Redis@2026 redis redis-cli SET hello:redis v1   # OK
docker inspect --format '{{.State.Health.Status}}' redis                     # healthy
```

远程验证(用同镜像当客户端,宿主机不装任何东西):

```bash
docker run --rm redis:8.0 redis-cli -h<Redis机器IP> -a 'Redis@2026' --no-auth-warning GET hello:redis
# 实测输出:v1
```

## 日常操作

```bash
docker logs -f redis          # 服务日志(stdout)
docker exec -it -e REDISCLI_AUTH=Redis@2026 redis redis-cli   # 交互式
docker restart redis
docker rm -f redis && docker run ...   # 数据在 /data/redis/data,随删随建
```

## 已知坑

1. **手工 bind 目录属主是 root**:容器内 redis(999)写不了 → `chown -R 999:999`;
2. **`docker exec` 继承容器环境变量**:带了 `-e REDISCLI_AUTH` 的容器,`docker exec redis redis-cli` 看似"免密"其实是环境变量在替你认证——验证认证问题时必须显式清空:`docker exec -e REDISCLI_AUTH= redis redis-cli ...`(实测不清空会误判);
3. 密码含特殊字符时 `-a 'pass'` 要整体引号,并配 `--no-auth-warning` 消除告警。
