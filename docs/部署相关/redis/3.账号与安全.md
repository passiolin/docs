# 3. 账号与安全(ACL)

## 认证模型

Redis 6.0+ 是完整 ACL 体系:`requirepass` 只是给 **default 用户**设密码的快捷方式。基线采用"default 供运维 + 按业务建受限用户"两层。

**未认证的实测报错**(排障时认得它):

```
AUTH failed: WRONGPASS invalid username-password pair or user is disabled.
NOAUTH Authentication required.
```

## 业务账号:ACL 最小权限(实测矩阵)

```bash
# 建账号:只能动 app:* 前缀的 key,只给 get/set/del,显式禁 FLUSHALL/CONFIG
redis-cli ACL SETUSER app on ">App@2026" "~app:*" +get +set +del -flushall -config
# 注意:修饰符要作为独立参数传入(实测整串引号包一起会报
#       "Unknown command or category name in ACL")

redis-cli ACL GETUSER app
# flags: on
# commands: -@all +get +set +del -flushall -config
# keys: ~app:*
```

实测权限边界(报错原文):

```bash
redis-cli --user app --pass App@2026 SET app:k1 v1     # OK
redis-cli --user app --pass App@2026 GET app:k1        # v1
redis-cli --user app --pass App@2026 SET other:k1 v1
# (error) NOPERM No permissions to access a key 'other:k1'
redis-cli --user app --pass App@2026 FLUSHALL
# (error) NOPERM User app has no permissions to run the 'flushall' command.
redis-cli --user app --pass App@2026 CONFIG GET maxmemory
# (error) NOPERM User app has no permissions to run the 'config|get' command.
```

三维度:命令(`+/-@category`)、key 模式(`~pattern`)、密码。巡检/监控只读账号给 `+info +ping +config|get +slowlog|get +cluster|info +cluster|slots +sentinel|master` 一类只读命令即可(联动巡检 R 系列)。

## docker 环境的认证陷阱(实测)

容器用 `-e REDISCLI_AUTH=Redis@2026` 启动后,**`docker exec redis redis-cli` 会继承这个环境变量自动认证**——看起来"免密",实则是环境变量在自动输密码。验证认证配置时必须显式清空:

```bash
docker exec -e REDISCLI_AUTH= redis redis-cli PING   # 此时才真实走认证路径
```

## 其他安全基线

- `protected-mode yes`(默认)+ requirepass:内网双保险;`bind 0.0.0.0` 仅在 host 网络与密码齐备时可用;
- 危险命令治理走 ACL(`-flushall -config -keys` 按账号收权),比老式 `rename-command` 可维护;
- 从库同样要 requirepass + masterauth(第 5 篇拓扑里哨兵连主也用它);
- ACL 持久化:`ACL SAVE` 写入 aclfile,或跟随 conf 模板;重启不丢。
