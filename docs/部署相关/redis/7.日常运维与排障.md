# 8. 日常运维与排障

## 日常操作速查

```bash
docker logs -f redis                                     # 服务日志
redis-cli INFO memory | grep -E "used_memory_human|maxmemory_human|mem_fragmentation_ratio"
redis-cli DBSIZE                                          # 键数
redis-cli SLOWLOG GET 5                                  # 慢命令(含微秒耗时,密码已 redacted)
redis-cli --bigkeys                                      # 只读采样找大 key(低峰执行)
redis-cli --latency                                      # 实时延迟采样(Ctrl-C 停)
```

## 大 key 与热 key 治理(R09/R12 联动)

- 发现:`redis-cli --bigkeys`(采样)或 `MEMORY USAGE <key>`(精确单个);
- 治理方向:拆分大 value(如大 hash 按分段)、改用短 TTL、异步删除(`UNLINK` 替 `DEL`);
- 预防:业务侧约定单 value 上限(如 <100KB),超限进慢日志告警。

## 排障字典(实测错误集)

| 报错/现象 | 根因 | 处置 |
| --- | --- | --- |
| `NOAUTH Authentication required.` | 未认证/密码错 | 认证排查;docker 环境注意 exec 继承 REDISCLI_AUTH 的假象(第 3 篇) |
| `WRONGPASS invalid username-password pair or user is disabled` | 密码错或用户被 ACL 禁用 | 核对 ACL 用户状态 `ACL GETUSER` |
| `NOPERM No permissions to access a key` | ACL key 模式不匹配 | 核对 `~pattern`;业务前缀与 ACL 对齐 |
| `NOPERM User app has no permissions to run 'flushall'` | 命令被 ACL 收权 | 属预期(最小权限);需要时按变更流程放权 |
| `READONLY You can't write against a read only replica.` | 向从库/被降级节点写 | 应用走哨兵寻主或集群 -c;排障时确认当前拓扑角色 |
| `(error) MOVED 15495 10.10.12.127:7005` | Cluster 下 key 不在本节点 | 客户端开集群模式;不是故障 |
| `MISCONF Redis is configured to persist RDB snapshots...` | BGSAVE 失败(fork 内存不足/磁盘满) | R07 P1:查 vm.overcommit_memory 与磁盘;修复后手动 BGSAVE 验证 |
| `LOADING Redis is loading the dataset in memory` | 重启加载 AOF/RDB 中 | 等待;加载时长与数据量成正比(大实例预热见第 4 篇) |
| `OOM command not allowed when used memory > 'maxmemory'` | noeviction 且写满 | R09 P0:清大 key/扩容;或按业务确认改淘汰策略 |
| master_link_status:down 持续 | 从库连不上主 | R11 P1:网络/主密码(masterauth)/主实例状态 |
| 哨兵 num-other-sentinels=0 | announce-ip 错,互不相见,**永不切换** | 部署验收必查(第 5 篇实测教训) |
| Cluster 实例 crash 循环 | 数据目录 root 属主,nodes.conf 写不了 | `chown -R 999:999`(第 6 篇实测) |
| 容器反复重启但数据"丢了" | dir 指到容器层而非挂载卷 | 核对 -v 与 `dir` 一致(第 1 篇布局) |
