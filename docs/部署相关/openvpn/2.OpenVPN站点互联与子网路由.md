# 2. OpenVPN 站点互联与子网路由

2026-11-27,在站点 VPN 服务端 `vpn-hub` 上打通 `office-client` 后面的 192.168.10.0/24:服务端是 kylemanna/openvpn 容器(host 网络),两个站点客户端各带自己的内网;`openvpn.conf` 里的 `route` 把后端子网指进 tun0,客户端 ccd 里的 `iroute` 决定包投给谁,两处都配完重启容器才通。文中域名、IP、客户端名均为示例值。

## 一、拓扑与配置形态

```mermaid
flowchart LR
    A["office-client<br/>办公核心路由 10.9.10.1<br/>10.9.10.0/24<br/>192.168.10.0/24"] -- "TCP 8443" --> H["vpn-hub 10.0.0.21<br/>openvpn 容器(host 网络)<br/>tun0 10.9.0.1"]
    B["lab-client<br/>10.9.12.1 侧"] -- "TCP 8443" --> H
    H -- "route + iroute<br/>10.9.10.0/24、192.168.10.0/24" --> A
    H -- "route + iroute<br/>10.9.12.0/24" --> B
```

| 组件 | 位置 | 关键点 |
| --- | --- | --- |
| 服务端 | `vpn-hub`(10.0.0.21) | `openvpn` 容器 host 网络,直接监听 TCP 8443;隧道 10.9.0.0/24(net30),服务端 10.9.0.1 |
| `office-client` | 办公核心路由 | 证书 CN 即 ccd 文件名;ccd 声明 10.9.10.0/24 与 192.168.10.0/24 在该客户端后面 |
| `lab-client` | 实验室 PVE/iKuai 侧 | ccd 声明 10.9.12.0/24 |
| 服务端内核路由 | `openvpn.conf` | `route` 指令,把后端子网指向 tun0 |
| 客户端专属路由 | `ccd/<CN>` | `iroute` 指令,决定网段投给哪个客户端 |

两个客户端都在办公站点内侧,从同一公网出口连入(示例中同为 198.51.100.20),服务端按证书 CN 区分。

示例参数:

| 项 | 值 |
| --- | --- |
| 宿主 | `vpn-hub`(10.0.0.21),Ubuntu 26.04 LTS |
| 域名 / 端口 | `vpn.example.com` / TCP 8443 |
| 镜像 | `kylemanna/openvpn:latest`(OpenVPN 2.4.9 + OpenSSL 1.1.1g) |
| 容器 | `openvpn`,`--privileged --restart=always`,host 网络,数据卷 `/data/openvpn` |
| 隧道 | 10.9.0.0/24,net30;服务端 10.9.0.1,客户端 10.9.0.6 / 10.9.0.10 |
| 客户端 | `office-client`、`lab-client`,nopass |

`openvpn.conf` 的服务端与路由段:

```conf
server 10.9.0.0 255.255.255.0
verb 3
keepalive 10 60
persist-key
persist-tun
proto tcp
port 8443
dev tun0
status /tmp/openvpn-status.log
user nobody
group nogroup

### Route Configurations Below
route 10.9.0.0 255.255.255.0
route 10.9.10.0 255.255.255.0
route 10.9.12.0 255.255.255.0
route 192.168.10.0 255.255.255.0
```

host 网络下容器内 `port` 就是对外端口,没有端口映射;[第 1 篇](1.OpenVPN服务端Docker部署与出口IP.md)是 `-p 8443:1194/tcp` + 容器内 `port 1194` 的形态,两种不要混。

ccd 按客户端证书 CN 命名:

```conf
# /data/openvpn/ccd/office-client
iroute 10.9.10.0 255.255.255.0
iroute 192.168.10.0 255.255.255.0
```

```conf
# /data/openvpn/ccd/lab-client
iroute 10.9.12.0 255.255.255.0
```

`openvpn.conf` 里没有 `client-config-dir`,是镜像的 `ovpn_run` 补的:`/etc/openvpn/ccd` 目录存在时自动追加 `--client-config-dir /etc/openvpn/ccd`,存在 `crl.pem` 时追加 `--crl-verify`。容器内 `ps` 可见完整参数:

```bash
docker exec openvpn ps -ef | head -2
# openvpn --config /etc/openvpn/openvpn.conf --client-config-dir /etc/openvpn/ccd --crl-verify /etc/openvpn/crl.pem
```

服务端不做 NAT:`iptables -t nat -S POSTROUTING` 里只有镜像默认网段(192.168.255.0/24、192.168.254.0/24)的 MASQUERADE,与实际隧道 10.9.0.0/24 不对应。回程靠客户端配置的 `redirect-gateway def1`(两个 .ovpn 都有),它把 0.0.0.0/1 与 128.0.0.0/1 指向隧道,覆盖 10.9.0.0/24。

## 二、route 与 iroute 的分工

- `route` 是服务端全局的:OpenVPN 启动时写内核路由表,`ip route` 里能看到 `192.168.10.0/24 via 10.9.0.2 dev tun0`。它只负责把包送进 tun0。
- `iroute` 是每客户端的:客户端连接时从 ccd 读入 OpenVPN 内部路由表,status 文件 ROUTING TABLE 里的 `192.168.10.0/24,office-client,...` 就是它。它决定包投给哪个客户端。
- 只有 `route`:包进了 tun0,OpenVPN 找不到归属客户端,丢弃;只有 `iroute`:内核没有对应路由,包到不了隧道。
- 生效时机:`route` 随服务端启动生效;`iroute` 只在客户端连接时读取,改完 ccd 必须 `docker restart openvpn` 或让客户端重连。

## 三、添加客户端后端子网的操作

本次把 192.168.10.0/24 挂到 `office-client` 后面,步骤:

1. 备份:

```bash
cd /data/openvpn
cp openvpn.conf openvpn.conf.bak-$(date +%s)
cp ccd/office-client ccd/office-client.bak-$(date +%s)
```

2. `openvpn.conf` 的 `### Route Configurations Below` 段尾追加:

```conf
route 192.168.10.0 255.255.255.0
```

3. `ccd/office-client` 追加 `iroute`:

```bash
echo 'iroute 192.168.10.0 255.255.255.0' >> ccd/office-client
cat ccd/office-client
```

```conf
iroute 10.9.10.0 255.255.255.0
iroute 192.168.10.0 255.255.255.0
```

4. 重启容器:

```bash
docker restart openvpn
```

重启会断开全部客户端(本例两个都自动重连),host 网络下 8443 监听短暂消失;本次操作时当前 SSH 会话也在重启瞬间被重置过一次,重连即可。挑低峰做。

5. 验证 status 与内核路由:

```bash
docker exec openvpn sed -n '/ROUTING TABLE/,/GLOBAL/p' /tmp/openvpn-status.log
ip route | grep tun0
```

ROUTING TABLE 出现 `192.168.10.0/24,office-client,...`,内核路由出现 `192.168.10.0/24 via 10.9.0.2 dev tun0`,两处就都生效了。

## 四、验证结果

重启后 status 的相关行(公网地址为示例值):

```
ROUTING TABLE
Virtual Address,Common Name,Real Address,Last Ref
192.168.10.0/24,office-client,198.51.100.20:33536,Fri Nov 27 02:56:04 2026
10.9.10.0/24,office-client,198.51.100.20:33536,Fri Nov 27 02:56:04 2026
10.9.12.0/24,lab-client,198.51.100.20:26180,Fri Nov 27 02:56:08 2026
192.168.10.114C,office-client,198.51.100.20:33536,Fri Nov 27 02:57:01 2026
10.9.0.6,office-client,198.51.100.20:33536,Fri Nov 27 02:57:01 2026
10.9.0.10,lab-client,198.51.100.20:26180,Fri Nov 27 02:56:59 2026
```

带 `C` 后缀的 `192.168.10.114C` 是 OpenVPN 从客户端流量里动态学到的源地址,不是 `iroute`;带 `/24` 的网段行才是 ccd 配置的结果。

服务器上 ping:

```bash
ping -c2 192.168.10.114   # 2 received, 0% packet loss, 平均约 7ms
ping -c2 192.168.10.200   # 2 received, 0% packet loss
ping -c2 192.168.10.1     # 100% packet loss
```

`192.168.10.1` 与 `10.9.10.1` 都不回 ICMP(设备侧过滤),不能据此判断不通;以终端主机和 status 为准。

## 五、坑表

| 坑 | 现象 | 处理 |
| --- | --- | --- |
| 只加 `route` 不加 `iroute` | 内核路由正常,ping 后端子网无回应 | ccd 里补 `iroute <网段> <掩码>`,重启容器 |
| 改完 ccd 不重启 | 已连接客户端仍按旧 iroute 转发,新网段不通 | `docker restart openvpn` 或让客户端重连 |
| ccd 文件名与证书 CN 不一致 | 客户端能连,但 iroute 不生效 | 文件名必须等于签发时的 CN |
| host 网络照搬端口映射 | 配置写 `port 1194` 或运行加 `-p 8443:1194`,客户端连 8443 失败 | host 网络时 `port` 直接写对外 8443 |
| 服务端未做 NAT | 隧道网段没有 MASQUERADE,回程依赖客户端路由 | 客户端带 `redirect-gateway def1`(本例两端都有),或手工把 10.9.0.0/24 指回隧道,否则只有去程 |
| 目标地址不回 ICMP | ping 网关全丢包,误判路由未生效 | 换一台回包的终端主机,或看 status 的 ROUTING TABLE |
| 重启影响 | 所有客户端断开重连;本次 SSH 会话也被重置一次 | 低峰操作,重启后确认客户端与网段行都回来 |
| 混淆学习地址与 iroute | status 里 `192.168.10.114C` 与 `/24` 行混在一起 | `C` 是动态学到的主机地址,只认 `<网段>,<CN>` 行 |

## 六、运维命令

```bash
docker exec openvpn cat /tmp/openvpn-status.log   # 客户端列表与路由表
docker logs --tail 50 openvpn                     # 连接、断开、证书错误
ip route | grep tun0                              # 服务端内核路由
docker restart openvpn                            # 改 openvpn.conf / ccd 后重载
```

备份:`tar czf /root/openvpn-data-$(date +%F).tgz -C /data openvpn`,内容含 CA 私钥与所有客户端私钥,权限 600,不进仓库。
