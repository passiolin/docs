# 4. 数据面:topic 与收发

> **实测状态**:✅ 已实测 —— Kafka 4.3.1,topic 创建/生产/消费/offset/lag 全链路(2026-10-01)。

## CLI 全路径 + timeout(本环境两条铁律)

镜像内 CLI 在 `/opt/kafka/bin/`;所有命令 `timeout 60` 包装(见第 2 篇坑 3)。

## topic 管理

```bash
B=10.10.12.128:9092
timeout 60 docker exec kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server $B \
  --create --topic device-events --partitions 3 --replication-factor 2
# Created topic device-events.

timeout 60 docker exec kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server $B \
  --describe --topic device-events
# 实测(注意 Leader 与副本分布):
# Partition: 0  Leader: 1  Replicas: 1,2  Isr: 1,2
# Partition: 1  Leader: 2  Replicas: 2,1  Isr: 2,1
# Partition: 2  Leader: 1  Replicas: 1,2  Isr: 1,2
```

建 topic 三要素:分区数(并行度/顺序性边界——**分区内有序,跨分区无序**)、RF(副本)、归属配置(retention 等,否则继承 broker 默认)。

## 生产与消费(docker 的 -i 陷阱)

```bash
# 生产:管道喂 stdin 时 docker exec 必须加 -i,否则输入被静默丢弃(实测踩坑,无任何报错):
for i in $(seq 1 10); do echo "device-$i:temp=$((20+i))"; done | \
  timeout 30 docker exec -i kafka /opt/kafka/bin/kafka-console-producer.sh \
  --bootstrap-server $B --topic device-events

# 消费(建消费组):
timeout 30 docker exec kafka /opt/kafka/bin/kafka-console-consumer.sh \
  --bootstrap-server $B --topic device-events --from-beginning \
  --max-messages 10 --timeout-ms 10000 --group lab-group
```

**实测观察**:无 key 消息按 sticky 分区器**整批落进同一分区**(10 条全在 partition 1)——需要打散必须显式带 key(同 key 保序进同分区,这正是按设备 key 分区的 IoT 用法)。

## offset 与 lag(巡检 K02 的命令面)

```bash
timeout 45 docker exec kafka /opt/kafka/bin/kafka-consumer-groups.sh \
  --bootstrap-server $B --describe --group lab-group
# 实测:
# GROUP      TOPIC           PARTITION CURRENT-OFFSET LOG-END-OFFSET LAG
# lab-group  device-events   0        0              0             0
# lab-group  device-events   1        10             10            0
# lab-group  device-events   2        0              0             0
```

LAG = LOG-END − CURRENT;**绝对值与增速要一起看**(巡检 K02:绝对 >100 万 P1,持续增长 >1h P0)。

## 已知坑(实测)

| 坑 | 现象 | 解 |
| --- | --- | --- |
| 生产管道丢数据 | producer 不报错,offset 不涨 | `docker exec -i` |
| console-consumer 无 stdout | 本镜像消费确认以 offset/lag 为准更可靠 | 用 `_count` 思路:groups describe 对账 |
| CLI 挂住不动 | 高负载 JVM 慢启动 | timeout 包装 + 逐 broker 核验 |
