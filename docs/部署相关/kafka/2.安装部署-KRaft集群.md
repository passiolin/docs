# 2. 安装部署-KRaft 集群

> **实测状态**:✅ 已实测 —— Kafka 4.3.1 KRaft 合并模式(broker+controller 同进程),`--net=host`,2026-10-01。报错与启动日志均实录。

## 拓扑与端口

```
kafka-1 10.10.12.128  node.id=1(broker+controller)
kafka-2 10.10.12.129  node.id=2
kafka-3 10.10.12.130  node.id=3(配置同型)
端口:9092 客户端;9093 controller 仲裁(节点间)
```

KRaft 合并模式 = 每台一个进程,既是 broker 又是 controller;3 台构成元数据仲裁(2/3 多数派)。

## 部署

配置 = 共享 env(`kafka-common.env`)+ 节点 env(gen 生成),docker `--env-file` 两次挂入:

```bash
cd conf/
./gen-node-env.sh 10.10.12.128 1 /root/     # 产出 kafka-node.env
mkdir -p /data/kafka && chown -R 1000:1000 /data/kafka   # 实测必须:容器 uid 1000
docker run -d --name kafka --restart=always --net=host \
  --env-file /root/kafka-common.env --env-file /root/kafka-node.env \
  -e CLUSTER_ID=5Yk94ZjURJOVSqLZkUqzNQ \
  -v /data/kafka:/var/lib/kafka/data \
  apache/kafka:4.3.1
```

要点(每条都实测过):

| 项 | 说明 |
| --- | --- |
| `CLUSTER_ID` | 全集群同一个 base64 UUID;首启自动 format 元数据目录 |
| `--env-file` × 2 | common 三台一致;node 只有 NODE_ID + ADVERTISED_LISTENERS |
| **uid 1000** | `/data/kafka` root 属主时 crash 循环:`AccessDeniedException: /var/lib/kafka/data/bootstrap.checkpoint.tmp` |
| advertised 必须真实 IP | 客户端与节点互访都靠它;写错=能连上但元数据里全是错误地址 |

## 验证(实测输出)

```bash
# 进程起没起(日志):
docker logs kafka | grep "Kafka Server started"
# [KafkaRaftServer nodeId=1] Kafka Server started

# controller 仲裁:
timeout 60 docker exec kafka /opt/kafka/bin/kafka-metadata-quorum.sh \
  --bootstrap-server 10.10.12.128:9092 describe --status
# LeaderId: 2 / LeaderEpoch: 1 / HighWatermark: 731
# CurrentVoters: [{id:1,...CONTROLLER://10.10.12.128:9093}, {id:2...}, {id:3...}]

# broker 清单:
timeout 60 docker exec kafka /opt/kafka/bin/kafka-broker-api-versions.sh \
  --bootstrap-server 10.10.12.128:9092 | grep "^10.10"
```

## 已知坑(实测)

1. **CLI 不在 PATH**:镜像内脚本在 `/opt/kafka/bin/`,docker exec 必须写全路径;
2. **数据目录属主**(见上表);
3. **CLI 一律 timeout 包装**(巡检纪律的出处:JVM 启动在高负载下可能 20s+,不包装会把慢启动误报成 broker 挂了;实测 `kafka-consumer-groups --describe` 就能挂住不动);
4. KRaft 没有 ZK 的 2181——老文档/老监控的 ZK 探活项要退役。
