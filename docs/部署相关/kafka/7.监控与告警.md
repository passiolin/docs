# 7. 监控与告警

> **实测状态**:✅ 已实测 —— kafka_exporter **v1.8.0**(`danielqsj/kafka-exporter`),2026-10-01,实测 385 个 kafka_ 指标,指标名与数值摘自抓取。

## 分工:巡检(命令面)与监控(指标面)用同一套 K 编号

| 巡检项 | 命令面 | 指标面(实测指标名) | 阈值(同源巡检) |
| --- | --- | --- | --- |
| K01 broker 存活 | broker-api-versions | `kafka_brokers` | < 预期台数 P0 |
| K02 消费 lag | consumer-groups describe | `kafka_consumergroup_lag{...}` / `kafka_consumergroup_lag_sum` | >100 万 P1;持续增 P0 |
| K03 消费组活跃 | groups describe | `kafka_consumergroup_members` | 关键组无成员 P1 |
| K08 消息速率 | — | `rate(kafka_topic_partition_current_offset[5m])` | 突降 0 P1 |
| K10 分区分布 | topics describe | `count by (leader) (...)`(leader 分布) | 失衡 P2 |

实测指标样例:

```
kafka_brokers 2
kafka_consumergroup_lag{consumergroup="lab-group",partition="0",topic="device-events"} 1
kafka_consumergroup_lag_sum{consumergroup="lab-group",topic="device-events"} 1
kafka_topic_partition_current_offset{partition="0",topic="__consumer_offsets"} 4
```

(样例里 lag=1 正是杀 broker 期间生产、消费组未跟上的那条——指标面如实反映故障窗口,与命令面对账一致。)

## exporter 部署(实测)

```bash
docker run -d --name kafka-exporter --restart=always --net=host \
  danielqsj/kafka-exporter:v1.8.0 --kafka.server=10.10.12.128:9092
# 注意:v1.8 是命令行参数(--kafka.server),不是 KAFKA_URI 环境变量(实测踩坑)
# 验证:curl -s localhost:9308/metrics | grep -c '^kafka_'  → 385
```

- 一台 exporter 指向任一 broker 即可看到全集群(元数据自发现);多集群则按集群各部署一组;
- broker 端 JVM/请求延迟类指标(K09)exporter 不覆盖,需要 JMX exporter 挂 broker——本文未实测,需要时先实验机验证。

## 告警规则示例(与巡检阈值对齐)

```yaml
groups:
- name: kafka
  rules:
  - alert: KafkaBrokersLost                  # K01 / P0
    expr: kafka_brokers < 3
    for: 1m
  - alert: KafkaConsumerLagHigh              # K02 / P1
    expr: kafka_consumergroup_lag_sum > 1000000
    for: 10m
  - alert: KafkaConsumerLagGrowing           # K02 / P0
    expr: deriv(kafka_consumergroup_lag_sum[1h]) > 0
    for: 1h
```
