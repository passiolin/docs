# 4. 容灾实测

> **实测状态**:✅ 已实测 —— Kafka 4.3.1(2 broker 在线形态),2026-10-01。杀 broker 全流程:Leader 迁移、ISR 收缩、单副本可写、回归自动补齐。

## 杀 broker 实测时间线

`docker stop` kafka-1(128,持有 2 个分区的 Leader):

**停后 12 秒**,从幸存 broker(129)视角:

```
Partition: 0  Leader: 2  Replicas: 1,2  Isr: 2     ← Leader 已迁移,ISR 从 [1,2] 收缩为 [2]
Partition: 1  Leader: 2  Replicas: 2,1  Isr: 2     ← (原本 Leader 就在 2)
Partition: 2  Leader: 2  Replicas: 1,2  Isr: 2
```

**期间继续生产**:成功(RF=2 但 min.insync.replicas=1,单副本仍满足写入条件)——3 节点基线(RF=2/minISR=1)在单 broker 故障时**读写双可用**;若基线是 minISR=2,此刻写入会报 NotEnoughReplicas,这是可用性/一致性的显式取舍点。

**128 回归**:副本自动追平(ISR 回到 [1,2]),Leader 是否回迁由 broker 设置决定(默认不抢)。

## KRaft 仲裁容灾

controller 仲裁 3 选 2:杀 1 台,元数据多数派仍在,集群自治;**同时挂 2 台 = 元数据不可用,全集群停摆**——三节点的容错边界就是 1 台。巡检 K06(quorum describe --status 的 LeaderId/CurrentVoters)是这一层的健康口径。

## 运维动作速查

```bash
# 优先选举(preferred leader 回迁,低峰执行):
kafka-leader-election.sh --bootstrap-server $B --election-type preferred --all-topic-partitions
# 分区重分配(扩容后均衡,K10):
kafka-reassign-partitions.sh --bootstrap-server $B --reassignment-json-file plan.json --execute
# 下线节点前:先把它的分区迁走再停
```
