# 0. 安装部署-单机

> **实测状态**:✅ 已实测 —— Doris 2.1.7 单机 = 同机 1 FE + 1 BE(jmqtt-2 / 10.10.12.138,8G 与 jmqtt-broker 混部),2026-10-01。FE Master、BE 注册、RF=1 建表、Stream Load、查询全验证。

## 什么时候用单机

开发测试、小规模分析(GB 级)。单机 = 无副本无容错;协议面与集群完全一致,**加 BE/FE 扩成集群是演进**(第 4 篇扩容流程)。

## 宿主前置(与集群篇相同的三件套)

```bash
sysctl -w vm.max_map_count=2000000 && echo "vm.max_map_count=2000000" >> /etc/sysctl.conf
swapoff -a && sed -i '/swap/s/^/#/' /etc/fstab
# BE 容器 --ulimit nofile=655350:655350
```

## 部署(实测命令)

```bash
mkdir -p /data/doris    # ★ 先建父目录!docker cp 不创建父级(实测静默失败的根因)
# FE(FE_ID=1,选民只有自己):
docker create --name feconf apache/doris:fe-2.1.7
docker cp feconf:/opt/apache-doris/fe/conf /data/doris/fe-conf-tmp; docker rm feconf
mv /data/doris/fe-conf-tmp /data/doris/fe-conf2
test -f /data/doris/fe-conf2/fe.conf || echo "提取失败!"    # ★ 校验
sed -i 's|^# priority_networks.*|priority_networks = 10.10.12.0/24|' /data/doris/fe-conf2/fe.conf
mkdir -p /data/doris/fe/{doris-meta,log}
docker run -d --name doris-fe --restart=always --net=host \
  -e FE_SERVERS="fe1:<本机IP>:9010" -e FE_ID=1 \
  -v /data/doris/fe-conf2:/opt/apache-doris/fe/conf \
  -v /data/doris/fe/doris-meta:/opt/apache-doris/fe/doris-meta \
  -v /data/doris/fe/log:/opt/apache-doris/fe/log \
  apache/doris:fe-2.1.7
# 等 9030 监听(FE JVM 要 2~3 分钟)再起 BE

# BE(同机,mem_limit 按混部情况压低):
docker create --name beconf apache/doris:be-2.1.7
docker cp beconf:/opt/apache-doris/be/conf /data/doris/be-conf-tmp; docker rm beconf
mv /data/doris/be-conf-tmp /data/doris/be-conf2
printf '\npriority_networks = 10.10.12.0/24\nmem_limit = 30%%\n' >> /data/doris/be-conf2/be.conf
mkdir -p /data/doris/be/{storage,log}
docker run -d --name doris-be --restart=always --net=host \
  --ulimit nofile=655350:655350 \
  -e FE_SERVERS="fe1:<本机IP>:9010" \
  -e BE_ADDR=<本机IP>:9050 \
  -v /data/doris/be-conf2:/opt/apache-doris/be/conf \
  -v /data/doris/be/storage:/opt/apache-doris/be/storage \
  -v /data/doris/be/log:/opt/apache-doris/be/log \
  apache/doris:be-2.1.7
```

## 验证(实测输出)

```bash
docker run --rm mysql:8.4 mysql -h<本机IP> -P9030 -uroot -e "SHOW FRONTENDS\G SHOW BACKENDS\G"
# IsMaster: true / Alive: true;BE Alive: true

# RF=1 建表(★ 单机必须,默认 RF=3 会报 "replication num ... available backend num is 0"):
CREATE TABLE demo.events(id INT NOT NULL, v INT) DUPLICATE KEY(id)
  DISTRIBUTED BY HASH(id) BUCKETS 2 PROPERTIES("replication_num"="1");

# 导入(★ 小文件必须显式 100-continue,否则 FAILED "There is no 100-continue header"):
curl --location-trusted -u root: -H "column_separator:," -H "expect:100-continue" \
  -T /tmp/s.csv -X PUT "http://<本机IP>:8030/api/demo/events/_stream_load"
# "Status":"Success" / "NumberLoadedRows":3
SELECT COUNT(*), SUM(v) FROM demo.events;   -- 3 / 60
```

## 已知坑(实测)

| 坑 | 现象 | 解 |
| --- | --- | --- |
| docker cp 目标父目录不存在 | **静默失败**→ fe.conf 缺失 → FE restart 循环 `No such file or directory` | `mkdir -p /data/doris` 先行 + `test -f` 校验 |
| RF 没降到 1 | 建表报 replication num > available backends | 建表显式 `replication_num=1` |
| 小文件 stream load 失败 | `There is no 100-continue header` | curl 显式 `-H "expect:100-continue"`(集群篇实测命令一直带着,单机篇首次踩裸奔的坑) |
| BE 先于 FE 起来 | Alive 长时间 false | BE 心跳会自愈;规范是等 9030 再起 BE |
| FE 启动 2~3 分钟 | 误判失败 | 等 9030,见集群篇同款纪律 |
