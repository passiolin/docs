# 3. 数据导入与查询

> **实测状态**:✅ 已实测 —— Doris 2.1.7,10 万行 Stream Load 两次(冷缓存 16s / 热缓存 3.9s),2026-09-30。

## 建表(实测 DDL)

```sql
CREATE DATABASE demo;
CREATE TABLE demo.events(
  id      INT NOT NULL,
  user_id INT,
  event   VARCHAR(32),
  ts      DATETIME
) DUPLICATE KEY(id)
DISTRIBUTED BY HASH(id) BUCKETS 4
PROPERTIES("replication_num" = "2");
```

建模三件套:数据模型(DUPLICATE 明细 / AGGREGATE 聚合 / UNIQUE 主键)、分桶(HASH(高频过滤列),桶数 ≈ BE 数 × 1~2 起步)、副本数(实验 2 / 生产 3)。**没有 BE Alive 时建表直接报** `System has no available disk capacity or no available BE nodes`(实测)——先查 SHOW BACKENDS 再排 DDL 问题。

## Stream Load(实测)

```bash
# 造数据
awk 'BEGIN{for(i=1;i<=100000;i++) print i","i%1000",click,2026-09-30 12:00:00"}' > /tmp/events.csv

# 导入:走 FE 8030,自动重定向到 BE 8040(--location-trusted 必须)
curl --location-trusted -u root: -H "column_separator:," \
  -T /tmp/events.csv -X PUT \
  "http://10.10.12.124:8030/api/demo/events/_stream_load"
```

实测输出:

```
"Status": "Success",
"NumberLoadedRows": 100000,
"LoadTimeMs": 3947,        ← 第二次(热)3.9s;首次冷缓存 16s
```

**实测坑:默认列分隔符是 TAB**——CSV 逗号文件不带 `column_separator:,` 时全部行报错 `actual column number ... is less than schema column number`,错误详情要看返回体里的 ErrorURL(浏览器/curl 打开即见逐行原因)。

查询验证(MySQL 协议):

```sql
SELECT COUNT(*), COUNT(DISTINCT user_id) FROM demo.events;   -- 100000 / 1000
SELECT user_id, COUNT(*) c FROM demo.events GROUP BY user_id ORDER BY c DESC LIMIT 3;
```

## 导入方式选型

| 方式 | 场景 | 备注 |
| --- | --- | --- |
| Stream Load(HTTP) | 文件/流式批量,≤10GB | 本文实测;程序侧走此路最简单 |
| INSERT INTO VALUES | 少量手造数据 | 别当批量通道 |
| Broker Load / S3 | 对象存储大规模 | 走我们的对象存储体系,未实测 |
| routine load | Kafka 消费 | 未实测;IoT 链路候选 |
