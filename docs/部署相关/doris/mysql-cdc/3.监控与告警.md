# 3. 监控与告警

同步链路的监控分两层:**链路活不活**(Flink 作业、checkpoint、MGR、Router、Doris BE)和**数据到没到**(端到端心跳延迟、binlog 位点/体积)。只看 Flink 的 `RUNNING` 不够——作业活着但卡在某个大事务、Doris 在拒绝写入、binlog 被清理,都需要不同的信号。

## 监控面

| 层 | 指标 | 采集方式 | 说明 |
| --- | --- | --- | --- |
| Flink 作业 | 状态、checkpoint 年龄、失败次数、source fetch/emit lag | Flink REST 8081 | 作业重启/卡住的第一信号 |
| 端到端 | 心跳延迟(MySQL NOW - Doris MAX(ts)) | exporter 查 MySQL + Doris | 最贴近“数据到没到” |
| MySQL binlog | 总量、文件数、当前位点、保留秒数 | `SHOW BINARY LOGS` / `SHOW BINARY LOG STATUS` | 判断同步是否落后、保留是否够 |
| MGR | 成员 ONLINE/角色/应用队列 | `performance_schema.replication_group_members` 等 | 主库切换、成员失联 |
| Router | 6446/6447 TCP 可达 | exporter socket 探活 | 访问层单点 |
| Doris | FE/BE Alive、BE tablet 数、BE 导入/磁盘指标 | `SHOW FRONTENDS/BACKENDS` + `/metrics` | 目标端健康 |
| 主机 | CPU/内存/磁盘/网络 | node_exporter | 兜底 |

## 心跳:端到端延迟的探针

心跳表只有一行:

```sql
CREATE TABLE app_db.sync_heartbeat (
  id TINYINT PRIMARY KEY,
  ts DATETIME(3) NOT NULL,
  seq BIGINT UNSIGNED NOT NULL
);
```

单机场景用 MySQL EVENT 每秒更新:

```sql
CREATE EVENT app_db.ev_heartbeat ON SCHEDULE EVERY 1 SECOND
  DO UPDATE app_db.sync_heartbeat SET ts=NOW(3), seq=seq+1 WHERE id=1;
```

MGR 场景**不要用 EVENT**。EVENT 在从库上是 `REPLICA_SIDE_DISABLED`;124 升主后,事件不会自动启用,心跳停在被切换前的时刻。本次实测到这一点后,改为 monitor 机(131)上的外部 writer,经 Router 6446 每秒更新:

```bash
# /opt/doris-sync-exporter/mgr_heartbeat.sh
while true; do
  MYSQL_PWD="$APP_PASSWORD" mysql --protocol=tcp -h10.10.12.125 -P6446 -uapp -N -B \
    -e "UPDATE app_mgr.sync_heartbeat SET ts=NOW(3), seq=seq+1 WHERE id=1;" \
    >/dev/null 2>&1
  sleep 1
done
```

延迟口径:

```text
lag = MySQL NOW(3) - (SELECT MAX(ts) FROM <db>.sync_heartbeat 在 Doris 里的值)
```

两端查询在 exporter 的同一轮刷新里完成,MySQL 侧用 `NOW(3)` 和心跳 `ts` 同一个时钟;Doris 侧只读取已同步的值,不参与时钟比较。exporter 另外暴露一个 `..._lag_doris_seconds`(Doris 自己的 `NOW(3)` 减心跳值),用于交叉检查两端时钟是否漂移。

外部 writer 的代价是:它自己挂了,心跳延迟会涨,告警会响。这是有意的——监控探针本身也要被监控。单机场景保留 EVENT,少一个进程;MGR 场景用 writer,换来跨主库切换的连续性。

## Exporter

代码见 [conf/exporter/sync_exporter.py](conf/exporter/sync_exporter.py),部署在 131,Python 标准库 + `mysql` 客户端,无第三方依赖。它每 5 秒刷新一次,HTTP 暴露 `:9273/metrics`(Prometheus 格式)和 `/status`(JSON,含采集错误)。

| 指标 | 含义 | 正常范围 |
| --- | --- | --- |
| `mysql_doris_flink_job_state{pipeline}` | 0 down / 1 running / 2 restarting / 3 failed | 1 |
| `mysql_doris_flink_checkpoint_age_seconds` | 最近一次完成 checkpoint 距今秒数 | < 10s(3s 间隔) |
| `mysql_doris_flink_checkpoint_failed_total` | 失败 checkpoint 计数 | 不增长 |
| `mysql_doris_source_fetch_lag_seconds` | Flink source `currentFetchEventTimeLag` | 0–2s,-1 表示空闲/未知 |
| `mysql_doris_source_emit_lag_seconds` | Flink source `currentEmitEventTimeLag` | 0–2s |
| `mysql_doris_heartbeat_lag_seconds{pipeline,db}` | 端到端心跳延迟 | < 2s |
| `mysql_doris_heartbeat_lag_doris_seconds{pipeline,target_db}` | 纯 Doris 时钟口径,交叉检查 | < 5s |
| `mysql_doris_binlog_total_bytes{instance}` | binlog 文件总大小 | 按容量设阈值 |
| `mysql_doris_binlog_file_count` | binlog 文件数 | 观察增长 |
| `mysql_doris_binlog_position{file}` | 当前 binlog 位点 | 观察推进 |
| `mysql_doris_binlog_retention_seconds` | `binlog_expire_logs_seconds` | ≥ 同步故障恢复窗口 |
| `mysql_doris_mgr_member_online{member}` | MGR 成员 ONLINE | 全部 1 |
| `mysql_doris_mgr_member_primary{member}` | 是否主库 | 只有一个 1 |
| `mysql_doris_mgr_transactions_in_queue{member}` | 成员应用队列长度 | 0 或接近 0 |
| `mysql_doris_router_up{endpoint}` | 6446/6447 TCP 可达 | 1 |
| `mysql_doris_doris_fe_alive` / `..._be_alive` | Doris FE/BE Alive | 全部 1 |
| `mysql_doris_flink_api_up` | exporter 到 Flink REST 的可达性 | 1 |
| `mysql_doris_exporter_last_refresh_timestamp` | 最近刷新时间 | 距今 < 60s |

exporter 的密码从 `/etc/doris-sync-exporter.env` 读(600 权限),不写死进脚本:

```bash
CDC_PASSWORD=<CDC_PASSWORD>
MGR_ADMIN_PASSWORD=<MGR_ADMIN_PASSWORD>
APP_PASSWORD=<APP_PASSWORD>
```

systemd unit 见 [conf/systemd/doris-sync-exporter.service](conf/systemd/doris-sync-exporter.service) 与 [mgr-heartbeat.service](conf/systemd/mgr-heartbeat.service)。

Flink 的 `currentFetchEventTimeLag` 在 REST 的指标列表里 `value` 是空的,必须用 `.../metrics?get=0.Source__...currentFetchEventTimeLag` 取值;exporter 先列 metric id,再按 id 批量 `get`,取所有 subtask 的非负最大值。这个细节不处理会永远拿到 -1。

## Prometheus

抓取配置见 [conf/prometheus/prometheus.yml](conf/prometheus/prometheus.yml):15s 一次,目标包括 exporter、11 台 node_exporter(基线 10 台 + 132)、Doris FE(8030/metrics)、3 个 BE(8040/metrics)。Doris 4.0.8 的 BE 指标里有少量同名同时间戳的重复序列,Prometheus 会打 `Error on ingesting samples with different value but same timestamp` 并丢弃重复项,不影响 FE/BE 存活与导入指标的采集。

告警规则见 [conf/prometheus/doris-sync-rules.yml](conf/prometheus/doris-sync-rules.yml),10 条:

| 告警 | 表达式 | for | 级别 |
| --- | --- | --- | --- |
| PipelineDown | `flink_job_state != 1` | 1m | critical |
| HeartbeatLagHigh | `heartbeat_lag_seconds > 30` | 2m | warning |
| HeartbeatStalled | `heartbeat_lag_seconds > 300` | 2m | critical |
| CheckpointStale | `checkpoint_age_seconds > 120` | 3m | warning |
| CheckpointFailures | `changes(checkpoint_failed_total[10m]) > 0` | 1m | warning |
| BinlogTooLarge | `binlog_total_bytes > 5GiB` | 10m | warning |
| MgrMemberNotOnline | `mgr_member_online == 0` | 1m | critical |
| RouterDown | `router_up == 0` | 1m | critical |
| DorisBeDown | `doris_be_alive == 0` | 1m | critical |
| ExporterStale | `time() - last_refresh > 60` | 1m | warning |

阈值是实验起步值,生产按业务容忍度调。没有接 Alertmanager;Prometheus 的 `/alerts` 页面能看到 firing,接飞书/邮件时在 `alerting` 段加 webhook 即可。本次 10 条规则在稳定期全部 `inactive`。

## 告警处置

| 告警 | 先看什么 | 处置 |
| --- | --- | --- |
| PipelineDown | `flink list`、`/jobs/<id>/exceptions`、TM 日志 | MySQL 挂 → 先恢复源;binlog 被清 → 重提作业做全量;OOM → 调 TM 内存/并发 |
| HeartbeatLagHigh | 作业状态、source lag、binlog 位点、Doris BE | 大事务/批量写入会短时抬高;持续 5 分钟看 Doris Stream Load 与 BE 磁盘 |
| HeartbeatStalled | 心跳 writer/EVENT、Router、Flink | MGR 先看 writer 与 6446;单机看 EVENT 是否被禁用;Flink 卡住看 checkpoint |
| CheckpointStale | Flink JM/TM 日志、checkpoint 目录、Doris sink | Doris 拒绝写入/网络超时会拖住 checkpoint;先修 sink,再看状态后端 |
| CheckpointFailures | `.../checkpoints` 的失败原因 | 磁盘满、TM 丢失、Doris 超时;按原因处理,不要盲目重启 |
| BinlogTooLarge | `SHOW BINARY LOGS`、同步延迟、保留期 | 同步追不上先修同步;磁盘紧张再评估缩短保留(会缩小恢复窗口) |
| MgrMemberNotOnline | `replication_group_members`、成员 error log | 单成员失联看网络/磁盘;多数派丢失先恢复多数派,不要贸然 bootstrap |
| RouterDown | `systemctl status mysqlrouter`、6446/6447 | 重启 Router;元数据损坏用 `--bootstrap` 重新生成(注意凭据) |
| DorisBeDown | `SHOW BACKENDS`、BE error log、磁盘、`vm.max_map_count` | 先修 BE;副本数 3 时单 BE 故障查询仍可用,但导入会降级 |
| ExporterStale | `systemctl status doris-sync-exporter`、`curl :9273/status` | 看 errors 字段;MySQL 客户端路径/密码/网络是常见原因 |
