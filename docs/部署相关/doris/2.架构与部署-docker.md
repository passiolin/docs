# 1. 架构与部署-docker

> **实测状态**:✅ 已实测 —— Doris 2.1.7,3 FE + 3 BE(doris-1/2/3,`--net=host`),2026-09-30。所有宿主前置与报错均为实录。

## 架构一分钟

- **FE(前端)**:元数据存储(BDBJE 多数派复制)、SQL 解析与规划、MySQL 协议接入(9030)。奇数个(1/3/5)才有容错意义——**2 FE 是伪高可用**(第 4 篇实测)。
- **BE(后端)**:数据存储(tablet 分片多副本)、MPP 执行。副本数在建表时指定(实验基线 2,生产 3)。
- 端口:FE 8030(http)/9010(edit log)/9030(mysql);BE 8040(http/stream load)/9050(心跳)/9060(thrift)/8060(brpc)。

## 宿主机前置(三个,全踩过,缺一 BE 起不来)

```bash
# ① 内核:虚拟内存映射数(BE 启动硬检查,实测默认 65530 直接拒启)
sysctl -w vm.max_map_count=2000000
echo "vm.max_map_count=2000000" >> /etc/sysctl.conf
# ② 关 swap(BE 启动硬检查,实测报 "Please disable swap memory before installation")
swapoff -a && sed -i "/swap/s/^/#/" /etc/fstab
# ③ BE 容器文件句柄(实测默认不足,报 "greater than 60000")
#    在 docker run 上加:--ulimit nofile=655350:655350
```

## 配置文件:从镜像提取 + 改 priority_networks(必做)

`--net=host` 下宿主机有 docker0(172.17.0.1),**不显式设置 priority_networks 时 FE 会绑到 172.17.0.1**(实测踩坑,FE 元数据全记错地址)。env `FE_PRIORITY_NETWORKS` 在本镜像实测不落盘,正确做法是改 conf 挂载:

```bash
# FE conf 提取(每台一次;注意校验 fe.conf 真实存在——实测 docker cp 静默失败过)
docker create --name feconf apache/doris:fe-2.1.7
docker cp feconf:/opt/apache-doris/fe/conf /data/doris/fe-conf-tmp
docker rm feconf && mv /data/doris/fe-conf-tmp /data/doris/fe-conf2
test -f /data/doris/fe-conf2/fe.conf || echo "提取失败!"
sed -i 's|^# priority_networks.*|priority_networks = 10.10.12.0/24|' /data/doris/fe-conf2/fe.conf

# BE conf 提取 + 实验机调优(8G VM 与 FE 共存)
docker create --name beconf apache/doris:be-2.1.7
docker cp beconf:/opt/apache-doris/be/conf /data/doris/be-conf-tmp
docker rm beconf && mv /data/doris/be-conf-tmp /data/doris/be-conf2
cat >> /data/doris/be-conf2/be.conf <<'EOF'
priority_networks = 10.10.12.0/24
mem_limit = 50%
EOF
```

## 建群:先 FE1,后 FE2/FE3,再 BE

**entrypoint 必填 env 组合是 `FE_SERVERS` + `FE_ID`**(实测只给 FE_SERVERS 会死循环报 `[ERROR] [Entrypoint]: EOF`):

```bash
# FE1(首节点,FE_ID=1)
docker run -d --name doris-fe --restart=always --net=host \
  -e FE_SERVERS="fe1:10.10.12.124:9010,fe2:10.10.12.126:9010,fe3:10.10.12.125:9010" \
  -e FE_ID=1 \
  -v /data/doris/fe-conf2:/opt/apache-doris/fe/conf \
  -v /data/doris/fe/doris-meta:/opt/apache-doris/fe/doris-meta \
  -v /data/doris/fe/log:/opt/apache-doris/fe/log \
  apache/doris:fe-2.1.7
# FE 启动要 2~3 分钟(JVM),等 9030 监听再继续:
while ! ss -tln | grep -q :9030; do sleep 5; done

# FE2/FE3:同命令,FE_ID=2/3(容器 entrypoint 会向 master 注册)

# BE(每台):注意 --ulimit
docker run -d --name doris-be --restart=always --net=host \
  --ulimit nofile=655350:655350 \
  -e FE_SERVERS="fe1:10.10.12.124:9010" \
  -e BE_ADDR=<本机IP>:9050 \
  -v /data/doris/be-conf2:/opt/apache-doris/be/conf \
  -v /data/doris/be/storage:/opt/apache-doris/be/storage \
  -v /data/doris/be/log:/opt/apache-doris/be/log \
  apache/doris:be-2.1.7
```

## 验证(MySQL 协议,root 默认无密码)

```bash
docker run --rm mysql:8.4 mysql -h10.10.12.124 -P9030 -uroot -e "SHOW FRONTENDS\G SHOW BACKENDS\G"
# 实测终态(3FE+3BE 全绿):
#   FE: 10.10.12.124 IsMaster:true Alive:true;125/126 FOLLOWER Alive:true
#   BE: 三台 Alive:true,TabletNum > 0(系统 tablet 已分布)
```

客户端直接用 mysql 客户端/驱动(协议兼容),不必装 Doris 专用工具。

## 已知坑(实测)

| 坑 | 现象 | 解 |
| --- | --- | --- |
| 缺 FE_ID | entrypoint 死循环 `[ERROR] EOF` | FE_SERVERS + FE_ID 成对给 |
| priority_networks 没写进 conf | FE 绑 172.17.0.1(docker0) | 挂载改好的 conf(本文做法) |
| max_map_count / swap / ulimit | BE 分别拒启,报错原文见"宿主前置" | 三件套一次配齐 |
| conf 提取静默失败 | start_fe.sh 报 fe.conf No such file | `test -f` 校验(实测 125 栽过) |
| FE 换元数据重来,BE 旧 storage 拒入 | BE 心跳不注册(cluster_id 不匹配) | 同步清 BE storage 重建 |
| 首启 3 分钟没端口 | 以为挂了反复重启反而更慢 | FE JVM 就是慢,等 9030 |
