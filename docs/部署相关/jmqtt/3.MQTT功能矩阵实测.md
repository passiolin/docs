# 3. MQTT 功能矩阵实测

> **实测状态**:✅ 已实测 —— mosquitto 客户端(eclipse-mosquitto:2 容器)对 jmqtt-broker 的协议矩阵,2026-10-01。**发现一个上游缺陷(QoS2 下行断连)**,证据链完整。

## 矩阵总表

| 功能 | 结果 | 实测证据 |
| --- | --- | --- |
| QoS1 收发 | ✅ | sub 收到 `hello-qos1` |
| 保留消息(retained) | ✅ | 发布后新订阅者立即收到 `sticky-value` |
| 遗嘱(LWT) | ✅ | kill 客户端后订阅者收到 `device-7-offline` |
| QoS2 发布侧 | ✅ | PUBLISH→PUBREC→PUBREL→PUBCOMP 四步完整(RC:0) |
| **QoS2 订阅侧** | ❌ **缺陷** | 4/4 复现:订阅者收不到消息且连接被断(见下) |
| 认证 | ✅ | 错密码 `Connection Refused`;默认 jmqtt/jmqtt |
| WebSocket(8083 `/mqtt`) | ✅ | TCP 发布 → WS 订阅者收到 `cross-tcp-ws` |
| 空 clientId | ❌ 拒绝 | CONNACK code 2(identifier rejected);**客户端必须显式带 id** |

## 客户端纪律(实测)

**必须显式 `-i <clientId>`**:不带 id 的连接被拒(CONNACK 2),broker 日志显示 `clientId=unknown`。mosquitto 客户端一律加 `-i`:

```bash
docker run --rm --net=host eclipse-mosquitto:2 mosquitto_pub \
  -h <broker> -i my-client-1 -t lab/qos1 -m "hello" -q 1 -u jmqtt -P jmqtt
```

## QoS2 下行缺陷(实测证据链)

现象:QoS2 订阅者永远收不到消息,broker 侧 `本地投递=1` 显示已投递。订阅端 debug 抓包:

```
received PUBLISH (d0, q2, r0, m5, 'lab/q2dbg', ... (11 bytes))   ← broker 下发了
sending PUBREC (m5, rc0)                                          ← 订阅者应答
sending CONNECT                                                   ← 连接已断,自动重连重订阅
```

时序(broker 日志):`本地投递=1` 后 **17 毫秒**订阅者连接被关闭;无 Java 异常栈(干净关闭)。即:**broker 在 QoS2 下行 PUBREL 阶段前断开了客户端连接**。发布侧(客户端→broker 的 QoS2)握手完整不受影响。

**运维口径**:在修复发布前——
1. 业务侧统一用 QoS1(IoT 上报场景事实标准,QoS2 极少用);
2. 网关/客户端把 QoS2 降级为 QoS1 的开关打开;
3. 上游修复后按本矩阵重跑本篇(README 已挂重跑要求)。

**缺陷复核(2026-10-09)**:上游仓库 HEAD 仍为 028f439(**修复未发布**),本日重放 QoS2 下行 2/2 复现——发布侧 QoS2 提交 OK,订阅者等满窗口收不到消息,与 10-01 的缺陷行为一致。绕过措施(业务统一 QoS1 + 网关降级开关)继续有效,重跑矩阵的前提仍未满足。

## 功能测试命令速查(实测脚本式)

```bash
# 收发对(bash 后台 sub + pub,详见第 1 篇部署机执行):
sub=mqtt-sub-1; docker run -d --name $sub --net=host eclipse-mosquitto:2 \
  mosquitto_sub -h 127.0.0.1 -i lab-sub-1 -t lab/t1 -q 1 -C 1 -W 10 -u jmqtt -P jmqtt
docker run --rm --net=host eclipse-mosquitto:2 mosquitto_pub \
  -h 127.0.0.1 -i lab-pub-1 -t lab/t1 -m payload -q 1 -u jmqtt -P jmqtt
docker logs $sub; docker rm -f $sub
```
