# 2. 参数与配置

> **实测状态**:✅ 已实测 —— 全部 env 占位在 jmqtt-1/2 实际应用生效(节点 id、Redis 三模式切换、Kafka 总线)。

## 配置体系(上游设计,很规矩)

三层优先级:**外部覆盖文件 > 环境变量占位 > jar 内 application.yml**:

1. jar 内 `application.yml`:全量默认值,关键项都带 `${JMQTT_*:default}` 占位;
2. `JMQTT_*` 环境变量:部署期覆盖(docker run -e);
3. `application-local.yml`(工作目录/config/)或 `SPRING_CONFIG_ADDITIONAL_LOCATION=file:...`:文件级覆盖,适合密码/地址不入命令行。

## 按"值由谁拍板"分组(env 占位实测)

| 组 | 拍板人 | 关键参数(默认 → 基线) |
| --- | --- | --- |
| 一、身份与端口 | 拓扑 | JMQTT_ID(必配,集群节点唯一)、JMQTT_PORT(1883)、WEBSOCKET_PORT(8083)、SERVER_PORT(8922) |
| 二、认证 | 合规 | JMQTT_AUTH_PASSWORD(jmqtt 明文默认 → **sha256:<hex>**,上游 PwdUtil 生成) |
| 三、Redis | 架构 | REDIS_ENABLED(false→true)、HOST/PORT/PASSWORD、**MODE(standalone/sentinel/cluster 三模式原生支持)** |
| 四、Kafka/集群 | 架构 | CLUSTER_ENABLED + KAFKA_ENABLED(双开关)、BOOTSTRAP_SERVERS、uplink-topic(上行数据面,默认关) |
| 五、容量 | 机器 | max-inflight(窗口 32)、max-mqueue-len、consumer-threads |
| 六、行为 | 业务 | broadcast-enabled/broadcast-filters(集群广播收敛) |

**两个部署判断**:

1. **单机也开 Kafka**(演进前置,同 MySQL 篇 GTID 的思路):关着是纯单机总线,开着的单机行为不变,将来加节点零停机;
2. 认证密码生产必须换 sha256 摘要形态,明文默认值是扫描器最爱的靶子。

## Redis 三模式的选择(实测 standalone,sentinel/cluster 为上游声明)

- standalone:一个实例,小规模与管理简单优先;
- sentinel:复用我们的 [Redis 哨兵体系](../redis/5.主从与哨兵.md),主从切换后 broker 侧自动跟随(**推荐生产形态**,与 EMQX 时代的 Redis 高可用对齐);
- cluster:数据量/写入超单机时。

## 生效方式

env 改动 = 重建容器;yml 文件改动 = 重启。无动态改参通道(与 Redis 同类的"配置即文件"模型,没有 MySQL SET GLOBAL 的漂移问题——巡检对照 [conf/application-local.yml](conf/application-local.yml) 模板即可)。
