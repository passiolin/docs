# 6. 日常运维与排障

> **实测状态**:✅ 已实测 —— 排障字典条目全部来自本实验实录(jmqtt main@028f439 + docker)。

## 日常操作速查

```bash
docker logs -f jmqtt-broker                          # 业务+访问日志(DEBUG 含收发轨迹)
curl -s localhost:8922/actuator/health               # 健康
curl -s localhost:8922/actuator/prometheus | head    # 指标(NodeMetricsService 绑定,热路径零开销)
docker exec jmqtt-redis redis-cli SMEMBERS jmqtt:admin:nodes   # 集群成员快照
# 管理台:UI(9100)或 /api/nodes(见第 5 篇)
```

## 排障字典(实测错误集)

| 现象 | 根因 | 处置 |
| --- | --- | --- |
| 启动失败 `Failed to create parent directories for /app/logs` | **上游镜像缺陷**:WORKDIR 属 root | `-v /data/jmqtt/logs:/app/logs`(第 1 篇) |
| Kafka 刷 `UNKNOWN_TOPIC_OR_PARTITION` | jmqtt-cluster topic 不存在(基线禁自动建) | 先建 topic(第 1 篇) |
| Redis 冷却期循环(`Redis 仍在冷却期`) | Redis 不可达/密码错/网络 | 逐层:ping → 密码 → bind;`--net=host` 下才可用 127.0.0.1 |
| 客户端 `identifier rejected` | 未显式带 clientId | 客户端 `-i`;jmqtt 不接受空 id(第 3 篇) |
| QoS2 订阅者收不到消息且掉线重连 | **上游 QoS2 下行缺陷** | 业务用 QoS1;跟踪上游修复(第 3 篇证据链) |
| admin 里"一个节点都没有" | key-prefix 不一致 / admin Redis 配置没生效 | 覆盖文件核对(第 5 篇);admin yml 无 env 占位是坑 |
| admin overview 报 Redis Cluster 连接错 | 未覆盖上游硬编码的 cluster 配置 | SPRING_CONFIG_ADDITIONAL_LOCATION 覆盖(第 5 篇) |
| 启动 90 秒无端口 | Spring 正常时长 | 等 `Started` 日志,勿反复重启 |
| 跨节点消息"静默不到" | broadcast-filters 收敛后共享过滤器不在白名单 | admin 的"跨节点订阅重叠检查"(第 5 篇 UI) |

## 监控接入

- `/actuator/prometheus`(8922)直接进 Prometheus,零 exporter——jmqtt 的指标面是自带的(比 MySQL/Redis 那套还省一层);
- 核心告警面:health DOWN、连接数突降、Redis/Kafka 依赖不可达(admin overview 的 redis.reachable 字段亦可探)。
