# 写作人称规范(writing-style)

> 本文件是仓库级项目规范,适用于 `docs/` 下全部文档与产出的巡检报告;同步安装于 `~/.agents/skills/writing-style/` 供 AI 自动触发。规范源于一次真实修订(2026-10:jmqtt 文档把仓库主人写成"作者",已全量改写)。

## 人称总则

| 人称 | 语义 | 允许的场景 | 禁止的场景 |
| --- | --- | --- | --- |
| **笔者** | 第一人称自指 | 文档写作者谈到自己:做实验的人、下判断的人、**自研项目的作者**(jmqtt 等)、踩坑的当事人 | —— |
| **我们** | 第一人称复数(团队/环境主体) | 运维与实验语境:"我们实测"、"我们生产在用"、"我们的基线" | 与"笔者"同句混用谈同一个人 |
| **你** | 第二人称(面向读者) | 教程式讲解(与本仓库技术方案系列风格一致):"你可以用 X" | 正式结论、事故复盘、规范条文 |
| **作者** | 第三人称,专指**别人** | 外部项目作者,且优先直接写实名(antirez、Doug Cutting、Jay Kreps 等) | **指写作者本人或本仓库主人;指自研项目** |
| 角色名(运维负责人/值班人员/巡检账号) | 第三人称,流程中的角色 | 操作规程、授权红线中的岗位 | —— |

一句话判别:**这套 docs 是 passio 的个人笔记——写作者就是 passio 本人;凡"谁做的实验、谁的判断、谁的项目",不是笔者就是实名,永远不是"作者"。**

## 正反例(取自真实修订)

| ❌ 反例(旁观者口吻) | ✅ 正例 |
| --- | --- |
| jmqtt 是作者自己的开源项目 | jmqtt 是**笔者**自己的开源项目 |
| 性能口径取自**作者 README 数据** | 性能口径为**笔者的 README 自述**(笔者尚未在本文档环境复测) |
| 把**作者本机**的 Redis Cluster 硬编码 | 把**笔者本机**的 Redis Cluster 硬编码 |
| 我们未复测(同句前文已用"笔者"自指) | **笔者**尚未在本文档环境复测 |
| Kafka——**作者** Jay Kreps 等(✔ 合法,外部实名) | 保留,且尽量直接写实名少用"作者" |
| Lucene 以**作者之子**的中间名命名(✔ 合法,指 Doug Cutting) | 保留 |

## 补充细则

1. **同句人称一致**:一句之内不"笔者/我们"混用指同一主体;段落切换视角时要自然(叙述实验→"我们";叙述判断与经历→"笔者")。
2. **外部人优先实名**:"antirez 给过口径"优于"Redis 作者给过口径"。
3. **"本人"只作同位语**:如"antirez 本人",且能删则删;绝不用"本人"替代"笔者"作主语。
4. **被动旁观腔自查**:诸如"本文作者将"、"读者将会看到"、"用户应当"(指写作者自己时)一律改为第一人称。
5. 教程类文章(技术方案系列风格)可用"你";**巡检报告、事故复盘、规范条文、部署手册**用"笔者/我们",不用"你"。

## 路径与链接(一律相对)

1. 文内引用仓库内文件(其他篇目、conf/ 模板、图片、巡检 references)一律写**相对路径**,这样 docs 站渲染与换机检出都不断链:`[第 2 篇](2.安装部署-KRaft集群.md)`、`[conf/zoo.cfg](conf/zoo.cfg)`、跨目录如 `../../../../部署相关/redis/README.md`;
2. **禁绝对路径**:不写本机仓库绝对路径(`/home/passio/Codes/...`),不写以 `/` 开头的站内根路径链接(`](/部署相关/...)`)——换机器、换检出目录即断;
3. 运维命令里**目标机自身**的文件系统路径(`/etc/nginx/nginx.conf`、`/data/mysql/`)不受此限——那是被操作机器的路径,不是仓库路径;确需表达仓库位置的场景(如 symlink 安装 skill),用 `$PWD` 相对当前目录表达,不硬编码检出位置。

## 目录与文件命名(2026-10-29 增补,源于 openwrt 目录返工)

主题目录与章节文件的摆法在 mysql / redis / kafka / pve 里已经稳定,写成条文:

| 位置 | 约定 | 依据 |
| --- | --- | --- |
| 一级目录 | 中文大类:`部署相关` / `技术方案` / `运维巡检` / `开发` | 站点目录树按真实层级展示 |
| 主题目录 | 组件或主题的英文小写名:`mysql`、`redis`、`kafka`、`openwrt` | 短链别名从路径 ASCII 词派生,中文目录名会落到 `p-xxxxxx` 兜底 |
| 目录首页 | 必有 `README.md`,只当索引 | 站点把 README 置顶 |
| 章节文件 | `N.标题.md`,`N` 从 1 起连续 | 排序即阅读顺序 |
| 配置模板 | `conf/` 子目录,按角色分层 | 正文只引用,不整份粘贴 |
| 图片 | 同目录或 `assets/`,相对路径引用 | —— |

索引 README 至少四块:版本基线与环境数据的引用块、文章索引表(`编号 | 文章 | 内容 | 状态`)、阅读路径、组件或主题说明。索引里的链接直接指向 `N.标题.md`。

一篇一个主题:同一主题不并存简版与图解版,两行同题索引等于把重复内容摆到读者面前。确实要留两份,就合并成一篇,次要版本降为该篇的附录章节。

**README 不当正文(2026-10-29 全量检查补,源于 linux / tailscale 返工)**:主题目录的 README 只能承载索引,不能把正文写进去。判别方法很直接——README 里有 `## 一、` 这类正文章节标题,就是违规。拆法:

| ❌ 现状 | ✅ 拆后 |
| --- | --- |
| `linux/README.md` 149 行讲「主机到手清单」,旁边躺着 `1.内核参数与百万连接.md` | README 变索引;正文进 `1.主机到手清单.md`,原第 1 篇顺移为 `2.` |
| `tailscale/README.md` 270 行讲 headscale/derper 部署 | README 变索引;正文进 `2.自建headscale与derper中继部署.md`,原 `1.` 不动 |

拆分时正文一律用 `git mv` 保住历史,拆出来的正文改 H1 与文件名对齐,`README.md` 里的 `[第 N 篇](N.xxx.md)` 逐条跟着改。原 README 里的「篇目规划表」搬进新 README,不要留在正文里。

**编号有洞(2026-10-29 补,源于 redis 缺第 7 篇)**:`1-6` 之后直接 `8`、`9`,说明中间某篇被删过。两种处理,按引用数选:

- 引用少(跨目录引用 ≤ 5 处):重编号补洞,`8→7`、`9→8`,同步改所有指向它的链接与索引表编号列;
- 引用多:保留洞,在该目录 README 的索引表下方写一行「第 N 篇已移除」,说明现状。

统计引用时**必须带目录前缀**(`../redis/8.日常运维与排障.md`),不能只 grep 文件名——`mysql`、`kubernetes` 里也有同名的 `9.监控与告警.md`,混在一起统计会把 5 处算成 16 处。

**报告目录另立命名**:`reports/` 下的巡检报告不是文章,按 `类型-YYYYMMDD.md` 命名(`inspect-ac-20261016.md`),`类型` 与 `docs/skills/巡检/` 下的 skill 同名。同日多次巡检覆盖同一份文件,以文内时间戳为准。这条是 `N.标题.md` 规则的例外,检查脚本已按目录排除。

反例(2026-10-29 openwrt 目录返工实录):

| ❌ | ✅ |
| --- | --- |
| `README.md` 当正文,目录内没有索引 | `README.md` 只放索引,正文进 `1.xxx.md` |
| 文章名不带编号:`OpenWrt双WAN按目标IPv4分流(图解版).md` | `1.OpenWrt双WAN按目标IPv4分流.md` |
| 图解版与简版两篇同题并存 | 合并为一篇,以图最全的那版为准 |
| 链接写 `./2.家用OP路由器外网访问并分流.md`,而文件没有 `2.` 前缀 | 改名后逐个校验链接可达 |
| 两篇 OpenWrt 文章落在 `llamacpp/` 下 | 主题目录按内容归属,别处不留副本 |

改完目录或文件名,遍历 `docs/` 下全部 markdown,取出 `](...)` 里的相对路径、`normpath` 后判断文件是否存在。文件名带括号时(`1.办公网到10.61组网迁移(WG转tailscale).md`)简单正则会从括号处截断,校验要按括号配对切。

## 构建产物:manifest.json 不代跑(2026-10-12 增补,源于 k3s 第 5 篇交付后 AI 擅自生成根目录 manifest.json 的返工)

`manifest.json` 是站点目录树缓存(index.html 的数据源),由仓库主人**自己**执行 `python3 build-manifest.py` 生成,不入 git。AI 增删/移动文档后到此为止:文档落盘、相对链接正确即交付完成,**不自动跑构建脚本,不生成、不删除、不"顺手刷新" manifest.json**;交付说明里提一句"manifest 由主人自行重新生成"即可。

## 反 AI 腔(2026-10 增补,源于八套 README 组件介绍开场的返工)

1. **禁元叙述**:不写"本节先铺 X 再交代 Y"、"本章将介绍"、"本节是通用知识速览"这类章节说明书——内容直接开始,让事实当第一句。口径信息(实测版本、TODO 约定)写在正文对应位置,全文说**一次**即可。
2. **禁模板同构**:多份文档不得共用同一开场句式或引语骨架(**小节框架/表格结构同构是仓库惯例,豁免**——判别标准:句式逐字级复制违例,框架相同而内容各异合法)——AI 批量生成的最大破绽就是八篇开头一个模子。每篇的引入必须从**该组件自己的具体事实**切入。
3. **禁免责复读**:"以实测为准"、"未验证标 TODO"这类声明在一份文档内至多出现一次。
4. **禁状态戳**:文档头部不写「实测状态:✅ 已实测 ——」式 blockquote(2026-10 已全库清除 61 处)。版本、环境、日期作为数据写进正文小节,验证经过("全验证""摘自实测")融进对应小节的叙述;标题下直接进正文。

**AI 腔黑名单(逐行检查用)**:

- 元叙述句式:`本节先铺/再交代`、`本章将/本章回答/本章讲`、`本节是…速览`、`下面我们来看`、`首先…其次…最后`的空转版本(有实际内容的编号列表除外);
- 空洞连接词:`值得注意的是`、`总而言之`、`综上所述`、`不难发现`、`由此可见`、`众所周知`、`需要指出的是`;
- 结构性套路:每节结尾的复述式小结(把刚说的再说一遍)、**三件套括号枚举滥用**(`(来历、功能面、核心原理)`式定语——除非真是清单)、跨文档同构开场/同构结尾;
- 复读套路:口径/免责/约定在一份文档内多次出现;
- 状态戳:文档头部「实测状态:✅ 已实测 ——」之类 blockquote(2026-10 已全库清除,不再新增;验证经过写进正文,版本/环境作为数据出现即可)。

**句式类 AI 腔(2026-10 二次增补,源于 pve 存储配置 SLOG 擦写段的返工)**:词级黑名单会打地鼠——禁掉一个词,模型换一个词("值得注意的是"→"需要关注的是","退一步"→"换个角度看")。病根在议论文骨架,按句式类自查,判别只用一把尺:**换成最平的说法而信息无损,即装饰,删**。

| 句式类 | 特征 | ❌ 反例(pve 返工实录) | ✅ 改法 |
| --- | --- | --- | --- |
| 先立靶再驳 | 先虚构一个担忧/观点再驳倒 | SLOG 把 nvme1 磨出局部坏块的**担忧不成立**,两层机制各自独立—— | 盘不会被 SLOG 局部磨坏。ZIL 是环形日志,… |
| 结构预告 | 先报框架("两层/三个/N 个维度")再填内容 | 两层机制各自独立——(删掉,后文一分不少) | 直接讲第一个事实 |
| 议论文转折 | 让步、换角度的作文连接词 | 退一步,即便写死同一批 LBA… | 就算写死同一批 LBA… |
| 强行拟人/修辞 | 给技术对象派戏剧人格或加比喻 | 坏块因此**不认 SLOG 边界**,寿命**以整盘 TBW 耗尽的方式到来**…**烂出洞** | 坏块出现时是整盘 Percentage Used 爬升,不是 SLOG 那一小块先写穿 |
| 二元对比/否定铺垫 | "不是A,而是B"制造转折感;连排几个"不是"再揭晓要说的 | 这不是一次故障,而是一次校准;不是一个工具,而是一种方法 | 对比两端都带事实才合法("瓶颈不是容量,是磁头"合法);一端为空即删,直接陈述后半句 |
| 空泛断言 | 断言重要性/难度/收益而不给具体 | 该方案收益显著;原因主要是结构性的 | 写出那个具体数字或事实;写不出即删 |
| 空转设问 | 设问引出"洞见"却不交付 | 想一想:如果从另一个角度看呢? | 删设问,直接给结论 |

后三行(二元对比/否定铺垫、空泛断言、空转设问)为 2026-10 依据外部同源规范 [stop-slop](https://github.com/hardikpandya/stop-slop)(MIT)增补:其 False Agency 与本表"强行拟人"独立收敛,互为通用性佐证;此三行尚无本仓库返工实录,反例为构造示例,待真实案例回流校准。

2026-10-10 已将 stop-slop 整体 vendor 至本仓库 [`.agents/skills/stop-slop`](../stop-slop/SKILL.md)(上游 commit `8da1f03`),走工作区级 skill 路径随仓库生效,`~/.agents/skills/stop-slop` 另有 symlink 供其他工作区使用;本规范正本也随之落在 `.agents/skills/writing-style/`(原仓库根 SKILL.md 已并入)。正文已本地化为中文——词句表补了中文 AI 腔对应物,示例改写为中文语境,英文原版见上游,升级时重新克隆上游后按现有中文版重译覆盖。冲突裁决已内置进其 SKILL.md「本仓库适配」节:人称(部署手册禁"你","You beats People" 只适用教程类)、副词("约/仅/才"等承重词保留,只删修饰性)、破折号(——中文不禁,英文场景才执行);判别尺与本规范「句式类 AI 腔」表通用。

边界一例:"主控不认分区"合法——"不认"作"不识别"讲是术语用法;违规的是给无生命对象派角色(坏块认边界、寿命"到来")。

三个可执行检验(比词级 grep 更根本,句式类 grep 抓不全):

1. **首句检验**:第一句删掉、后文不受影响,它就是框架句,删("担忧不成立"即属此类);
2. **删减 pass**:交付前把成稿过一遍"删掉所有删掉后信息不变的词"——装饰从句、结构预告、拟人比喻全在这批;
3. **密度锚点**:新句与仓库自有实句对照(如"填满后任何尺寸都是 180MB/s,瓶颈在磁头,与盘容量无关"),每句携带的事实量不得低于锚点。

写作前预设读者是"三年后半夜排障的自己":裁判从打分的评委换成赶时间的读者,比堆禁令更接近病根。

**豁免(仓库自有文体,不是 AI 腔)**:"已知坑表"、"排障字典"、"决策参数表"等结构化表格;排比仅当每项都携带不同事实;"先…后…"仅当描述真实操作顺序。

## AI 写作自查清单(每次交付前执行)

```bash
# 在 docs/ 下执行,命中项逐条分类:自指→改"笔者";外部实名→保留;混用→统一
grep -rn "作者\|本人\|本文作者" --include="*.md" . | grep -vE "实名白名单(Jay Kreps|Doug Cutting|以作者之子|三位作者|antirez)"
# 同句混用检查:grep 同一行同时出现 笔者与我们的,人工判定主体是否同一
grep -rn "笔者.*我们\|我们.*笔者" --include="*.md" .
# 反 AI 腔:元叙述/章节说明书/空洞连接词检查
grep -rn "本节先\|本章讲\|本章回答\|本节是.*速览\|先铺\|值得注意的是\|总而言之\|综上所述\|不难发现\|由此可见\|众所周知\|需要指出的是\|实测状态" --include="*.md" .
# 句式类 AI 腔可 grep 的部分(结构预告/拟人 grep 抓不全,按句式表人工过)
grep -rn "退一步\|诚然\|不可否认\|担忧不成立" --include="*.md" .
# 相对路径检查:站内根路径链接与仓库绝对路径
grep -rn "](/\|(/home/" --include="*.md" .
# 目录检查:主题目录缺 README
find docs -mindepth 2 -maxdepth 2 -type d ! -exec test -e '{}/README.md' \; -print
# 命名检查:主题目录下的 markdown,凡属"文章"的须为 N.标题.md
# 只管 .md;Dockerfile / Jenkinsfile / *.sh / conf 下配置模板不属于文章,不在此列
# SKILL.md 是被 skill 管理的应用自带入口,视为自带索引;reports/ 按日期命名,另立规则
find docs -mindepth 3 -maxdepth 3 -type f -name "*.md" \
  ! -name "README.md" ! -name "SKILL.md" ! -name "[0-9]*.*" \
  -not -path "*/reports/*" -print
```

两条检查的分工要说清:`README.md` 那条查的是"目录有没有索引",缺了就是目录没入口,必补;`N.标题.md` 那条查的是"文章有没有编号",只对文章成立,构建文件和 skill 入口不适用——上一版写法对全类型文件一刀切,第一次跑就误报了 8 项里的 5 项,这种检查会被忽略,等于没有。

## 全量检查脚本(2026-10-29 增补,源于 144 篇全量体检)

上面的 grep 清单只覆盖词级问题,断链、表格列数、索引漏项、孤儿文档、编号连续性这些它查不了。全量体检用同目录的 `check_docs.py`:

```bash
python3 .agents/skills/writing-style/check_docs.py           # 只列必修与待核的头部
python3 .agents/skills/writing-style/check_docs.py --verbose # 待核项全量
```

输出分两类:**必修**是明确的规范违反(断链、缺索引、编号不连续、标题跳跃、表格错位、孤儿文档),直接修;**待核**是脚本只能给线索、需要人判断的(引号内拟人、否定铺垫、同构开场、内容重复、未完成标记),逐条决定改或留。

脚本本身踩过的坑,改它的时候别退回去:

| 坑 | 症状 | 正确做法 |
| --- | --- | --- |
| 链接用正则 `\]\(([^)]+)\)` | 文件名带括号时被截断,`1.办公网到10.61组网迁移(WG转tailscale).md` 误报断链 | 从 `](` 起做括号配对扫描,遇 `(` 加深度 |
| 表格列数直接数 `\|` | 行内代码里的 `\|`(`kubectl get ep`、`curl ... \| sh`)被当分隔符,首次运行 8 项误报 5 项 | 先剥离 `` `...` `` 再数 |
| 空行压缩用 `\n{3,}` | 压掉代码块与 mermaid 里的空行,内容被改坏 | 逐行扫,维护围栏开关,围栏内不动 |
| 状态戳全文件找「实测状态」 | 正文里「并入前实测状态:quorum…」被判成头部状态戳 | 只查前 20 行的 blockquote 行 |
| 同构开场用 8 字符 n-gram | 长句内部自我重叠,一次跑出 568 条噪音 | 取首句归一化后前 40 字,两两算整句相似度 |

**豁免清单(脚本会报,但属于仓库自有文体,不改)**:

- 阅读路径的框架同构:`从零搭:1 → 3 → 4(单机闭环)→ 2 → 5(进集群);接手在跑的:6 → 7` 在 mysql/kafka/redis/ES/ZK/doris/jmqtt 里句式一致,是索引结构的复用,每篇编号序列不同、携带不同事实;
- `SKILL.md` 的 frontmatter:`name:` / `description:` 字段同名同构是 skill 机制的硬要求;
- 否定铺垫两端都带事实:`验收标准不是"跑成功了",而是"恢复演练通过"`、`partition 在磁盘上不是一个文件,而是一族 segment`;
- 引号内的行话:`应答 ARP("这个 IP 在我这")` 是网络排障的通行说法,不是给技术对象派人格;模拟他人误读的心声(`"这个节点怎么不存在,我这不正在建吗"`)属叙事手法;
- 首页 `docs/README.md` 是个人主页,索引的是主题目录而非一级目录,`技术方案`/`运维巡检` 这类中文大类不出现不算漏;
- 巡检报告 `类型-YYYYMMDD.md` 命名,见上文目录规范。

## 适用范围与变更

- 适用:`docs/` 全部 markdown(部署相关/技术方案/skills)及巡检报告产出;
- 变更流程:改本文件 → 同步 `~/.agents/skills/writing-style/SKILL.md` → 两处一致才算生效;
- `check_docs.py` 随本文件一起同步到用户级 skill 目录,两处的脚本必须一致。
